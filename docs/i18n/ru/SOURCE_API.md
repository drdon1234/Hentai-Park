# API плагинов сайтов

[Быстрый старт](#быстрый-старт) · [Поля manifest](#поля-manifest) · [Методы](#методы) · [API среды выполнения](#api-среды-выполнения) · [Коды ошибок](#коды-ошибок) · [Локализация](#локализация) · [Публикация](#публикация)

Каждый сайт в HentaiPark — отдельный плагин на JavaScript. Приложение загружает плагины во время работы; их можно установить из репозитория, обновить, включить или выключить **без пересборки приложения**. Официальные плагины лежат в [`assets/sources/`](../../../assets/sources/) и годятся как примеры.

Основной считается версия этого документа на упрощённом китайском. Правила конкретного сайта живут в его плагине; сеть, кэш и изображения обеспечивает фреймворк, который никогда не делает исключений по имени сайта.

## Быстрый старт

### Среда выполнения

- Плагины работают в безоконном WebView внутри приложения, с современным JS и `DOMParser`. Нативный слой даёт криптографию, cookie и нативный HTTP; у нативного HTTP нет ограничений CORS, а сеть браузера и медиа подчиняются собственным правилам, описанным ниже.
- Среда плагина запускается при первом обращении к сайту и освобождается примерно через 5 минут простоя или когда их больше 6. Manifest кэшируется по «SHA-256 скрипта + версия среды», поэтому запуск приложения не выполняет плагины. Не рассчитывайте, что плагин работает сразу после старта приложения.
- Та же среда ([`assets/runtime/park_runtime.js`](../../../assets/runtime/park_runtime.js)) работает в Node, так что во время разработки можно проверять работу с настоящими сайтами. Хост на Node — инструмент разработки, а не песочница для недоверенных скриптов.

### Минимальный плагин

```js
Park.register({
  key: 'mysite',
  name: '我的站点',
  version: '0.0.1',
  minAppVersion: '0.9.2',
  type: 'comic',
  category: 'doujin',
  homepage: 'https://example.com',
  domains: ['example.com'],
  defaultFeed: 'popular',
  feeds: [{ key: 'popular', label: '热门' }],

  async feed(key, { page }) {
    const doc = Park.html.parse(await this.http.text(`https://example.com/popular?page=${page}`));
    return {
      items: [...doc.querySelectorAll('.gallery')].map((el) => ({
        id: el.dataset.id,
        title: Park.html.text(el.querySelector('.title')),
        cover: el.querySelector('img').src,
      })),
      hasNext: !!doc.querySelector('.next'),
    };
  },
  async detail(id) { /* … */ },
  async chapter(id, chapterId) { /* … */ },
});
```

## Поля manifest

```js
Park.register({
  key: 'mysite',              // уникальный и неизменный; только [A-Za-z0-9_-], 1–100 символов, не _app
  name: '我的站点',
  version: '0.0.1',
  minAppVersion: '0.9.2',           // три числа; если в репозитории версия выше, приложение предложит обновиться
  type: 'comic',              // comic | video | novel | game: как работы читаются или воспроизводятся
  category: 'doujin',         // doujin | anime | aiDrama | jav | adult | shortvideo | recording | live | gallery | illustration | novel | game | other
  color: '#E5355F',           // фирменный цвет: значок и страница сайта
  description: '一句话介绍',
  homepage: 'https://example.com',
  domains: ['example.com'],                   // сайты плагина, см. «Изоляция и безопасность»; без него выводится из homepage и др.
  linkPatterns: ['example\\.com/g/(\\d+)'],   // вставленная ссылка открывает работу; 1-я группа — ID работы
  idPattern: '^(\\d+)$',                      // введённый ID открывает работу
  imageHeaders: { Referer: 'https://example.com/' },  // заголовки по умолчанию для обложек и изображений
  network: { mode: 'auto', vpnHint: true },  // см. «Сеть»
  media: { mode: 'browser', origin: 'https://example.com', domains: ['media.example.com'] },  // разрешение медиа для видео и прямых файлов
  imageNetwork: { mode: 'browser', origin: 'https://img.example.com', domains: ['img.example.com'] }, // необязательно
  imageDecrypt: { /* необязательно, см. «Зашифрованные изображения» */ },

  settings: [ /* параметры, см. «Параметры» */ ],
  account: { /* необязательно, см. «Аккаунты» */ },
  defaultFeed: 'ranking',     // вкладка, открываемая на странице сайта по умолчанию (key из feeds)
  feeds: [ /* вкладки страницы сайта */ ],
  searchFilters: [ /* фильтры поиска */ ],
  searchHint: '搜索技巧提示',
  i18n: { /* собственные переводы интерфейса плагина, см. «Локализация» */ },

  subscription: { /* необязательно: подписка на каналы/авторов, см. «Подписки» */ },
  postShortVideos: true,
  updateSubscriptions: { /* необязательно: подписки на обновления */ },

  async init() {},              // необязательно: вызывается один раз при запуске среды (например, обновить список доменов)
  async onSettingsChanged() {}, // необязательно: вызывается после изменения настроек сайта
  // плюс методы из раздела «Методы»
});
```

Возможности (`capabilities`) среда выводит сама по реализованным методам; не пишите их вручную.

### Тип и категория

`type` определяет, как работы читаются, воспроизводятся или обрабатываются как игровые ресурсы; `category` — где сайт показывается в «Обзоре», в управлении сайтами и в поиске. Неизвестные или не указанные категории попадают в «Другое». Новые сайты должны точно объявлять тип, категорию и возможности.

| Категория | Значение |
| --- | --- |
| `doujin` | Додзинси и комиксы |
| `gallery` | Фотогалереи: косплей, фотографии и наборы изображений реальных людей. Сайты изображений используют `type: 'comic'`; один набор — одна работа, `chapter()` возвращает изображения по порядку. Чтение, избранное и загрузки общие. Число изображений и откровенность не определяют категорию |
| `illustration` | Галереи иллюстраций: рисунки и изображения аниме. Сайты изображений используют `type: 'comic'`; один набор — одна работа, `chapter()` возвращает изображения по порядку. Чтение, избранное и загрузки общие. Число изображений и откровенность не определяют категорию |
| `anime` | Аниме для взрослых |
| `aiDrama` | ИИ-мини-драмы. Старое значение `drama` не принимается; названия каналов сайта объявляйте как есть, категория приложения их не фильтрует |
| `jav` | Специализированные сайты JAV |
| `adult` | Общее видео для взрослых (Pornhub, XVideos, 91porn…), `type: 'video'`. Категория — это группировка; она не заменяет теги сайта и фильтры пользователя |
| `shortvideo` | Короткие видео: полноэкранная вертикальная лента, см. ниже |
| `recording` | Записи и видео по запросу, `type: 'video'` |
| `live` | Прямые эфиры, `type: 'video'` |
| `novel` | Новеллы, `type: 'novel'` |
| `game` | Игры, `type: 'game'` |
| `other` | Сообщества авторов |

- **Короткие видео** (`type: 'video', category: 'shortvideo'`): работы, поиск, избранное и история открывают ленту сразу. Каждая работа — одно видео, `videos(id, '_')` возвращает его текущий медиафайл; страница описания не нужна. `hasNext` и `cursor` из `feed` подгружают следующую страницу у конца ленты; курсоры не должны содержать учётные данные или подписи медиа. Обновление начинается с первой страницы; текущий ролик играет, следующий предзагружается на паузе, остальные освобождаются. Не объявляйте `search`, если на сайте нет поиска.
- **Видео из постов** (`postShortVideos: true`): страницы сайта и объектов подписки воспроизводят каждое видео из `media[]` отдельно. Нужен прямой `url` либо непустой `episodeId`; отложенное получение вызывает `videos(исходный ID поста, episodeId)` при воспроизведении или предзагрузке, не выдавая веб-страницу за медиассылку. Изображения не воспроизводятся; поддерживаются `preview`, `format` и `headers`. Переходы и обновление сохраняют feed, фильтры или область `subscription.posts` объекта. Плеер различает вложения, а избранное, история и действия на сайте используют исходный ID поста. Категория не меняется; отдельный API случайных видео не подразумевается.
- **Агрегаторы, где видео играет только на исходном сайте**: всё равно объявляют `type: 'video', category: 'adult'`; без проверенного API медиа не реализуйте `videos`, и среда выводит `capabilities.videos: false`. Главная кнопка на странице работы открывает `detail.url` в системном браузере, воспроизведение, загрузки и серии скрываются, вымышленные главы не сохраняются и обновления глав не проверяются; избранное и история работают.
- **Новеллы** и **игры** описаны в «Методах».

`defaultFeed` выбирайте в порядке **рекомендации > рейтинги > популярное**; страницу новинок или другую рабочую вкладку используйте, только если ничего из этого на сайте нет, и никогда не выдумывайте непроверенный API. Если он не задан или не найден, приложение выбирает по key (сначала `promote` / `recommend` / `featured`, затем `rank` / `toplist`, затем `popular` / `hot` / `trending`), а иначе берёт первую вкладку.

Источники с анонимным доступом, но рекомендациями только после входа объявляют `anonymousDefaultFeed: 'ranking'`. Значение должно указывать на проверенный анонимно доступный раздел в `feeds`, предпочтительно рейтинг. Главная страница и страница источника используют его без входа и `defaultFeed` после входа; явно выбранная пользователем вкладка сохраняется. Пустой список или сетевая ошибка сами по себе не означают анонимный сеанс.

### Параметры

`feeds[].options`, `searchFilters` и `settings` используют один формат:

```js
{ key: 'sort', label: '排序', type: 'select', default: 'date',
  values: [{ value: 'date', label: '最新' }, { value: 'popular', label: '热门', color: '#f00' }] }
// type: select | multi | number | text | password | switch
// в settings вместо values можно писать options
```

Каждый элемент `feeds` — вкладка на странице сайта: `{ key, label, options?: [...] }`.

### Динамические и зависимые фильтры

Поля выбора в `feeds[].options` и `searchFilters` могут объявлять `dynamic: true, values: []`. Динамический дочерний фильтр указывает родителей той же группы через `dependsOn: ['range']`. Ключи уникальны, зависимости существуют и не образуют циклов. Зависимости допускаются только у динамических полей.

`filterOptions(request)` возвращает массив вариантов. Запрос содержит `scope: 'feed' | 'search'`, `filter` и `values`; для списков передаётся `feed`, для поиска возможен `keyword`. `values` содержит только объявленных непосредственных родителей, без данных аккаунта, настроек и посторонних фильтров. При пустом или невыбранном родителе дочерние варианты не загружаются.

Объявите `keywordDependent: true`, если варианты зависят от поискового запроса. Изменение запроса сбрасывает поле и его потомков, сохраняя остальные фильтры. Родительские значения в `values` — строки, числа или логические значения, не массивы множественного выбора. Исходные названия не являются фиксированным текстом интерфейса; перевод контента и тегов доступен отдельно.

Возвращается не более 500 записей `{value, label, color?}`. Значения — уникальные строки или конечные числа. Названия — непустые исходные имена без управляющих символов, до 256 символов; цвет содержит шесть шестнадцатеричных цифр. Большие каталоги разделяются на зависимые группы без скрытого усечения. Названия с сайта автоматически не переводятся.

Выбор передаётся в `feed` через `options`, в `search` через `filters`. Плагин проверяет принадлежность каталогу и сохраняет условия при пагинации; ошибки разбора должны вызывать исключения. Кэш действует две минуты отдельно для сайта, списка/поиска, ключа списка или запроса и родительских значений. Изменение родителя очищает потомков и отбрасывает устаревшие ответы; сбой можно повторить.

Плагин каждого домена читает только собственный каталог. Связанные домены не вызывают чужие плагины и не делятся Cookie. Общий разбор переиспользуется шаблонами при сборке с генерацией автономных скриптов. Для генерации служит `node tools/build_catalog_sources.mjs`, для проверки соответствия — `--check`.

```js
{key: 'category', label: '分类', type: 'select', default: '',
 dynamic: true, dependsOn: ['range'], values: []}

async filterOptions({scope, feed, filter, keyword, values}) {
  return [{value: 'site-category-id', label: 'Site category'}];
}
```

### Сеть

- `network.mode: 'auto'` (по умолчанию): сначала используется нативный HTTP. Для одноимённых HTTPS GET / HEAD без тела проверка Cloudflare, ответы HTTP 403 и 429 или восстанавливаемые ошибки соединения запускают одну повторную попытку в браузере. Ошибки DNS, TLS, тайм-ауты, потоки ответа и обычные 5xx не открывают браузер, чтобы не добавлять задержку. Адрес должен входить в домены источника; ограничения того же источника и перенаправлений сохраняются.
- `network.mode: 'native'`: Использует только нативный HTTP с постоянными Cookie и настроенным прокси. При проверке Cloudflare возвращает `CLOUDFLARE` для повтора в приложении; если ошибка содержит адрес проверки сайта, пользователь может открыть страницу подтверждения.
- `network.mode: 'browser'` + `network.origin`: Выполняет одноисточниковый `fetch()` со скрытой страницы `origin`. При Cloudflare (включая HTTP 200) или проверке возраста без нужных Cookie/контента запрос чтения переходит для проверки максимум один раз; записи не повторяются. Возраст обрабатывается по `network.confirmation`. Android и Windows отправляют ввод единственному стандартному флажку Cloudflare; другие платформы ждут автоматическую проверку. При сбое можно повторить запрос или открыть подтверждение, если указан адрес проверки сайта.

  Документы переходят между объявленными доменами с той же схемой и портом. Если `origin` не указан, он определяется целевым URL сайта. Ответ сохраняет итоговый `url`.

  Автоматический переход не применяется к `followRedirects: false`, `connectAddress` и неклассифицированным сетевым ошибкам. Браузерные GET/HEAD без тела выполняются не более трёх обычных раз и ещё один раз после проверки, только при сбое соединения или HTTP 408, 500, 502, 503, 504; ответы 429 и тайм-ауты не повторяются. Навигация для проверки допускается один раз на весь логический запрос. Запуск, запросы, чтение документа и освобождение ресурсов имеют ограниченное время ожидания. Запросы с особыми заголовками API выполняются через `fetch()`, а не заменяются навигацией. При повторном использовании HTML сохраняется статус ошибки; `responseType: 'base64'` возвращает исходные байты в base64.

- `network.vpnHint: true`: объявляйте для сайтов, которым в материковом Китае может понадобиться VPN или прокси; при ожидании дольше 8 секунд и при ошибках появится «может потребоваться VPN или прокси». Не сваливайте все ошибки на VPN.
- `network.confirmation: { selector, readySelector, requiredCookies, auto: { clickSelector }, message }`: Объявляет проверку возраста: `selector` — диалог, `auto.clickSelector` — единственная кнопка подтверждения внутри него, `readySelector` — доступный контент, `requiredCookies` — необходимые после подтверждения имена Cookie. Только после подтверждения совершеннолетия при входе в приложение скрытый браузер имитирует нажатие и проверяет исчезновение диалога, появление контента, Cookie и завершение переходов. При неполных, несовпадающих правилах или сбое можно повторить запрос. Если ошибка содержит адрес проверки сайта, пользователь может открыть страницу, выполнить действия вручную и нажать «Готово». Ограничения доменов и разделение Cookie сохраняются; уведомления об операциях не повторяют исходное действие автоматически. Не применяется для входа, оплаты или публикаций.
- Сетевые ошибки содержат безопасные поля `diagnostics` `host`, `transport` и `reason`, различающие сертификаты TLS, рукопожатие, DNS, подключение и тайм-ауты; автоматический журнал хранит только эти разрешённые поля. `reason: 'TLS_HANDSHAKE_TERMINATED'` означает лишь, что нативное `HandshakeException.message` в точности равно `Connection terminated during handshake` (соединение оборвалось до завершения рукопожатия, это не ошибка сертификата); один повтор делается только для HTTPS GET/HEAD без тела, остальное не повторяется.

### Изображения

- `imageNetwork: { mode: 'browser', origin, domains }`: Домены изображений с поддоменами независимы от разрешений cookie сайта. `origin` принадлежит сайту или домену изображений. Используются HTTPS 443 и разрешённые заголовки с сеансом сайта браузера для изображений того же origin, если origin принадлежит объявленному домену сайта; изображения другого origin, внешние origin и видео не передают учётные данные; разрешены переходы между объявленными доменами изображений. Сохраняются лимит 20 МиБ, расшифровка, проверка формата, декодирование и кэш по сайтам. Без объявления используется нативная передача. Ограничения перенаправлений браузера по платформам описаны в разделе разрешений медиа.
- **Зашифрованные изображения**: объявите `imageDecrypt`, и фреймворк расшифрует до проверки формата и кэширования; параметры расшифровки входят в идентичность кэша, неудачи не кэшируются. Поддерживается AES-CBC со строгим дополнением PKCS#7, `key` и `iv` в UTF-8; домены изображений обязательно ограничиваются, остальные идут обычным путём.

```js
imageDecrypt: {
  type: 'aes-cbc',
  key: '0123456789abcdef', // 16, 24 или 32 байта UTF-8
  iv: '0123456789abcdef',  // 16 байт UTF-8
  domains: ['images.example.com'],
},
```

Ответ HTTP 200 на обложку ещё не значит, что она годится, — проверьте, что она декодируется.

### Разрешение на медиа (HLS и прямые файлы)

Разрешение `media` не зависит от `this.http`, `network` и cookie сайта:

Каждый плагин с `videos()` должен объявлять действительные разрешения `media`, даже если возвращает только MP4. `scope: 'session'` можно сочетать со статическим списком `domains`: HLS использует точные URL, разрешённые для сеанса, а прямые MP4 должны соответствовать статическому списку доменов. Проверка официальной публикации отклоняет отсутствующие или неверные объявления.

```js
domains: ['example.com'],
network: { mode: 'native' },
media: { mode: 'native', origin: 'https://example.com', domains: ['media.example.com'] },
```

- `media.mode` — `'native'` или `'browser'`. `media.origin` должен принадлежать сайтам плагина, использовать HTTPS на порту 443 и не содержать учётных данных, запроса или фрагмента.
- `media.domains` — отдельный список разрешённых доменов медиа (с поддоменами), не дающий доступа к cookie сайта. Плейлисты, сегменты и ключи — только HTTPS на 443; учётные данные в URL, фрагменты, IP, localhost (и поддомены) и `.local` отклоняются.
- `'native'`: Использует отдельный клиент без cookie, Authorization и авторизации прокси; каждый переход проверяется до подключения. Разрешены `Referer`, `Origin`, `Accept`, `Accept-Language`; первые два принадлежат доменам сайта с языковыми поддоменами. `Origin` содержит только origin.
- Необязательный `media.referrerDomains` доступен только для нативных видеоресурсов: не более 16 действительных публичных доменов с поддоменами. Он явно расширяет только разрешённые источники заголовка `Referer` за пределы доменов сайта выше. Права `Origin`, адресов медиа, навигации документов и cookie не расширяются. Поле недопустимо для `imageNetwork` и браузерных медиа.
- `'browser'`: Создаёт скрытую сессию на `media.origin` с навигацией в пределах доменов сайта. Использует `credentials: 'omit'`, `mode: 'cors'`; Origin/Referer формируются реальным документом и браузером. В Windows WebView2 проверяет домен перед каждым подключением, разрешает переходы между разрешёнными доменами и проверяет итоговый URL. Другие движки не имеют интерфейса проверки каждого перехода и используют `redirect: 'error'`. CORS и CSP сайта действуют; одной проверки итогового URL недостаточно.
- Ответы ограничиваются по размеру прямо при получении, их итоговый адрес проверяется снова: плейлисты до 2 МиБ, сегменты до 32 МиБ, ключи AES-128 ровно 16 байт. Слишком большие или пустые ответы и неразрешённые адреса отклоняются.

- Динамические HLS CDN могут объявлять `media.scope: 'session'` при `mode: 'native'`. Разрешение охватывает только URL, ресурсы плейлиста и допустимые перенаправления текущего сеанса воспроизведения или загрузки и исчезает при его закрытии. Права Cookie и постоянный список доменов не расширяются. Сохраняются HTTPS, запросы без учётных данных и ограничения адресов и размера; прямые MP4 и браузерные медиа используют статические списки доменов.

### Изоляция и безопасность

- Каждый плагин работает в **своей** среде JS (своём безоконном WebView) и не видит глобальных объектов других; нативный мост знает, какая среда его вызвала, так что скрипт не может выдать себя за другой плагин.
- У каждого плагина **своё хранилище cookie**: его запросы отправляют и сохраняют только его cookie.
- Secure-cookie никогда не отправляются по HTTP. Открытие страниц проверки и импорт cookie из браузера проверяются по `domains` установленного плагина с сохранением доступных атрибутов безопасности и срока действия. Очистка cookie сайта или удаление плагина также закрывает его сессию браузера и стирает cookie этого сайта в браузере; эти cookie общие для системы, поэтому плагины, объявившие тот же сайт, тоже затрагиваются.
- `domains` указывает сайты плагина (регистрируемые домены с поддоменами). Только cookie этих сайтов синхронизируются со встроенным браузером (общим для проверки Cloudflare и веб-входа), и `network.origin` в режиме браузера должен им принадлежать. Если поле не задано, оно выводится из `homepage`, `network.origin` и `account.cookieUrl/loginUrl`.
- Перенаправления на другой источник отбрасывают заголовки авторизации исходного; перенаправления на другой источник с сохранением тела запроса отклоняются. Проверка сертификатов TLS всегда включена.
- При установке по ссылке или из репозитория приложение сначала читает скрипт в песочнице без сети и показывает имя, версию, SHA-256, объявленные сайты и риски; ничего не устанавливается без подтверждения пользователя.

### Аккаунты

```js
account: {
  type: 'password' | 'cookies' | 'session',
  title, hint, required: false,
  fields: [{ key: 'email', label: '邮箱' }, { key: 'password', label: '密码', secret: true }],
  loginUrl?, cookieUrl?, requiredCookies?: ['session_id'],   // включает веб-вход; приложение забирает cookie
  loginDomains?: ['accounts.google.com', 'appleid.apple.com'],  // домены сторонних входов, только для переходов при входе
  localStorageKeys?: ['session_key'],  // только разрешённые ключи localStorage с origin cookieUrl передаются в login(values); значения не журналируются
  async login(values) { return { name } },
  async logout() {},
  async status() { return { loggedIn, name, configured } },
  managedAccount: true,                 // необязательно: автоматически обслуживаемый аккаунт
  async enableManaged() {},             // вызывается только после согласия пользователя на регистрацию
}
```

- Состояние аккаунта обновляется только при первом использовании, после входа, выхода и веб-входа, а также если последней проверке больше 10 минут, — не после каждого вызова. `configured` означает, что аккаунт настроен, независимо от того, удаётся ли сейчас войти.
- `loginDomains`: домены сторонних входов, которые сайт действительно использует (с поддоменами). Они разрешены только пока открыта страница веб-входа и только по HTTPS на 443; учётные данные в URL, IP, localhost и `.local` отклоняются. Страницы проверки, подтверждение доступа, запросы плагина и импорт cookie по-прежнему проверяются по `domains`; не добавляйте домены входа в `domains`, чтобы расширить доступ. Страница входа поддерживает переходы в том же окне и всплывающие окна с сохранением `window.opener` и теми же проверками; пустая начальная страница не даёт внешних переходов. Пока открыта сторонняя страница, вход не считается завершённым; cookie синхронизируются после возврата на сайт. Сторонние cookie не импортируются в хранилище плагина и не стираются вместе с cookie сайта — ими управляет системный WebView. Сторонние сервисы всё равно могут ограничивать вход во встроенных браузерах.
- `type: 'session'` импортирует уже авторизованную сессию: объявите одно секретное поле (например, `session`); содержимое буфера обмена сохраняется целиком и проверяется плагином, а не делится на логин, пароль или cookie. Вход должен действительно подтверждать авторизацию — никогда не сообщайте об успехе по одному лишь формату ввода.
- `managedAccount: true` и `account.enableManaged()` предоставляют необязательное управление аккаунтом, включаемое только после информированного подтверждения пользователя. Храните ручные и управляемые аккаунты раздельно, не перезаписывая существующие данные. Данные аккаунта остаются на устройстве и не включаются в документацию, диагностику и файлы выпуска.
- Пароли, токены и состояние плагина — локальные данные пользователя; никогда не пишите настоящие учётные данные в документы или журналы.

## Методы

`this` в методах описан в «API среды выполнения». Все методы могут быть `async`.

```js
async feed(key, { page, cursor, options }) {}      // вкладки страницы сайта
async search({ keyword, page, cursor, filters }) {}
async random() {}                                  // возвращает ID работы
async detail(id, preview) {}
async chapter(id, chapterId) {}                    // комиксы, галереи
async resolveImage({ id, chapterId, index, token, retry }) {}  // необязательно: отложенное получение изображения
async thumbnails(id, page) {}                      // необязательно: миниатюры по страницам
async videos(id, episodeId = '_') {}               // видео
async textChapter(id, chapterId) {}                // новеллы
async gameResources(workId) {}                     // игры
async resolveGameResource(workId, resourceId, channelId) {}
```

### Списки: `feed` / `search`

```js
{
  items: [WorkItem], page: 1, totalPages: 20, total: 500,
  hasNext: true,
  cursor: '12345',        // необязательно: сайты с курсорами возвращают следующий, приложение передаёт его обратно как есть
}
// или разделы, которые показываются блоками:
{ sections: [{ title: '连载更新', items: [WorkItem] }], hasNext: false }
```

**WorkItem**: `{ id, title, subtitle?, cover, coverBlurred?, coverAspect?, pages?, rating?, likes?, views?, language?, category?, badge?, badgeColor?, duration?, uploaded?, tags?, mediaKind?, workCode?, editions? }`

- `workCode` — подтверждённый источником код произведения только для поиска того же произведения. Он не заменяет `id` и не объединяет идентификаторы, избранное, прогресс или загрузки.
- `editions` содержит фиксированные метки версий, явно указанные источником, например китайские субтитры или утечка без цензуры. Отсутствие метки не означает оригинальную версию. Перевод для отображения не меняет исходные метки.

- `coverAspect` (ширина / высота) позволяет разложить сетку до загрузки изображений.
- `badgeColor` задаёт цвет значка категории.
- `mediaKind: 'comic' | 'video' | 'novel' | 'game'` — тип самой работы. Плагины с одним типом могут его опускать; плагины со смешанными типами обязаны указывать его — никогда не считайте изображения видео только из-за `type` плагина. Работы новелл и игр указывают его всегда, чтобы офлайн-работы и история открывались в правильном режиме и после удаления плагина.
- Результаты в виде постов могут содержать `presentation: 'post'`, `text`, `date`, `url` и массив `media` и показываются карточками постов; `presentation: 'media'` показывает сетку медиа, открывающую медиа внутри работы. У поста может не быть медиа; адреса медиа подчиняются объявленным доменам и разрешениям.

### Описание: `detail`

Все поля WorkItem, а также:

```js
{
  url, authors: [], description, uploader?, size?, comments?,
  tags: [{ namespace: 'artist', label: '作者', tags: [{ name, keyword, filters?, count? }] }],
  chapters: [{ id, title }] | null,   // null — одна глава
  singleChapterId?,                   // ID главы, нужный работам из одной главы
  thumbnails?: [url | { url, width, height, offsetX, offsetY }],   // поддерживаются спрайты
  related?: [WorkItem], series?: [WorkItem], variants?: [WorkItem],
}
```

- `variants` содержит только реальные ссылки источника на версии того же произведения в том же источнике с отдельным `id` для каждой версии; нельзя угадывать URL. Версии в других источниках ищутся по `workCode`; избранное, прогресс и загрузки остаются независимыми.

- Нажатие на тег ищет на этом сайте по `keyword` и `filters`, поэтому теги можно сопоставить с собственным синтаксисом сайта (например, `artist:"xxx"`) или параметрами фильтров.
- Необязательный второй аргумент `preview` содержит уже показанные или сохранённые публичные метаданные и передаётся, только если `preview.source` и `preview.id` совпадают с запросом. Плагин всё равно должен проверить ID и URL. У работ, открытых по введённому ID, preview нет, поэтому название и обложка могут быть неполными.

### Главы: `chapter` / `resolveImage` / `thumbnails`

```js
{ pages: [
  { url, headers?, fallbacks?: [url], width?, height?, transform? },  // адрес известен
  { token: '12' },                                                      // отложенно: приложение вызовет resolveImage
]}
```

- `fallbacks`: зеркала, которые пробуются по порядку, если основной адрес не работает.
- `transform: { type: 'unscramble-strips', segments: N }`: для изображений, разрезанных на N полос и сохранённых в обратном порядке; восстанавливаются на GPU. Офлайн-файлы хранят оригинал и восстанавливаются при показе.
- `resolveImage` возвращает `{ url, headers?, width?, height?, cacheKey? }`. При ошибке приложение вызывает его снова с бо́льшим `retry`, позволяя плагину сменить сервер.
- `thumbnails(id, page)` возвращает `{ thumbnails: [...], hasNext }`.

### Видео: `videos`

Возвращает `[{ quality: 1080, label: '1080P', url, headers?, format?, preferred?, hls? }]`. Прямые ссылки обычно истекают, поэтому приложение запрашивает их заново перед каждым воспроизведением или загрузкой.

- `format: 'hls'` допускает `hls: {manifest, keys}`: `url` — реальный базовый HTTPS-адрес варианта; `manifest` — подготовленный полный медиаплейлист VOD (до 2 MiB UTF-8); `keys` связывает используемые абсолютные URL ключей с 16-байтовыми ключами в Base64, до 32 записей. Только нативные медиа. Авторизация адресов и проверка содержимого сохраняются; неиспользуемые ключи отклоняются. Результаты с этим полем не кэшируются на диск; ключи остаются только в памяти сеанса, не в store, журналах, произведениях или курсорах.

- Видео с несколькими сериями возвращают `[{ id, title }]` в порядке просмотра в `detail(id).chapters`; каждый `id` должен быть стабильным, а не качеством или временным URL. Приложение по тому же ID выбирает серии, хранит прогресс, загружает и продолжает просмотр, вызывая `videos(id, episodeId)` для каждой серии. Одиночные видео используют `singleChapterId`, а без него — `'_'`.
- Без `format` ссылка воспроизводится и загружается как прямой MP4. HLS должен возвращать `format: 'hls'` и объявлять разрешение `media`.
- Мастер-плейлист HLS (`#EXT-X-STREAM-INF`) приложение разворачивает в плейлисты вариантов и берёт настоящее качество из `RESOLUTION`. Если вы возвращаете мастер-плейлист, `quality` — желаемое качество: выбирается максимальное настоящее качество не выше него, а если такого нет — самое высокое. Каждый вариант должен быть MPEG-TS или VOD fMP4 с мультиплексированными звуком и видео; отдельные `AUDIO`, `VIDEO`, `SUBTITLES` и адреса вне `media.domains` отклоняются. Дорожки `#EXT-X-I-FRAME-STREAM-INF` игнорируются. Если у одиночного плейлиста неизвестно разрешение, используйте `label: '原画'`, а не выдавайте желаемое качество за настоящее. Без `RESOLUTION` требуется корректный `BANDWIDTH`: варианты показаны в kbps, по умолчанию выбирается максимальный битрейт без выдуманного разрешения.
- `type: 'video', category: 'live'` обозначает открытые эфиры в 3D с карточками только из изображений. `videos()` возвращает HLS текущего открытого эфира; не выдавайте закрытые, платные и завершённые эфиры за доступные. Воспроизводятся обновляемые списки без прогресса VOD и скачивания. Запись запускается пользователем и сохраняет только фрагменты новее исходного окна. Остановка и выход из приложения завершают запись; перезапуск её не возобновляет. Независимая медиасессия и фоновая задача проверяют и расшифровывают фрагменты, сохраняя завершённый локальный список. При переподключении адрес определяется заново; границы кодирования и длинные записи могут создавать новые части. Сохранённое не теряется при сбое. Поддерживается только совмещённый MPEG-TS; MAP/fMP4, PART, BYTERANGE и GAP не поддерживаются.
- VOD требует полного непрерывного плейлиста MPEG-TS или fMP4 с `#EXT-X-ENDLIST`. fMP4 поддерживает один сегмент инициализации `#EXT-X-MAP` перед медиасегментами, без смены инициализации и диапазонов байтов. Все ресурсы проходят авторизацию адресов, проверку и локальную перезапись; инициализация сохраняется при офлайн-воспроизведении и экспорте. Для эфиров по-прежнему нужен MPEG-TS; разрешены скользящие списки и discontinuity. Оба режима поддерживают `METHOD=AES-128`, `KEYFORMAT=identity`, CBC/PKCS7 и ключи ровно 16 байтов. IV медиасегмента явный или получен из номера; зашифрованная инициализация требует явного IV. Ключи хранятся только в памяти сеанса. SAMPLE-AES, другие KEYFORMAT, BYTERANGE и GAP не поддерживаются; VOD также отклоняет discontinuity. `#EXT-X-TOKEN` удаляется.
- Списки HLS и сегменты MPEG-TS поддерживают оболочку PNG `roUd` (без сжатия или zlib). Распаковка выполняется до разбора, проверки или расшифровки; лимиты после распаковки — 2 MiB для списка и 32 MiB для сегмента. Плагины по-прежнему возвращают `format: 'hls'` без дополнительных разрешений.
- При воспроизведении используется случайный порт, привязанный к `127.0.0.1`, и случайный токен; проверенные сегменты выдаются по требованию из ограниченного реестра URL, а закрытие сессии отменяет запросы. Офлайн-загрузка HLS пока только на Android: каждый сегмент проверяется и сохраняется его SHA-256, загрузку можно продолжить и отменить, а в конце Media3 собирает MP4 — в офлайн-библиотеку попадают только полные файлы. fMP4 сохраняет инициализацию и медиасегменты по порядку без преобразования TS через Media3.

### Новеллы: `textChapter`

Плагины новелл объявляют `type: 'novel', category: 'novel'`; реализация `textChapter` выводит `capabilities.textChapter: true`. Списки и описания указывают `mediaKind: 'novel'` и `language: 'zh'` или `'en'`. Без настоящей обложки возвращайте `cover: ''` — приложение покажет текстовую обложку вместо запроса вымышленной картинки.

```js
async textChapter(id, chapterId) {
  // Полный текст главы; paragraphs — массив непустых строк без HTML.
  return { title: '章节标题', paragraphs: ['第一段正文。', '第二段正文。'] };
}
```

- Многоглавные новеллы возвращают в `detail.chapters` стабильные ID в подтверждённом сайтом порядке чтения; одиночные рассказы используют `chapters: null` и, при необходимости, `singleChapterId`.
- Разбивку главы на страницы плагин склеивает по порядку; никогда не добавляйте в текст следующую главу, ответы на форуме, рекламу или рекомендации. `Park.html.paragraphs(node)` извлекает чистый текст в общем виде; границы и разбивка сайта остаются задачей плагина.
- Если текст обрезан из-за входа, оплаты или прав, бросайте `LOGIN_REQUIRED`; никогда не выдавайте превью за полную главу.
- Приложение атомарно записывает `text.json` для каждой главы; загрузка считается завершённой, только если файл записан полностью. Прогресс и заметки используют позиции UTF-16 в `paragraphs.join('\n\n')`; размер, шрифт, отступы и другие настройки влияют только на отображение. Закладки и заметки хранятся отдельно от загрузок, входят в резервные копии и сохраняются после удаления загрузки.

### Игры: `gameResources` / `resolveGameResource`

Плагины игр объявляют `type: 'game', category: 'game'`; работы указывают `mediaKind: 'game'` и не имеют вымышленных `chapters`. Среда выводит `capabilities.gameResources` и `capabilities.resolveGameResource` по методам.

```js
async gameResources(workId) {
  return [{ id: 'resource-id', title: '', version: '1.2', size: '2 GB',
    platforms: ['Windows'], languages: ['SimplifiedChinese'], notes: '原站备注',
    status: 'valid', testStatus: 'untested',
    channels: [{ id: 'stable-channel-id', kind: 'direct', label: 'game.zip', size: '2 GB' }] }];
}
async resolveGameResource(workId, resourceId, channelId) {
  return { kind: 'direct', url: 'https://files.example/game.zip?temporary-signature',
    filename: 'game.zip', extractionCode: '', archivePassword: '' };
  // Облачные диски возвращают kind: 'external', urls: [все зеркала/части], url: urls[0].
}
```

- `gameResources` возвращает только стабильные ID, метаданные и каналы — без подписанных URL, паролей и вымышленных состояний загрузки. `testStatus` — `tested | untested | unknown`, переписанный с сайта; каналы со `status: 'expired'` отключаются.
- `resolveGameResource` вызывается только по нажатию пользователя или при повторе; его URL никогда не сохраняется и не попадает в журнал. Пароли можно хранить вместе с локальной задачей загрузки, но не в диагностике. Не отбрасывайте ссылки облачных дисков; возвращая несколько, можно передать `extractionCodes` той же длины, что `urls` (пустая строка — без кода), а для общего кода — `extractionCode`.
- Каналы, требующие ответа, объявляют `requiresReply: true, replyText: 'настоящий текст ответа'`; приложение показывает «Ответить и открыть ссылки» и точный текст и вызывает метод только после подтверждения. Перед получением ссылок плагин должен заново проверить первое сообщение: если уже открыто — только читать; отправлять один раз и только по нажатию пользователя, заранее надёжно сохранив состояние аккаунта и темы. Если результат неясен, попытка повторная или нужна динамическая проверка, верните `CONFIRM_REQUIRED` с URL темы и никогда не отправляйте повторно автоматически; никогда не отвечайте из списков, описаний, предзагрузки или фоновых обновлений.
- Прямые ссылки объявляют `media: { mode: 'native', origin, domains }`. Файлы загружаются потоком отдельным клиентом без cookie; HTTPS, проверку домена на каждом шаге, проверку длины, очистку при отмене и защиту готовых файлов обеспечивает фреймворк. Докачки нет: повтор заново получает адрес и начинает сначала. Облачные диски открываются во внешних приложениях — только HTTP(S), FTP(S), magnet, ed2k и thunder, без cookie сайта. Игры не создают глав, прогресса чтения и обновлений глав, а приложение никогда не устанавливает, не распаковывает и не запускает файлы.

### Подписки: `subscription`

Плагины подписок (каналы или авторы) объявляют объект `subscription`; среда выводит `capabilities.subscription`, если есть и `normalize`, и `posts`, и сайт появляется в «Обзор → Подписки». Плагины, которые также объявляют `feeds`, видны и в обычных категориях.

```js
subscription: {
  hint: '无需登录即可保存订阅；媒体访问取决于原站权限。',
  normalize(input) { return { id: validatedTarget, label: displayName }; },
  async resolve(input) { return { id: validatedTarget, label: displayName }; },
  async targets() { return [{ id: joinedChannelId, label: channelName }]; },
  async posts(target, { cursor }) {
    return { items: [{ id, title, text, date, url, locked,
      media: [{ type: 'image', url, preview, previewOnly: false },
              { type: 'video', url, preview, format: 'mp4', headers: {} }] }],
      cursor: nextCursor, hasNext: true };
  },
  async mediaChunk(resource, offset) { return { base64, done }; }, // необязательно
}
```

- `normalize` проверяет только локально, чтобы объект можно было сохранить без входа и без сети; принимаются только имена пользователей или контролируемые адреса профилей этого сайта. `resolve` и `targets` необязательны; при наличии `targets` manifest выводит `subscription.joinedTargets: true`.
- Для отдельного входа в сообщества объявите `communities: true`, `communityHint`, `communityExample`; среда экспортирует их без изменений. Объекты возвращают `{ id, label, kind: 'community' }`, их ID отличаются от авторских. `targets({ kind: 'community' })` перечисляет сообщества участника, `targets()` — стандартные объекты. Обрабатывайте их независимо, чтобы сбой API сообществ не ломал список авторов. `resolve` лишь проверяет имя и доступ в режиме чтения, без автоматического вступления.
- Курсоры `posts` — непрозрачные строки; на последней странице `hasNext: false`, а страницы без медиа могут продолжаться. `locked` означает нехватку прав; `previewOnly` помечает публичные превью — никогда не выдавайте миниатюру за полный контент.

### Публичные альбомы: `subscription.media`

Альбомы — независимая возможность: они не собираются из загруженных постов и не используют `subscription.posts` как запасной путь. Реализуйте `subscription.media(scope, { page, cursor })`. Источник с публичными feed без объектов подписки может объявить только этот метод в `subscription`. Среда экспортирует `capabilities.album` независимо от `capabilities.subscription`.

`scope` — это `{ feed, options }` либо `{ target }`: feed с фильтрами или пользователь, сообщество, канал, группа. Источник сам определяет и обходит объекты; UI не содержит условий по сайтам. Ответ — `{ items, cursor, hasNext }`. Страница без подходящих медиа может иметь продолжение; каждый курсор должен продвигаться, повтор считается ошибкой.

Каждый элемент содержит стабильный строковый `id`, `presentation: 'post' | 'work'`, разбираемую дату ISO 8601, если она известна, и полный массив `media` в порядке сайта. У вложения есть уникальный стабильный строковый `id`, `type: 'image' | 'video'` и реальный `url` контента либо контролируемый `resource`. `preview` — миниатюра изображения; вместо неё допустим `previewResource` в описанном ниже формате, отдельное изображение не более 2 MiB. Нельзя подменять миниатюру обложкой или видеоссылкой. Ограниченный контент возвращает только публичный предпросмотр с `previewOnly: true`, исходным размытием и `locked: true`, если закрыт весь пост.

Источник дополняет вложения между страницами и объединяет группы сайта. Клиент объединяет повторные работы по `id` вложений; конечный числовой `order` используется для сортировки, только если он есть у всех вложений работы. Фильтр дат включает обе границы по местному времени и исключает неизвестные даты при заданном диапазоне. Фильтр изображений/видео и сворачивание поста не меняют идентификаторы. После ограниченного числа пустых страниц можно продолжить вручную. `presentation: 'work'` открывает сведения о работе, `'post'` — полный пост. Обложки загружают лишь изображения или явные миниатюры, никогда ссылки воспроизведения.

- `coverBlurred: true` и `blurred: true` у медиа сохраняют размытие сайта в миниатюрах и полноразмерных фото. Не показывайте закрытые фото как полное изображение без размытия. Предпросмотры и полные видео сначала раскрывают мастер HLS, затем воспроизводят выбранный вариант VOD.
- Авторизованные вложения без прямой ссылки используют `media[].resource` и реализуют `mediaChunk(resource, offset)`: не больше 128 КиБ за вызов, смещения кратны 128 КиБ; resource должен содержать целое `size` и стабильную несекретную строку `cacheKey`, не меняющуюся вместе с учётными данными или временными ссылками. Фреймворк проверяет общий размер и каждый фрагмент и атомарно пишет в собственный кэш; одно вложение — до 512 МиБ, и resource не выбирает локальный путь. Подписанные ссылки и resource не сохраняются в записях подписок.
- Подписки с подпиской или вступлением на исходном сайте должны объяснять действие и требовать подтверждения перед сохранением. Непроверенные операции записи должны направлять на исходный сайт; нельзя незаметно подписываться, вступать или платить.

### Подписки на обновления: `updateSubscriptions`

Обычные плагины могут поддерживать «следить за обновлениями» отдельным объектом `updateSubscriptions`. Среда выводит `capabilities.subscriptionUpdates` только при наличии `check`; это не меняет ни категорию, ни `capabilities.subscription`. Метаданные включают `dimensions: [{ key, label, hint }]`; меню тегов может передавать исходный запрос и параметры фильтра.

- `normalize(dimension, input)` возвращает `{ id, label }`; `check({ dimension, target }, { cursor })` — `{ items, hasNext, cursor }`. Элементы — `{ id, title, kind, workId, chapterId }`, где `kind` только `work | post | chapter`, ID стабильные и непустые, без URL медиа, cookie и учётных данных. ID глав включают идентичность работы, чтобы «Глава 1» разных работ не совпадала.
- `Park.enableUpdateSubscriptions(Park.__pending, rules)` даёт общий адаптер; измерения объявляются явно в конце скрипта, при желании с `searchFilters` и `seriesPattern`. `work` использует настоящий список глав; `posts` — существующий API каналов; `search` и `filter` используют поиск, `code` точно совпадает с полным кодом, а `series` использует пути серий, проверенные по доменам сайта. Курсоры поиска хранят и номер страницы, и курсор сайта.
- Проверки поиска и постов возвращают `windowed: true`, то есть просматривают три последние страницы: первая проверка лишь записывает исходное состояние, последующие создают события «найдено новое» по стабильному ID, не утверждая дату публикации. Другие постраничные протоколы просматривают не больше трёх страниц за раз, сохраняя курсоры и кандидатов, и фиксируют всё одной транзакцией по завершении; списки глав никогда не обрезаются, кандидатов не больше 20 000 (превышение — ошибка). Сбои сети, прав, проверки, пустые списки и неполный разбор должны давать явные ошибки, а не пустой успех.
- Передний план и фон делят среду плагина, разделы cookie, ограничения доменов и механизм проверки. В фоне запускаются только нужные плагины, и они никогда не входят в аккаунт, не подписываются на сайте, не загружают медиа и не обходят права. Смена аккаунта или настроек плагина пересоздаёт исходное состояние (обновление токена — нет).

В методах через `this` доступны:

Глобальные помощники:

| Помощник | Описание |
| --- | --- |
| `Park.html.parse(text)` | возвращает стандартный `Document` для `querySelector` |

| `Park.crypto.digestBytes('sha1' \| 'sha256', bytes)` | массивы целых 0–255, до 2 МиБ |

| `Park.url.parse(value, base, domains)` / `site(source, value, base?)` / `response(source, response, requested)` | Разбирает HTTPS 443 URL разрешённых доменов и поддоменов, отклоняет учётные данные, убирает фрагмент; при ошибке возвращает `null`. `site` использует `domains` источника; `response` проверяет итоговый адрес, не изменяя общую базу источника, иначе выдаёт `BLOCKED`. Путь, страницу, произведение и поиск проверяет плагин; избегайте закрытых списков ключей запроса и имён узлов CDN. |

При ошибке аутентификации выдаёт исключение без неаутентифицированного текста.

### `http.request(opts)`

```js
await this.http.request({
  url, method: 'GET', headers: {}, params: { q: 'x' },   // params добавляются к URL
  json: {...} | form: {...} | body: 'raw' | bodyBase64: '...',
  timeout: 15000,
  responseType: 'text' | 'base64',
});
// → { status, headers, body, url, ok, json() }
```

- `text()` / `json()` бросают ошибку на ответы не из 2xx (404 → `NOT_FOUND`). Cookie сохраняются автоматически и подбираются заново для каждого адреса перенаправления.
- `bodyBase64` — двоичное тело (до 2 МиБ), несовместимое с `body` и режимом браузера; оно подчиняется тем же правилам изоляции доменов, TLS и перенаправлений, что и текстовые запросы. Плагины не могут сами открыть сеть браузера, WebSocket или произвольный доступ к файлам.

## Коды ошибок

Бросайте `throw Park.error(code, message, extra)`; приложение реагирует по коду:

| code | Что делает приложение |
| --- | --- |
| `CLOUDFLARE` | «Пройти проверку»: открывает встроенный браузер |
| `CONFIRM_REQUIRED` | «Подтвердить»: ждёт, пока пользователь пройдёт объявленное подтверждение доступа (`extra.url` указывает на него) |
| `LOGIN_REQUIRED` | «Войти»: открывает раздел аккаунта в настройках сайта |
| `NOT_FOUND` | показывает «Материал не найден» |
| `BLOCKED` | показывает «Доступ ограничен» (блокировка IP, исчерпана квота…); изображения не перезапрашиваются |
| `NETWORK` | показывает «Не удалось подключиться» с причиной и «Повторить» |
| `HTTP` / `PARSE` / `UNSUPPORTED` / `CONFIG` | показывает сообщение плагина и «Повторить» |

### Структурированные сообщения

`message` — это **шаблон на китайском**, он же ключ перевода; переменные части кладите в `extra.params`, а не склеивайте со строкой:

```js
throw Park.error('HTTP', '站点返回 HTTP {status}', { params: { status: res.status }, status: res.status });
throw Park.error('NOT_FOUND', '影片不存在');
```

Приложение переводит шаблон сначала собственным `i18n` плагина, затем общим словарём приложения и подставляет `params` в заполнители. Склеенную строку перевести нельзя — пользователи, не читающие по-китайски, увидят китайский текст. `status`, `url` и `diagnostics` в `extra` работают как прежде.

### Кэш главной и смысл ошибок

- Живые результаты `feed` сохраняют все поля. Приватный восстанавливаемый дисковый кэш хранит разрешённые метаданные работ, текст постов, данные доступа к вложениям и поддерживаемые поля подробностей, чтобы открывать записи до обновления. Он может содержать временные медиассылки и ссылки на ресурсы; истёкшие ссылки требуют обновления. Это не загрузки и не резервная копия. Идентичность кэша разделяет сайт, аккаунт, настройки и область запроса. Не помещайте учётные данные в возвращаемый контент, ID или курсоры и не копируйте данные доступа из кэша в диагностику или записи подписок.
- Устаревший кэш показывается как офлайн-содержимое только при явных ошибках `NETWORK` / `TIMEOUT` и помечается как кэш. Сбои входа, подтверждения, проверки на человека, разбора и настройки должны бросать свои ошибки; фреймворк никогда не выдаёт их за сетевые, и обновление по инициативе пользователя тоже показывает настоящую ошибку.

## Локализация

Интерфейс приложения поддерживает `zh-Hans`, `zh-Hant`, `ja`, `ko`, `en`, `es`, `ru` и `ar` (арабский — справа налево). Все статические тексты плагина, видимые пользователю (имя, описание, вкладки, параметры, подсказка поиска, пояснения к аккаунту, сообщения об ошибках), пишите на **упрощённом китайском**; исходный текст и есть ключ перевода.

Плагин несёт собственные переводы в поле `i18n` manifest:

```js
Park.register({
  i18n: {
    'zh-Hant': { '发行日期': '發行日期', '影片不存在': '影片不存在' },
    'en': { '发行日期': 'Release date', '影片不存在': 'Video not found', '站点返回 HTTP {status}': 'The site returned HTTP {status}' },
    // так же ja, ko, es, ru, ar
  },
  key: 'mysite',
  // …
});
```

- Порядок поиска: `i18n` плагина для текущего языка → `en` плагина (кроме упрощённого китайского) → общий словарь приложения (`assets/i18n/`, например «Сортировка», «Новое», «Популярное») → исходный текст.
- В `i18n` нужно класть только то, чего нет в приложении; общие слова берутся из его переводов. Заполнители `{name}` должны совпадать с оригиналом.
- Удалённое содержимое (названия, авторы, теги, описания), ввод пользователя и сохраняемые ключи протокола не переводятся как текст интерфейса.
- Изменение `i18n` — это изменение плагина, оно требует повышения версии. Пользователи старой версии видят прежние тексты до обновления.

Тексты интерфейса самого приложения вызываются через `tr('已选 {count}', { 'count': count })` или `context.tr`; восемь языковых файлов лежат в `assets/i18n/`, и любое добавление или изменение должно обновлять их все с теми же заполнителями.

## Публикация

### Репозитории

Репозиторий — это один `index.json` на любом статическом хостинге. Пользователь вводит его адрес в «Ещё → Сайты → Добавить сайт», чтобы смотреть, устанавливать и обновлять:

```json
{
  "name": "我的站点仓库",
  "apiVersion": 2,
  "sources": [
    {
      "key": "mysite",
      "name": "我的站点",
      "version": "0.0.1",
      "minAppVersion": "0.9.2",
      "description": "一句话介绍",
      "url": "https://example.com/sources/mysite.js",
      "sha256": "SHA-256 текста скрипта в UTF-8, 64 шестнадцатеричные цифры",
      "apiVersion": 2
    }
  ]
}
```

`url` — полный адрес скрипта; подойдёт и `file` относительно `index.json`. Сторонние репозитории устанавливаются вручную после подтверждения пользователя; `sha256` необязателен и проверяется, если указан.

### Версии и правила обновления

- Плагины должны объявлять minAppVersion (например, 0.9.2), совпадающую с официальным индексом. Текущая apiVersion — 2; требуется HentaiPark 0.9.2 или новее. Обновления и установка по URL проверяют совместимость до замены; при несовместимости установленный плагин сохраняется. Автоматические уведомления разделяют доступные обновления и плагины, которым нужна новая версия приложения. Игнорирование относится только к указанным версиям приложения или плагинов, сохраняется после перезапуска и не влияет на ручную проверку.

- Версия — три неотрицательных целых числа через точку без ведущих нулей (например, `0.0.1`), сравниваемые по частям численно; недостающие или лишние части и суффиксы предрелизов не принимаются.
- Официальные обновления должны указывать `sha256` текста скрипта в UTF-8 (без обрезки пробелов и преобразования переводов строк), а `key` и `version` скрипта должны совпадать с индексом; `apiVersion` должен в точности совпадать с версией среды приложения, иначе обновление отклоняется.
- Версии плагинов и приложения независимы. Меняя скрипт плагина (включая `i18n`), повышайте версию и в скрипте, и в `assets/sources/index.json`; публикатор отклоняет понижение версии и одну и ту же версию с разным содержимым.

### Официальные обновления в приложении

- «Проверять обновления плагинов при запуске» в «Ещё → Сайты» и «Ещё → О приложении → Обновления» включено по умолчанию: при каждом запуске читается только официальный индекс, о новых версиях сообщается, а загрузка, проверка и установка выполняются только после подтверждения. При возврате в приложение выдерживается интервал 12 часов, время проверки записывается и при неудаче. С выключенной автопроверкой работает ручная. Проверяются только установленные встроенные и официальные плагины; новые плагины не ставятся автоматически, а сторонние плагины с тем же key не перехватываются.
- При установке заново проверяются идентичность, версия, источник, API и хеш, и она завершается только после успешной инициализации и сохранения состояния; при сбое остаются старый скрипт и состояние пользователя, а прерванная установка восстанавливается при следующем запуске. Запуск никогда не перезаписывает установленные плагины встроенными скриптами; если скрипт пропал, его запись и данные сохраняются, пока пользователь не восстановит или не обновит его. «Вернуть встроенную версию» после подтверждения откатывает к версии из текущего пакета приложения.
- Обновления самого приложения тоже проверяются по умолчанию: на Android после подтверждения приложение скачивает подходящий официальный APK, проверяет размер, SHA-256, имя пакета, версию и подпись и открывает системный установщик — с прогрессом, отменой и повтором; запасной путь — официальная страница релизов.

### Публикация официальных плагинов

Официальные плагины ведутся в `assets/sources/index.json`. `tools/publish_sources.mjs` сверяет список с объявлениями среды без сети и создаёт индекс с неизменяемыми URL скриптов и SHA-256. Проверка не выполняет вход и методы сайтов и не заменяет реальные запросы. Сборка и публикация описаны в [руководстве разработчика](../../DEVELOPMENT.md).

### Генерируемые плагины

Единственная реализация плагина Telegram — `assets/sources/telegram_entry.mjs`; `assets/sources/telegram.js` генерируется, и править его вручную нельзя:

```powershell
npm ci --prefix 'tools/source-runner'
node tools/build_subscription_sources.mjs
```

Он использует [@mtproto/core 6.3.0](https://github.com/alik0211/mtproto-core) (GPL-3.0, [лицензия](../../licenses/mtproto-core.txt); сводка зависимостей — в [сторонних лицензиях](../../licenses/telegram-dependencies.txt)). Адаптер сайта заменяет транспорт, криптографию и хранилище и не включает стандартные WebSocket, localStorage браузера и отладочный журнал библиотеки.

### `webVideo(id, episodeId)`

Веб-плеер обрабатывает Cloudflare в отдельном временном сеансе. Разрешён только фрейм проверки с точным хостом `challenges.cloudflare.com`, но не переход основного фрейма на этот хост. `network.confirmation` применяется только к доменам источника, не к внешним плеерам. Если автоматическая проверка не завершилась, страница остаётся доступной для ручного ввода; Cookie плеера не импортируются и не экспортируются. `CONFIRM_REQUIRED` сохраняет сообщение плагина и открывает проверку внутри приложения. После явного завершения сеанс источника синхронизируется, исходная операция автоматически не повторяется.

Поддерживаемые источники iXXX и TubeSafari преимущественно воспроизводятся нативно, с продолжением просмотра и офлайн-сохранением. Остальные источники открываются во встроенном веб-плеере. Он может требовать подтверждения сайта и не поддерживает загрузку приложением и точное продолжение просмотра. Для веб-плеера Android нужен современный Android System WebView с изолированными сеансами.

Среда автоматически экспортирует `capabilities.webVideo`. Если реализован только `webVideo`, открывается встроенная веб-страница. Если реализованы и `videos`, и `webVideo`, приоритет имеет нативный плеер; переход к веб-странице происходит только при ошибке `UNSUPPORTED` от `videos`. Ошибки HTTP, сети, Cloudflare, входа, разбора, удалённого контента и отмены остаются видимыми. Загрузка доступна только для успешно полученных нативных медиаресурсов и не переходит к веб-странице.

```js
return { url: "https://player.example.com/watch/1", navigationDomains: ["player.example.com"], frameDomains: [] };
// Native HTTP only: this.http.get(url, { followRedirects: false })
```

## Рейтинги и отдельное распространение

`rankings` объявляет списки через `key`, `label`, `category`, `metric`, `options`. Специальный плагин задаёт `rankingOnly: true` без `feeds`. `ranking(board, {page, offset, cursor, options})` возвращает страницу произведений с `id`, исходным `rank`, `title`, `cover`, необязательными `keyword`, `subtitle` и HTTPS `url` товара. Равные места сохраняются. Существующий источник может указать `feed`: параметры наследуются, если опущены, а среда повторно использует `feed()`, сохраняет поля и добавляет `workId` и отсутствующий номер для открытия описания. Коммерческие записи ищут в указанной категории.

Исходники хранятся в основной ветке. Ветки `sources`, `rankings` и `reverse-search` распространяют обычные плагины, отдельные рейтинги и отдельный обратный поиск соответственно. В каждой находится индекс с URL фиксированных коммитов и SHA-256. Приложение читает каналы отдельно, отклоняет неверные маркеры и повторяющиеся key и запрашивает подтверждение обновлений. Переводы тегов распространяются через `tag-translations`.

```powershell
node tools/publish_sources.mjs --commit '<SHA>' --channel rankings --output '<本地输出文件>'
```
