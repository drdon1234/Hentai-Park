# Руководство по разработке плагина исходного кода

Каждый источник HentaiPark представляет собой отдельный файл JavaScript. Приложения загружают их во время выполнения: их можно устанавливать, обновлять, включать/деактивировать из исходного репозитория без перекомпиляции приложения.
Встроенный источник находится по адресу [`assets/sources/`](../../../assets/sources/) и может использоваться непосредственно в качестве примера.

## Рабочая среда

- Скрипты источников выполняются в WebView без интерфейса внутри приложения (современный JS с `DOMParser`). Нативный слой предоставляет криптографию, обработку Cookie и нативные HTTP-запросы. Для нативного HTTP нет ограничений CORS; сетевые и медиазапросы браузера подчиняются отдельным правилам ниже.
- Эту же среду выполнения ([`assets/runtime/park_runtime.js`](../../../assets/runtime/park_runtime.js)) можно запустить и в Node, и вы можете напрямую проводить дымовое тестирование на реальном сайте во время разработки:

Установите зависимости общего runner из корня и создайте игнорируемый `test/source-smoke.mjs` по примеру. Он лишь загружает manifest; добавьте реальные проверки главной, страницы2, поиска, деталей, декодирования обложки, глав и медиа изменённого источника. Хост Node — инструмент разработки, не безопасная изоляция недоверенных скриптов.

```js
import { loadSource } from '../tools/source-runner/host.mjs';
const { manifest } = await loadSource('nhentai.js');
console.log(manifest.key, manifest.version);
```

```powershell
npm ci --prefix 'tools/source-runner'
node 'test/source-smoke.mjs'
```

## Зарегистрируйте источник

```js
Park.register({
  key: 'mysite',              // Уникальный идентификатор, не может быть изменен после установки.
  name: 'Example Source',
  version: '0.0.1',           // Когда номер версии в хранилище выше, приложение предложит установить обновление.
  type: 'comic',              // comic | video | novel | game
  category: 'doujin',         // doujin | anime | aiDrama | jav | adult | shortvideo | gallery | novel | game | other
  color: '#E5355F',           // Цвет бренда: используется для исходных входных карточек и цветов темы исходной страницы.
  description: 'Example source description',
  homepage: 'https://example.com',
  domains: ['example.com'],                   // Информацию о сайте, которому он принадлежит, см. в разделе «Изоляция и безопасность»; если он опущен, он будет выведен из адреса, например домашней страницы.
  linkPatterns: ['example\\.com/g/(\\d+)'],   // Используется для прямого доступа при вставке ссылок в совокупный поиск; первая группа — это идентификатор работы
  idPattern: '^(\\d+)$',                      // Используется для прямого доступа при прямом вводе номера.
  imageHeaders: { Referer: 'https://example.com/' },  // Переносится по умолчанию при загрузке обложек и изображений.
  network: { mode: 'native', vpnHint: true },                // См. раздел «Сеть».
  media: { mode: 'browser', origin: 'https://example.com', domains: ['media.example.com'] },  // Необязательное разрешение HLS; см. ниже

  settings: [ /* option definitions */ ],
  account: { /* optional account */ },
  defaultFeed: 'ranking',                     // Ярлык, вводимый по умолчанию при открытии исходной страницы (введите фиды).
  feeds: [ /* browse tabs */ ],
  searchFilters: [ /* search filters */ ],
  searchHint: 'Search by title or tag',

  async init() {},                            // Необязательно: вызывается один раз при загрузке (например, при обновлении списка доменных имен).
  async onSettingsChanged() {},               // Необязательно: вызывается после того, как пользователь изменяет настройки источника.

  async feed(key, { page, cursor, options }) {},
  async search({ keyword, page, cursor, filters }) {},
  async random() {},                          // Возвращает идентификатор работы
  async detail(id, preview) {},
  async chapter(id, chapterId) {},            // комиксы
  async resolveImage({ id, chapterId, index, token, retry }) {},  // Необязательно: отложенный анализ изображений.
  async thumbnails(id, page) {},              // Необязательно: загрузите миниатюры предварительного просмотра на страницах.
  async videos(id, episodeId = '_') {},                        // видео
});
```

`type` определяет чтение или воспроизведение, а `category` — группы на главной странице, в управлении источниками и поиске. Неизвестные и отсутствующие категории попадают в «Другое». Для начальной ленты выбирайте рекомендации, затем рейтинг, затем популярное; новинки — только при отсутствии этих разделов.

Для ИИ-мини-драм используется `category: 'aiDrama'`; прежний идентификатор `drama` не принимается. Названия разделов сайта независимы от категории приложения и сохраняются без изменений. Категория приложения не фильтрует разделы сайта автоматически.

`adult` объединяет общие сайты, например Pornhub, XVideos и 91porn, с `type: 'video'`. Специализированные JAV-сайты используют `jav`. Категории не заменяют теги сайта или фильтры пользователя.

Агрегаторы также объявляют `type: 'video', category: 'adult'`. Без проверенного API не реализуйте `videos`: среда экспортирует `capabilities.videos: false`. Основное действие открывает `detail.url` в системном браузере; воспроизведение, загрузка и серии скрыты, фиктивные главы не синхронизируются и не проверяются на обновления. Избранное и история сохраняются. Необязательный `detail(id, preview)` получает публичные метаданные лишь при совпадении источника и ID; источник повторно проверяет ID и URL. iXXX использует внешнюю URL без известных параметров отслеживания как стабильный ID, TubeSafari сохраняет внешнюю ключевую строку. Внешние произведения не запрашиваются с Cookie источника. Прямые ссылки без preview открываются, но могут не иметь названия или обложки. Thumbzilla статически разбирает MP4-метаданные и ограничивает медиадомены.

`gallery` объединяет иллюстрации, косплей и фотосессии. Источники изображений сохраняют `type: 'comic'`: галерея соответствует одной работе, а `chapter()` возвращает изображения по порядку. Используются существующие просмотр, библиотека и загрузки. Категория не зависит от числа изображений или степени откровенности.

Объявляйте зашифрованные изображения через `imageDecrypt`. Расшифровка выполняется перед проверкой формата и кэшированием; стратегия входит в идентификатор кэша, ошибки не кэшируются. Поддерживается AES-CBC со строгим дополнением PKCS#7. `key` и `iv` кодируются в UTF-8; обязательно ограничьте домены изображений. Остальные изображения не изменяются.

```js
imageDecrypt: {
  type: 'aes-cbc',
  key: '0123456789abcdef', // UTF-8: 16, 24 or 32 bytes
  iv: '0123456789abcdef',  // UTF-8: 16 bytes
  domains: ['images.example.com'],
},
```

Сетевые ошибки содержат безопасные поля `diagnostics`: `host`, `transport` и `reason` для различения сертификатов, согласования TLS, DNS, соединения и тайм-аутов. Автоматические журналы записывают только разрешённые поля, без исходных сообщений, учётных данных, тел запросов и подписанных URL.

`reason: 'TLS_HANDSHAKE_TERMINATED'` означает только точное совпадение нативного `HandshakeException.message` с `Connection terminated during handshake`: соединение оборвалось до завершения TLS, а не из-за проверки сертификата. Только HTTPS GET / HEAD без тела повторяются один раз при этой ошибке. Отмена, сертификаты, другие ошибки TLS, HTTP и чтения ответа не повторяются. При повторном сбое показываются хост и рекомендация проверить VPN или прокси; журнал содержит только безопасную диагностику.

В методе вы можете использовать `this` для доступа:

| Участники | Описание |
|------|------|
| `this.http` | `request(opts)`, `get(url, opts)`, `post(url, opts)`, `text(url, opts)`, `json(url, opts)` |
| `this.config` | Значение, выбранное пользователем в настройках источника (`default`, если не установлено) |
| `this.store` | Постоянное хранилище значений ключа: `get(key, fallback)` / `set(key, value)`, используется для сохранения токена, списка доменных имен и т. д.; `await flush()` подтверждает успешную запись на диск и выдает ошибку в случае неудачи |
| `this.cookies` | `get(url)` / `set(url, {name: value})` / `clear(url)` |
| `this.log({code, host, transport, reason})` | Сохраняются только разрешённые структурированные поля; свободный текст удаляется. |

Глобальные инструменты:

### `http.request(opts)`

```js
await this.http.request({
  url, method: 'GET', headers: {}, params: { q: 'x' },   // параметры будут объединены в URL-адрес
  json: {...} | form: {...} | body: 'raw',
  timeout: 15000,
  responseType: 'text' | 'base64',
});
// → { status, headers, body, url, ok, json() }
```

`text()` / `json()` автоматически вызывают ошибку при ответе вне диапазона 2xx (404 → `NOT_FOUND`). Cookie сохраняются автоматически и выбираются заново для каждого адреса перенаправления. При переходе на другой origin исходные заголовки аутентификации не передаются; перенаправления на другой origin с сохранением тела запроса отклоняются.

## Структура данных

**Страница списка** (возвращаемое значение: `feed`/`search`)

```js
{
  items: [WorkItem], page: 1, totalPages: 20, total: 500,
  hasNext: true,
  cursor: '12345',        // Необязательно: сайты, на которых курсор переворачивает страницы (например, E-Hentai), возвращают курсор следующей страницы, и приложение вернет его таким, какой он есть, при следующем запросе.
}
// При возврате sections приложение выбирает разделы по ответу:
{ sections: [{ title: 'Latest chapters', items: [WorkItem] }], hasNext: false }
```

**Рабочий элемент**: `{ id, title, subtitle?, cover, coverAspect?, pages?, rating?, likes?, views?, language?, category?, badge?, badgeColor?, duration?, uploaded?, tags? }`

- `coverAspect` (ширина/высота) делает макет сетки перед загрузкой изображения, чтобы избежать прыжков.
- `badgeColor` Цвет, используемый для меток категорий (например, E-Hentai — традиционная цветовая схема для каждой категории).

**Подробности** (`detail`): все поля рабочего элемента, включая:

```js
{
  url, authors: [], description, uploader?, size?, comments?,
  tags: [{ namespace: 'artist', label: 'Author', tags: [{ name, keyword, filters?, count? }] }],
  chapters: [{ id, title }] | null,   // null представляет собой одну главу
  singleChapterId?,                   // Идентификатор главы, необходимый для работы с одной главой (например, «1» для Бики)
  thumbnails?: [url | {url, width, height, offsetX, offsetY}],   // Поддержка изображения спрайта
  related?: [WorkItem], series?: [WorkItem],
}
```

При нажатии на тег приложение выполняет поиск `keyword` и `filters` в источнике, поэтому тег можно сопоставить с собственным синтаксисом сайта (например, `artist:"xxx"`) или параметрами фильтра (например, Hanime1 из `tags[]`).

**Глава** (`chapter`)

```js
{ pages: [
  { url, headers?, fallbacks?: [url], width?, height?, transform? },  // Адрес известен
  { token: '12' },                                                      // Отложенное разрешение: приложение вызоветsolveImage.
]}
```

- `fallbacks`: резервное зеркало, попробуйте последовательно при сбое основного адреса.
- `transform: { type: 'unscramble-strips', segments: N }`: когда изображение разрезается на N полос по горизонтали и сохраняется в обратном порядке (JMComic), приложение будет восстановлено на графическом процессоре. Загруженный автономный файл сохраняет исходное изображение и восстанавливает его при отображении.
- `resolveImage` возвращает `{ url, headers?, width?, height?, cacheKey? }`. В случае сбоя приложение увеличит `retry` и вызовет снова, и источник может использовать это для изменения сервера (`nl` параметр E-Hentai).

**Видео** (`videos`): `[{ quality: 1080, label: '1080P', url, headers?, format?, preferred? }]`. Прямые ссылки на видео обычно имеют ограничение по времени, и приложение будет повторно получать его каждый раз перед воспроизведением/загрузкой.

- Источники видео возвращают `[{id, title}]` в порядке воспроизведения через `detail(id).chapters`. Каждый `id` должен быть постоянным; нельзя использовать качество или временный URL. Приложение использует один ID для выбора, отдельного прогресса, загрузки и продолжения и вызывает `videos(id, episodeId = '_')` для данного эпизода. Одиночное видео использует `singleChapterId`, а при его отсутствии — `'_'`.
- Если `format` не указан, используется существующий путь прямого воспроизведения и загрузки MP4. Для HLS необходимо явно вернуть `format: 'hls'` и объявить в manifest разрешение `media`, описанное ниже.
- Приложение сначала разворачивает главный плейлист HLS (`#EXT-X-STREAM-INF`) в отдельные плейлисты сегментов для каждого варианта, получает фактическое разрешение из `RESOLUTION` и передаёт варианты проигрывателю или загрузчику. Для главного плейлиста `quality` означает желаемое разрешение: по умолчанию выбирается максимальное доступное, не превышающее это значение, а если подходящего нет — самое высокое. Каждый вариант должен содержать звук и видео, мультиплексированные в MPEG-TS. Отдельные потоки `AUDIO`, `VIDEO` или `SUBTITLES` и URL вне `media.domains` отклоняются. Необязательные дорожки предпросмотра `#EXT-X-I-FRAME-STREAM-INF` игнорируются; их адреса не регистрируются и не запрашиваются. Если разрешение единственного медиаплейлиста неизвестно, укажите `label: '原画'`; метка переводится на язык интерфейса, а запрошенное качество не выдаётся за фактическое разрешение.
- Варианты HLS поддерживают только полные непрерывные MPEG-TS VOD с `#EXT-X-ENDLIST`. Поддерживается расшифровка CBC/PKCS7 для `METHOD=AES-128` и `KEYFORMAT=identity` (также при отсутствии KEYFORMAT), с ключом строго 16 байт и явным 128-битным IV либо IV из номера сегмента. Ключи остаются в памяти сеанса; расшифрованный TS проверяется общей цепочкой воспроизведения и загрузки. Прямой эфир, SAMPLE-AES, другие KEYFORMAT, `EXT-X-MAP`, `EXT-X-BYTERANGE`, fMP4, discontinuity и gap не поддерживаются. Нестандартный тег MissAV `#EXT-X-TOKEN` удаляется.
- Воспроизведение использует случайный порт, привязанный только к `127.0.0.1`, и случайный токен. Конечный реестр URL позволяет получать проверенные сегменты по мере необходимости; закрытие сеанса отменяет запросы. Офлайн-загрузка HLS сейчас поддерживается только на Android: каждый сегмент проверяется, сохраняется его SHA-256, а при возобновлении он проверяется повторно. Поддерживается отмена. Media3 на устройстве перепаковывает видео в MP4, и в офлайн-библиотеку попадает только готовый файл. Воспроизведение HLS на iOS/macOS в этот раз не проверялось и не должно описываться как проверенное.

## Определение опции

`feeds[].options`, `searchFilters`, `settings` используют тот же формат:

```js
{ key: 'sort', label: 'Sort', type: 'select', default: 'date',
  values: [{ value: 'date', label: 'Latest' }, { value: 'popular', label: 'Popular', color: '#f00' }] }
// type: select (один вариант) | multi (несколько вариантов) | number | text | password | switch
// В settings можно использовать options вместо values.
```

Каждый элемент в `feeds` представляет собой вкладку на исходной странице: `{ key, label, options?: [...] }`.

`defaultFeed` Указывает, какую вкладку следует открывать по умолчанию при открытии исходной страницы. Если соответствующий ключ не заполнен или не может быть найден, приложение автоматически выберет его в порядке «Рекомендация» > «Рейтинг» > «Популярные» (ключ включает `promote` / `recommend` / `featured`, а затем `rank`/`toplist`, затем `popular`/`hot`/`trending`), если нет, введите первый этикетка.

## сеть

- `network.mode: 'native'` (по умолчанию): собственный HTTP-запрос с использованием постоянных файлов cookie может проходить через прокси-сервер, установленный пользователем. Если обнаружен запрос Cloudflare, будет выдано `CLOUDFLARE`. Приложение поможет пользователю завершить проверку во встроенном браузере и синхронизировать общий файл cookie с собственным запросом.
- `network.mode: 'browser'` + `network.origin`: Запрос был сделан с источником `fetch()` на скрытой странице браузера, открытой по адресу `origin`, с реальным отпечатком браузера. Применяется к сайтам Cloudflare, которые более защищены (например, Hanime1). Если GET-запрос с тем же источником происхождения получает проверку Cloudflare, скрытый браузер открывает этот документ для автоматической проверки и один раз повторяет исходный запрос. При неудаче возвращается `CLOUDFLARE` и используется существующий процесс проверки.

## Разрешения для медиа (HLS)

Разрешение `media` независимо от `this.http`, `network` и синхронизации Cookie сайта. Оба способа передачи используют одинаковые правила доменов:

```js
domains: ['example.com'],
network: { mode: 'native' },
media: { mode: 'native', origin: 'https://example.com', domains: ['media.example.com'] },
```

- `media.mode` поддерживает `'native'` и `'browser'`. В обоих случаях `media.origin` должен принадлежать заявленному сайту, использовать HTTPS и порт 443, не содержать учётных данных, запроса или фрагмента URL.
- `media.domains` — отдельный список разрешённых медиадоменов с поддоменами; он не даёт доступа к Cookie сайта. Плейлисты, сегменты и ключи требуют HTTPS 443. Учётные данные и фрагменты URL, IP-адреса, localhost с поддоменами и `.local` отклоняются.
- `media.mode: 'native'` использует отдельный нативный клиент без Cookie сайта, Authorization и аутентификации прокси. Адрес каждого перенаправления проверяется до перехода. Разрешены только заголовки `Referer`, `Origin`, `Accept`, `Accept-Language`; первые два должны соответствовать `media.origin`.
- `media.mode: 'browser'` открывает сеанс в скрытом браузере на `media.origin` с `credentials: 'omit'`, `mode: 'cors'` и `redirect: 'error'`. Соблюдаются правила CORS CDN, перенаправления не выполняются.
- Размер ответа ограничен при потоковом чтении, URL проверяется повторно. Лимит плейлиста — 2 MiB, сегмента — 32 MiB, ключ AES-128 должен содержать строго 16 байт. Пустые и слишком большие ответы, а также запрещённые URL отклоняются. Правила `domains` и `network` с Cookie остаются независимыми.

## Изоляция и безопасность

- Каждый источник работает в **независимой** среде JS (каждый имеет неинтерфейсный WebView), и источники не могут видеть глобальные объекты друг друга; собственный мост распознает только среду, из которой поступает вызов, а сценарии не могут выдавать себя за другие источники.
- Каждый источник имеет независимую банку файлов cookie: запрос, выданный источником, принесет и сохранит только свой собственный файл cookie и не будет считывать статус входа в систему других источников.
- Cookie с атрибутом Secure не отправляются по HTTP. Доступ к странице проверки и импорт Cookie браузера проверяются по `domains` установленного источника; доступные атрибуты безопасности и срок действия сохраняются. Очистка Cookie источника или его удаление также закрывает связанные сеансы браузера и удаляет Cookie этого сайта. Система хранит Cookie сайтов браузера совместно, поэтому очистка влияет и на другие источники, объявляющие тот же сайт.
- `domains` объявляет сайт, которому принадлежит источник (доменное имя может быть зарегистрировано, имя субдомена включается автоматически). Только файлы cookie с этих сайтов будут синхронизироваться со встроенным браузером (совместно с Cloudflare аутентификацией, веб-входом), и `network.origin` в режиме браузера также должны принадлежать им. Если опущено, можно сделать вывод из `homepage`, `network.origin`, `account.cookieUrl/loginUrl`.
- При установке исходного кода с веб-сайта или склада приложение сначала прочитает информацию о скрипте в песочнице, которая не может быть подключена к Интернету, отобразит имя, версию, SHA-256, заявленный сайт и предупреждение о рисках для пользователя, а затем установит его после подтверждения. Запись `index.json` в исходном хранилище может иметь поле `sha256`, и в установке будет отказано, если содержимое загрузки не соответствует.

## Исходный склад

Репозиторий — это `index.json`, который можно разместить на статическом хостинге (например, GitHub raw). Пользователи могут просматривать, устанавливать и обновлять, введя адрес склада в «Управление исходным сайтом → Добавить источник»:

```json
{
  "name": "我的源仓库",
  "apiVersion": 1,
  "sources": [
    {
      "key": "mysite",
      "name": "我的站点",
      "version": "0.0.1",
      "description": "一句话介绍",
      "url": "https://example.com/sources/mysite.js",
      "sha256": "脚本 UTF-8 原文的 64 位十六进制 SHA-256",
      "apiVersion": 1
    }
  ]
}
```

`url` — полный адрес скрипта; Также можно использовать `file` относительно `index.json`. Сторонний склад устанавливается вручную после подтверждения пользователя. `sha256` не является обязательным. Загруженный контент будет проверен при его предоставлении.

Официальные обновления придерживаются строгих правил: версия должна представлять собой трехсегментное неотрицательное целое число, разделенное точками и без ведущих нулей (например, `0.0.1`, `0.1.0`), которое сравнивается сегмент за сегментом по номеру; отсутствующие сегменты, множественные сегменты или суффиксы предварительной версии не принимаются. Исходный текст сценария `sha256` в формате UTF-8 должен быть предоставлен без обрезки пробелов и преобразования новых строк; `key` и `version`, объявленные сценарием, должны соответствовать индексу. `apiVersion` должен полностью соответствовать текущей среде выполнения приложения. Если оно не совпадает, в обновлении будет отказано. Сначала вам необходимо использовать приложение, поддерживающее этот API; совместимая ветка не предусмотрена.

## Протокол подписок

Одновременное объявление `subscription.normalize` и `subscription.posts` создаёт `capabilities.subscription` для отдельного раздела подписок. Логика сайта остаётся в плагине. `normalize` проверяет имя/контролируемый URL профиля локально, без входа и сети. Необязательный `resolve` выполняет сетевое разрешение; `targets` возвращает присоединённые цели и создаёт `subscription.joinedTargets: true`. Курсор — непрозрачная строка; `hasNext: false` завершает, пустая страница может продолжаться. `locked` означает нехватку прав, `previewOnly` явно помечает превью.

```js
subscription: {
  normalize(input) { return { id: validatedTarget, label: displayName }; },
  async resolve(input) { return { id: validatedTarget, label: displayName }; },
  async targets() { return [{ id: joinedTarget, label: displayName }]; },
  async posts(target, { cursor }) {
    return {
      items: [{ id, title, text, date, url, locked, media: [
        { type: 'image', url, preview, previewOnly: false },
        { type: 'video', url, preview, format: 'mp4', headers: {} },
        { type: 'image', resource: { cacheKey, size } },
      ] }],
      cursor: nextCursor, hasNext: true,
    };
  },
  async mediaChunk(resource, offset) { return { base64, done }; },
}
```

Для вложений без прямой ссылки `media[].resource` содержит целое `size` и стабильный несекретный `cacheKey`, независимый от истекающих ссылок и учётных данных. `subscription.mediaChunk(resource, offset)` возвращает `{base64, done}`: до128 KiB, выровненные смещения, полные промежуточные блоки, до512 MiB на вложение. Хост проверяет размер и атомарно пишет в свой кеш, защищая используемые файлы. Ресурс не задаёт путь; подписки в копии не содержат подписанных URL/resource.

Существующий сеанс передаётся как `account.type: 'session'` с секретным полем и проверяется плагином без разбиения на пароль/Cookie. Успех входа подтверждается реальной авторизацией. Сохранение не выполняет подписку/вступление. Нативный `bodyBase64` ограничен2 MiB и несовместим с body/браузерным режимом; возможен ответ base64. `digestBytes('sha1'|'sha256', bytes)` принимает до2 MiB целых байтов, `randomBytes(length)` —1–65536. TLS, изоляция доменов и ограничения перенаправлений сохраняются; произвольная браузерная сеть, WebSocket и файлы запрещены.
