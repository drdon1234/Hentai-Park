# Руководство по разработке плагина исходного кода

Каждый источник HentaiPark представляет собой отдельный файл JavaScript. Приложения загружают их во время выполнения: их можно устанавливать, обновлять, включать/деактивировать из исходного репозитория без перекомпиляции приложения.
Встроенный источник находится по адресу [`assets/sources/`](../../../assets/sources/) и может использоваться непосредственно в качестве примера.

## Рабочая среда

- Скрипты источников выполняются в WebView без интерфейса внутри приложения (современный JS с `DOMParser`). Нативный слой предоставляет криптографию, обработку Cookie и нативные HTTP-запросы. Для нативного HTTP нет ограничений CORS; сетевые и медиазапросы браузера подчиняются отдельным правилам ниже.
- Эту же среду выполнения ([`assets/runtime/park_runtime.js`](../../../assets/runtime/park_runtime.js)) можно запустить и в Node, и вы можете напрямую проводить дымовое тестирование на реальном сайте во время разработки:

  ```bash
  cd tools/source-runner && npm install
  node ../../test/source-runner/smoke.mjs nhentai.js --keyword "tag:\"full color\""
  ```

  `smoke.mjs` — локальный тестовый файл в `test/source-runner/`, который не распространяется с репозиторием. Он проверяет каждую ленту (включая вторую страницу), поиск, случайные произведения, сведения, обложки, главы и загрузку изображений первой и последней страниц.

## Зарегистрируйте источник

```js
Park.register({
  key: 'mysite',              // Уникальный идентификатор, не может быть изменен после установки.
  name: 'Example Source',
  version: '0.0.1',           // Когда номер версии в хранилище выше, приложение предложит установить обновление.
  type: 'comic',              // comic | video
  color: '#E5355F',           // Цвет бренда: используется для исходных входных карточек и цветов темы исходной страницы.
  description: 'Example source description',
  homepage: 'https://example.com',
  domains: ['example.com'],                   // Информацию о сайте, которому он принадлежит, см. в разделе «Изоляция и безопасность»; если он опущен, он будет выведен из адреса, например домашней страницы.
  linkPatterns: ['example\\.com/g/(\\d+)'],   // Используется для прямого доступа при вставке ссылок в совокупный поиск; первая группа — это идентификатор работы
  idPattern: '^(\\d+)$',                      // Используется для прямого доступа при прямом вводе номера.
  imageHeaders: { Referer: 'https://example.com/' },  // Переносится по умолчанию при загрузке обложек и изображений.
  network: { mode: 'native' },                // См. раздел «Сеть».
  media: { mode: 'browser', origin: 'https://example.com', domains: ['media.example.com'] },  // Необязательное разрешение HLS; см. ниже

  settings: [ /* option definitions */ ],
  account: { /* optional account */ },
  defaultFeed: 'ranking',                     // Ярлык, вводимый по умолчанию при открытии исходной страницы (введите фиды).
  feeds: [ /* browse tabs */ ],
  searchFilters: [ /* search filters */ ],
  searchHint: 'Search by title or tag',

  async init() {},                            // Необязательно: вызывается один раз при загрузке (например, при обновлении списка доменных имен).
  async onSettingsChanged() {},               // Необязательно: вызывается после того, как пользователь изменяет настройки источника.

  async feed(key, { page, cursor, options }) {},
  async search({ keyword, page, cursor, filters }) {},
  async random() {},                          // Возвращает идентификатор работы
  async detail(id) {},
  async chapter(id, chapterId) {},            // комиксы
  async resolveImage({ id, chapterId, index, token, retry }) {},  // Необязательно: отложенный анализ изображений.
  async thumbnails(id, page) {},              // Необязательно: загрузите миниатюры предварительного просмотра на страницах.
  async videos(id) {},                        // видео
});
```

В методе вы можете использовать `this` для доступа:

| Участники | Описание |
|------|------|
| `this.http` | `request(opts)`, `get(url, opts)`, `post(url, opts)`, `text(url, opts)`, `json(url, opts)` |
| `this.config` | Значение, выбранное пользователем в настройках источника (`default`, если не установлено) |
| `this.store` | Постоянное хранилище значений ключа: `get(key, fallback)` / `set(key, value)`, используется для сохранения токена, списка доменных имен и т. д.; `await flush()` подтверждает успешную запись на диск и выдает ошибку в случае неудачи |
| `this.cookies` | `get(url)` / `set(url, {name: value})` / `clear(url)` |
| `this.log(...)` | Запись в «Журнал выполнения» приложения |

Глобальные инструменты:

| Инструменты | Инструкции |
|------|------|
| `Park.html.parse(text)` | Стандарт возврата `Document`, можно использовать `querySelector` |
| `Park.html.text(node)` / `unescape(s)` / `strip(html)` | Обработка текста |
| `Park.crypto.md5Hex(text \| text[])` | MD5, вы можете передавать массивы для пакетного расчета |
| `Park.crypto.sha256Hex` / `hmacSha256Hex(key, text)` / `aesEcbDecrypt(base64, key)` / `uuid()` | Собственная реализация, быстрая |
| `Park.utils.rateLimiter(ms)` | Возвращает `wait()`, обеспечивая минимальный интервал между двумя запросами |
| `Park.utils.mapLimit(items, n, fn)` / `lruMap(n)` / `parseCount('1.2万')` / `formatDate(ts)` | Другие часто используемые инструменты |
| `Park.error(code, message)` | Выдает ошибку с кодом ошибки, см. ниже |

### `http.request(opts)`

```js
await this.http.request({
  url, method: 'GET', headers: {}, params: { q: 'x' },   // параметры будут объединены в URL-адрес
  json: {...} | form: {...} | body: 'raw',
  timeout: 15000,
  responseType: 'text' | 'base64',
});
// → { status, headers, body, url, ok, json() }
```

`text()` / `json()` автоматически вызывают ошибку при ответе вне диапазона 2xx (404 → `NOT_FOUND`). Cookie сохраняются автоматически и выбираются заново для каждого адреса перенаправления. При переходе на другой origin исходные заголовки аутентификации не передаются; перенаправления на другой origin с сохранением тела запроса отклоняются.

## Структура данных

**Страница списка** (возвращаемое значение: `feed`/`search`)

```js
{
  items: [WorkItem], page: 1, totalPages: 20, total: 500,
  hasNext: true,
  cursor: '12345',        // Необязательно: сайты, на которых курсор переворачивает страницы (например, E-Hentai), возвращают курсор следующей страницы, и приложение вернет его таким, какой он есть, при следующем запросе.
}
// Или макет раздела (если макет канала — «разделы»):
{ sections: [{ title: 'Latest chapters', items: [WorkItem] }], hasNext: false }
```

**Рабочий элемент**: `{ id, title, subtitle?, cover, coverAspect?, pages?, rating?, likes?, views?, language?, category?, badge?, badgeColor?, duration?, uploaded?, tags? }`

- `coverAspect` (ширина/высота) делает макет сетки перед загрузкой изображения, чтобы избежать прыжков.
- `badgeColor` Цвет, используемый для меток категорий (например, E-Hentai — традиционная цветовая схема для каждой категории).

**Подробности** (`detail`): все поля рабочего элемента, включая:

```js
{
  url, authors: [], description, uploader?, size?, comments?,
  tags: [{ namespace: 'artist', label: 'Author', tags: [{ name, keyword, filters?, count? }] }],
  chapters: [{ id, title }] | null,   // null представляет собой одну главу
  singleChapterId?,                   // Идентификатор главы, необходимый для работы с одной главой (например, «1» для Бики)
  thumbnails?: [url | {url, width, height, offsetX, offsetY}],   // Поддержка изображения спрайта
  related?: [WorkItem], series?: [WorkItem],
}
```

При нажатии на тег приложение выполняет поиск `keyword` и `filters` в источнике, поэтому тег можно сопоставить с собственным синтаксисом сайта (например, `artist:"xxx"`) или параметрами фильтра (например, Hanime1 из `tags[]`).

**Глава** (`chapter`)

```js
{ pages: [
  { url, headers?, fallbacks?: [url], width?, height?, transform? },  // Адрес известен
  { token: '12' },                                                      // Отложенное разрешение: приложение вызоветsolveImage.
]}
```

- `fallbacks`: резервное зеркало, попробуйте последовательно при сбое основного адреса.
- `transform: { type: 'unscramble-strips', segments: N }`: когда изображение разрезается на N полос по горизонтали и сохраняется в обратном порядке (JMComic), приложение будет восстановлено на графическом процессоре. Загруженный автономный файл сохраняет исходное изображение и восстанавливает его при отображении.
- `resolveImage` возвращает `{ url, headers?, width?, height?, cacheKey? }`. В случае сбоя приложение увеличит `retry` и вызовет снова, и источник может использовать это для изменения сервера (`nl` параметр E-Hentai).

**Видео** (`videos`): `[{ quality: 1080, label: '1080P', url, headers?, format?, preferred? }]`. Прямые ссылки на видео обычно имеют ограничение по времени, и приложение будет повторно получать его каждый раз перед воспроизведением/загрузкой.

- Если `format` не указан, используется существующий путь прямого воспроизведения и загрузки MP4. Для HLS необходимо явно вернуть `format: 'hls'` и объявить в manifest разрешение `media`, описанное ниже.
- Приложение сначала разворачивает главный плейлист HLS (`#EXT-X-STREAM-INF`) в отдельные плейлисты сегментов для каждого варианта, получает фактическое разрешение из `RESOLUTION` и передаёт варианты проигрывателю или загрузчику. Для главного плейлиста `quality` означает желаемое разрешение: по умолчанию выбирается максимальное доступное, не превышающее это значение, а если подходящего нет — самое высокое. Каждый вариант должен содержать звук и видео, мультиплексированные в MPEG-TS. Отдельные потоки `AUDIO`, `VIDEO` или `SUBTITLES` и URL вне `media.domains` отклоняются.
- Развёрнутые варианты HLS поддерживают только полные непрерывные плейлисты MPEG-TS для видео по запросу с тегом `#EXT-X-ENDLIST`. Прямые трансляции, шифрование, диапазоны байтов, fMP4, discontinuity и gap не поддерживаются. Нестандартный тег MissAV `#EXT-X-TOKEN` удаляется до передачи плейлиста проигрывателю.
- Воспроизведение использует случайный порт, привязанный только к `127.0.0.1`, и случайный токен. Конечный реестр URL позволяет получать проверенные сегменты по мере необходимости; закрытие сеанса отменяет запросы. Офлайн-загрузка HLS сейчас поддерживается только на Android: каждый сегмент проверяется, сохраняется его SHA-256, а при возобновлении он проверяется повторно. Поддерживается отмена. Media3 на устройстве перепаковывает видео в MP4, и в офлайн-библиотеку попадает только готовый файл. Воспроизведение HLS на iOS/macOS в этот раз не проверялось и не должно описываться как проверенное.

## Определение опции

`feeds[].options`, `searchFilters`, `settings` используют тот же формат:

```js
{ key: 'sort', label: 'Sort', type: 'select', default: 'date',
  values: [{ value: 'date', label: 'Latest' }, { value: 'popular', label: 'Popular', color: '#f00' }] }
// type: select (один вариант) | multi (несколько вариантов) | number | text | password | switch
// В settings можно использовать options вместо values.
```

Каждый элемент в `feeds` представляет собой вкладку на исходной странице: `{ key, label, layout?: 'grid' | 'sections', options?: [...] }`.

`defaultFeed` Указывает, какую вкладку следует открывать по умолчанию при открытии исходной страницы. Если соответствующий ключ не заполнен или не может быть найден, приложение автоматически выберет его в порядке «Рекомендация» > «Рейтинг» > «Популярные» (ключ включает `promote` / `recommend` / `featured`, а затем `rank`/`toplist`, затем `popular`/`hot`/`trending`), если нет, введите первый этикетка.

## сеть

- `network.mode: 'native'` (по умолчанию): собственный HTTP-запрос с использованием постоянных файлов cookie может проходить через прокси-сервер, установленный пользователем. Если обнаружен запрос Cloudflare, будет выдано `CLOUDFLARE`. Приложение поможет пользователю завершить проверку во встроенном браузере и синхронизировать общий файл cookie с собственным запросом.
- `network.mode: 'browser'` + `network.origin`: Запрос был сделан с источником `fetch()` на скрытой странице браузера, открытой по адресу `origin`, с реальным отпечатком браузера. Применяется к сайтам Cloudflare, которые более защищены (например, Hanime1). Если GET-запрос с тем же источником происхождения получает проверку Cloudflare, скрытый браузер открывает этот документ для автоматической проверки и один раз повторяет исходный запрос. При неудаче возвращается `CLOUDFLARE` и используется существующий процесс проверки.

## Медиа в браузере (HLS)

Разрешение для медиа в браузере отделено от `this.http`, `network` и синхронизации Cookie сайта. Пример MissAV:

```js
domains: ['missav.ai'],
network: { mode: 'browser', origin: 'https://missav.ai' },
media: { mode: 'browser', origin: 'https://missav.ai', domains: ['surrit.com'] },
```

- `media.origin` должен принадлежать сайту, объявленному источником, использовать HTTPS на стандартном порту 443 и не содержать учётных данных в URL. Скрытый браузер создаёт медиасеанс на этой странице с тем же источником происхождения.
- `media.domains` — отдельный список разрешённых медиадоменов, включая их поддомены; он не даёт доступа к Cookie исходного сайта. Для плейлистов и сегментов разрешён только HTTPS на порту 443. Учётные данные и фрагменты в URL, IP-адреса, localhost (включая поддомены) и `.local` отклоняются. Запросы используют `credentials: 'omit'`, `mode: 'cors'` и `redirect: 'error'`, соблюдают правила CORS CDN и не следуют перенаправлениям.
- Размер ответа ограничивается при потоковом чтении, а его URL проверяется повторно. Плейлист ограничен 2 MiB, каждый сегмент — 32 MiB; слишком большие и пустые ответы, а также изменения URL отклоняются. Правила принадлежности сайта в `domains` и запросов `network` с тем же источником происхождения и Cookie не меняются; медиадомены не могут использовать состояние входа на сайт.

## Изоляция и безопасность

- Каждый источник работает в **независимой** среде JS (каждый имеет неинтерфейсный WebView), и источники не могут видеть глобальные объекты друг друга; собственный мост распознает только среду, из которой поступает вызов, а сценарии не могут выдавать себя за другие источники.
- Каждый источник имеет независимую банку файлов cookie: запрос, выданный источником, принесет и сохранит только свой собственный файл cookie и не будет считывать статус входа в систему других источников.
- `domains` объявляет сайт, которому принадлежит источник (доменное имя может быть зарегистрировано, имя субдомена включается автоматически). Только файлы cookie с этих сайтов будут синхронизироваться со встроенным браузером (совместно с Cloudflare аутентификацией, веб-входом), и `network.origin` в режиме браузера также должны принадлежать им. Если опущено, можно сделать вывод из `homepage`, `network.origin`, `account.cookieUrl/loginUrl`.
- При установке исходного кода с веб-сайта или склада приложение сначала прочитает информацию о скрипте в песочнице, которая не может быть подключена к Интернету, отобразит имя, версию, SHA-256, заявленный сайт и предупреждение о рисках для пользователя, а затем установит его после подтверждения. Запись `index.json` в исходном хранилище может иметь поле `sha256`, и в установке будет отказано, если содержимое загрузки не соответствует.

## Аккаунт

```js
account: {
  type: 'password' | 'cookies',
  title, hint, required: false,
  fields: [{ key: 'email', label: 'Email' }, { key: 'password', label: 'Password', secret: true }],
  loginUrl?, cookieUrl?, requiredCookies?: ['ipb_member_id'],   // После его предоставления вы можете войти на веб-страницу, и приложение автоматически получит файл cookie.
  async login(values) { return { name } },
  async logout() {},
  async status() { return { loggedIn, name, configured } },
  managedAccount: true,                 // Необязательно: предоставьте специальную учетную запись автоматического обслуживания.
  async enableManaged() {},             // Звонок только после подтверждения пользователем регистрации
}
```

`configured` указывает, что учетная запись настроена, независимо от того, успешен ли текущий вход в систему. `managedAccount: true` заявляет, что источник поддерживает выделенную учетную запись автоматического обслуживания; В настройках источника используется одноименный переключатель `managedAccount`. Хост должен сначала отобразить инструкции по автоматической регистрации и получить подтверждение пользователя, прежде чем сохранять настройки включения и звонить по номеру `account.enableManaged()`. Учетные данные кандидата должны быть сохранены и `await this.store.flush()` использоваться перед регистрацией, чтобы обеспечить возможность восстановления той же учетной записи после сбоя или перезапуска приложения.

В примере PicACG учетные данные, введенные вручную, и выделенные учетные записи сохраняются отдельно, а существующие учетные записи, созданные вручную, не должны перезаписываться выделенными учетными записями. Выключите переключатель, чтобы сохранить выделенную учетную запись, и снова включите ее для повторного использования; если срок действия токена истечет, вы сможете только снова войти в систему и больше не регистрироваться. После сбоя регистрации или потери ответа повторите попытку использования исходной учетной записи кандидата, чтобы избежать создания избыточных учетных записей. Пароль учетной записи, токен и статус источника — это локальные данные пользователя. Не указывайте настоящие учетные данные в документах и ​​журналах.

## Интернационализация

Поддержка интерфейса приложения `zh-Hans`, `zh-Hant`, `ja`, `ko`, `en`, `es`, `ru`, `ar`. Элементы управления материалом, Купертино и системой используют соответствующие языки; арабский интерфейс идет справа налево. Настройка языка интерфейса вступает в силу немедленно и сохраняется навсегда. По умолчанию он соответствует системе; Китайские сценарии и регионы определяют, использовать ли упрощенный или традиционный китайский язык.

Интерфейс Flutter единообразно вызывает `tr('已选 {count}', {'count': count})` или `context.tr`. Исходный текст сообщения на китайском языке используется в качестве ключа ресурса, параметр — `{name}`, а восьмиязычный ресурс расположен по адресу `assets/i18n/`. При добавлении или изменении видимой копии все ресурсы должны обновляться одновременно, а заполнители должны быть согласованными. Статическое имя, описание, метка просмотра, параметры и сообщения об ошибках подключаемого модуля сопоставляются с ресурсами при отображении приложения; название, автор, тег, пользовательский ввод и ключ протокола сохранения удаленной работы остаются исходным текстом.

## Код ошибки

Используйте `throw Park.error(code, message)`, чтобы выдать ошибку, и приложение предоставит соответствующие рекомендации на основе кода ошибки:

| код | Обработка приложений |
|------|-----------|
| `CLOUDFLARE` | Кнопка «Перейти к проверке»: Открыть встроенный браузер |
| `LOGIN_REQUIRED` | Кнопка «Перейти к входу»: Открыть раздел учетной записи в настройках источника |
| `NOT_FOUND` | Отобразить «Содержимое не существует» |
| `BLOCKED` | Отображает «Доступ ограничен» (например, IP-адрес заблокирован, квота исчерпана), повторная попытка изображения не будет |
| `NETWORK` / `HTTP` / `PARSE` | Отображение сообщения об ошибке с помощью кнопки «Повторить попытку» |

## Исходный склад

Репозиторий — это `index.json`, который можно разместить на статическом хостинге (например, GitHub raw). Пользователи могут просматривать, устанавливать и обновлять, введя адрес склада в «Управление исходным сайтом → Добавить источник»:

```json
{
  "name": "我的源仓库",
  "apiVersion": 1,
  "sources": [
    {
      "key": "mysite",
      "name": "我的站点",
      "version": "0.0.1",
      "description": "一句话介绍",
      "url": "https://example.com/sources/mysite.js",
      "sha256": "脚本 UTF-8 原文的 64 位十六进制 SHA-256",
      "apiVersion": 1
    }
  ]
}
```

`url` — полный адрес скрипта; Также можно использовать `file` относительно `index.json`. Сторонний склад устанавливается вручную после подтверждения пользователя. `sha256` не является обязательным. Загруженный контент будет проверен при его предоставлении.

Официальные автоматические обновления придерживаются строгих правил: версия должна представлять собой трехсегментное неотрицательное целое число, разделенное точками и без ведущих нулей (например, `0.0.1`, `0.1.0`), которое сравнивается сегмент за сегментом по номеру; отсутствующие сегменты, множественные сегменты или суффиксы предварительной версии не принимаются. Исходный текст сценария `sha256` в формате UTF-8 должен быть предоставлен без обрезки пробелов и преобразования новых строк; `key` и `version`, объявленные сценарием, должны соответствовать индексу. `apiVersion` должен полностью соответствовать текущей среде выполнения приложения. Если оно не совпадает, в автоматическом обновлении будет отказано. Сначала вам необходимо использовать приложение, поддерживающее этот API; совместимая ветка не предусмотрена.

### Официальные обновления в приложении

«Управление исходным сайтом» по умолчанию включает «Автоматическое обновление официальных источников» и проверяется каждые 12 часов при запуске или возврате на передний план; в случае неудачи также записывается время проверки, чтобы избежать частых повторных попыток. Проверка наличия обновлений теперь по-прежнему доступна после отключения автоматического обновления. Он обновляет только установленные встроенные источники и официальные онлайн-источники. Он не устанавливает автоматически новые источники и не заменяет сторонние одноименные источники, установленные пользователями.

Проверьте личность, версию, API и дайджест во время установки и дождитесь успешного завершения инициализации и сохранения состояния, прежде чем завершать обновление. Невозможность сохранить старый сценарий и статус пользователя; если приложение будет прервано во время установки, оно будет восстановлено при следующем запуске. Новая онлайн-версия имеет приоритет над более старыми или идентичными версиями встроенных сценариев, а новый установочный пакет можно обычно обновлять, если он содержит более новую версию. «Восстановление встроенных источников» позволяет активно откатиться к текущей версии установочного пакета; если вы позже включите автоматические обновления, вы все равно продолжите получать официальную новую версию.

### Публикация официальных источников

В официальном источнике указан основной общедоступный склад [drdon1234/Hentai-Park](https://github.com/drdon1234/Hentai-Park), а фиксированный вход для клиента:

```text
https://raw.githubusercontent.com/drdon1234/Hentai-Park/sources/index.json
```

`assets/sources/index.json` — это единственный поддерживаемый список исходного кода, а `file` указывает на единственный исходный код сценария в том же каталоге. Имя файла должно соответствовать `[A-Za-z0-9_-]+.js`. Подкаталоги, символические ссылки или точки в теле имени файла не принимаются и должны соответствовать официальной проверке исходного адреса клиента. `tools/publish_sources.mjs` Создать индекс публикации: каждая запись содержит `key`, `name`, `version`. ,`description`, `url`, `sha256` и `apiVersion`. URL-адрес сценария фиксируется на полном 40-значном номере фиксации этого исходного кода:

```text
https://raw.githubusercontent.com/drdon1234/Hentai-Park/<源码提交 SHA>/assets/sources/<file>
```

Ветка `sources` сохраняет только сгенерированный корневой каталог `index.json`, без копирования сценария или ручного сохранения второго списка источников. При обновлении сценария версии сценария и манифеста должны быть обновлены одновременно; издатель отказывается понижать версию, а также отказывается использовать одну и ту же версию для другого содержимого сценария. Одну и ту же версию можно публиковать повторно с неизмененным содержимым, и старая индексная версия не повлияет на обычные обновления.

Издатель полагается только на встроенный модуль Node.js и может работать в автономном режиме в версии Node.js 22 или новее. Он проверяет манифесты, существование файлов и границы каталогов, загружает общую среду выполнения и сценарии в отдельном контексте, который не предоставляет сетевых интерфейсов или интерфейсов хранилища, и проверяет, используя те же зонды `Park.__pending` / `Park.manifest`, что и предварительный просмотр установки приложения `key`, `version` и API. Обнаружение не вызывает `setup`, `init`, бизнес-методы входа или сайта и не может заменить проверку удобства использования сети исходного сайта.

Пример локального предварительного просмотра (выходной код `test/`, который был проигнорирован и не будет опубликован; номер фиксации должен использовать реальный SHA соответствующего исходного кода):

```powershell
node tools/publish_sources.mjs --commit '<完整 40 位源码提交 SHA>' --output 'test/official-source-index.json'
```

Если вам нужно проверить наличие существующих выпусков, введите `--previous '旧索引本地路径'`. Если проверка не удалась, когда старый индекс недействителен, защита версии не будет автоматически пропущена. Если в рабочей области есть незафиксированные изменения, локальные результаты используются только для предварительного просмотра; Официальный выпуск создается путем отправки исходного кода, проверенного рабочим процессом.

`.github/workflows/publish-sources.yml` Запускается только тогда, когда основной репозиторий по умолчанию `main` отправляет файлы, связанные с ветвью, или запускает вручную из `main`. Рабочий процесс выполняется последовательно, и извлекается последняя версия `main`. в начале каждой задачи, а адрес сценария и запись выпуска фиксируются с фактическим номером извлеченной фиксации. Последующие отправки документов во время выполнения задачи не помешают публикации; последующие отправки исходного файла инициируют следующую последовательную задачу. Рабочий процесс сначала загружает существующий стабильный индекс и завершает всю автономную проверку, а затем использует обычный Git для отправки атомарного обновления в ветку `sources`; онлайн-индекс не будет перезаписан в случае сбоя проверки или одновременного изменения в ветке `sources`. Публикация впервые может быть создана без стабильного индекса. В релизе лишь указано, что скрипт и индекс прошли вышеуказанную проверку. Доступ к сайту, вход в учетную запись и загрузка изображений или видео по-прежнему требуют отдельного подтверждения.
