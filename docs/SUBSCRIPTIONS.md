# 订阅功能与能力验证

入口为“发现 → 订阅”和“我的 → 订阅与通知设置”。无账号也可保存目标，访问取决于原站权限。`capabilities.subscriptionUpdates` 与动态浏览的 `capabilities.subscription` 分开，普通源不会因支持更新订阅从原分类消失。

已添加的订阅可在列表菜单中选择“编辑订阅”，修改目标和备注名称。仅修改备注保留检查进度；修改目标保留检查开关、通知开关与列表顺序，并为新目标建立基线，旧请求结果不再写入。重复目标拒绝保存，保存失败保留输入供重试。

目标、检查点、已见 ID、更新事件及通知队列在书库 SQLite 的独立表中。旧 `subscriptions.json` 只导入一次并保留原文件及必要快照，之后只写数据库；备份恢复同事务合并目标，保留现有名称和状态，新增目标建立新基线。

维度由源插件声明：频道/博主、真实作品章节、搜索关键词、详情标签或作者筛选；JAV 另支持完整番号。123AV 和 MissAV 提供站点系列路径或本站系列链接，其他 JAV 源不把番号前缀冒称官方系列。单篇正文分页不作为章节更新。

搜索和动态检查最近三页滚动窗口，记录表示“新发现内容”，不保证原站发布时刻；章节目录完整检查，普通分页协议按每轮三页预算持久续查。首次基线不推送历史，稳定 ID 去重。账号或源配置改变重建基线；账号 Token 续期和错误冷却计数不会重建基线。失败记录安全错误码并指数退避，候选上限 20,000，超限报错不截断。

默认 6 小时，可关闭或设 1/3/6/12/24 小时；支持启动、恢复、手动检查。两源并发、同源串行，五分钟数据库租约防同目标竞争。事件按源、类型、稳定 ID 跨目标去重。Android JobScheduler 启动独立 Flutter 引擎与原沙箱，仅加载启用订阅关联的源，不主动刷新全部账号状态；源读取仍使用用户已授权的会话续期和账号维护逻辑。前台启动先等待后台取消和写入完成；保留 Cookie 分区、域白名单及 TLS 校验。系统可能推迟任务，不承诺实时通知。

应用内记录不依赖通知权限。系统通知需用户开启并授权，默认不显示标题；成功才标记投递，拒绝或频道关闭稍后重试，稳定通知 ID 避免叠加。最多展示最近 500 条，可进入作品或频道。移除目标停止其通知，历史事件保留，应用锁继续遮挡内容。

2026-10-13 验证：39 源声明和版本离线通过；多类源已真实请求搜索、分页、章节或动态，123AV 真实系列链接检查返回两部作品。Pica 需登录，hanime1/MissAV/Jable/SupJav 等被验证页阻断，其他部分站点仍有访问限制。Android 独立测试应用验证了进程退出后的无界面源引擎、持久 Cookie、首次基线、新增通知、重复去重及系统通知点击冷启动导航，未替换用户原应用。

## 登录及权限

X 的 auth_token 和 ct0 不是一次性参数；ct0 必须与 X-CSRF-Token 对应。会话可能到期或被撤销。登录接口从当前网页加载操作编号和 feature flags，再读取 UserTweets 并过滤目标作者媒体，排除其他作者、转推和引用帖。匿名第三方代理不会收到 X Cookie。此接口属于网页内部接口，站点改版仍可能使读取失败。

Telegram 的本地存储不是 Cookie。导入内容需有 `dc` 和对应的 `dcN_auth_key`（512 位十六进制字符串），可以是 JSON 或 key=value 文本。应用只恢复已有 WebK 会话，使用其既有公开 Web 应用身份，不发起登录验证码、不注册自有第三方客户端。若实现独立新登录，需注册自己的 Telegram API ID/API hash。退出只移除本应用保存的会话，不注销用户的 Telegram 网页会话。

无需为能直接读取的公开目标自动关注或加入。自动写操作尚未经过账户实测，当前受限时提示到原站手动关注/加入或检查权限；不执行静默关注、加入或付费操作。站点授权与本地“订阅”相互独立。

所有凭据沿用现有源分区存储，不导入实验凭据到正式配置。不输出 Cookie、授权密钥、签名媒体 URL 或频道私密文本到诊断日志。系统 TLS 验证、源域名白名单和跨域重定向限制保持有效。Telegram 网络仍走原生隔离 HTTP 桥，未开放 WebView fetch/WebSocket 权限。账户导出遵循现有“包含凭据”备份选项；书库备份包含订阅目标与名称，恢复取并集，重复目标保留当前名称，不包含媒体缓存、分页游标或 Cookie。

TG 附件按 128 KiB 分块读取，框架控制路径并原子完成缓存，下载失败或取消删除临时文件；单附件目前最多 512 MiB，超出、CDN 重定向或不支持的媒体引导原站打开。视频需完整下载后播放，大文件首次打开较慢。媒体引用过期时刷新对应消息引用一次。上述会员媒体的 Android 网页登录和内置视频 UI 仍待单独验收；本次独立测试包仅验证更新检查与通知，未部署或替换用户原应用。

附件与图片共用媒体缓存上限，可在“我的 → 存储空间 → 媒体缓存”查看并清理；使用中的附件受保护，退出播放或查看后允许淘汰。缓存只保存可重建媒体，不替代下载或用户资产备份。

## 插件构建与依赖

Telegram 的唯一站点实现源为 `assets/sources/telegram_entry.mjs`，内置与发布脚本为构建生成的 `assets/sources/telegram.js`。开发时在 `tools/source-runner` 安装锁定依赖后运行 `node tools/build_subscription_sources.mjs`。发布器本身仍仅需 Node 内置模块，可离线校验已生成脚本。不得手改生成文件。

使用 [@mtproto/core 6.3.0](https://github.com/alik0211/mtproto-core) 的 MTProto/TL 实现（GPL-3.0）；[完整许可证](licenses/mtproto-core.txt)。其依赖与锁定版本在 `tools/source-runner/package-lock.json`，许可证汇总见 [第三方许可](licenses/telegram-dependencies.txt)。站点适配替换传输、密码学和存储，不开放库默认 WebSocket、浏览器 localStorage 或调试日志。

针对性验证、夹具、凭据捕获及结果只在被忽略的根 `test/`，不提交。

已有安装源不会被内置脚本静默替换；需在源站管理中更新到声明 `subscriptionUpdates` 的插件，才能使用新增维度。

新增游戏源采用作品关键词订阅，跟踪新发现的游戏条目，不将资源版本变化伪装成新作品。KUN 关键词检查返回 19 条，GalgameX GINKA 检查返回 2 条；GalgameX 默认排行在本轮采样出现 PARSE，搜索与详情采样成功，此站点首页问题与本次订阅检查分开记录。
