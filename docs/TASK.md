# 跨端重构实施清单

基线为 `v0.15.1`（`beaeff7dde1041663e5e695d5627bc1fbdec8b5f`）。范围、模块所有者及 17 分区行为见[架构设计](ARCHITECTURE_DESIGN.md)。以下均为待执行事项。每项签收记录基线、输入、设备／系统、操作、预期及实际结果；环境受限保留未验证范围。脱敏样本、测试脚本与产物统一放在被忽略的根目录 test/。

## M1　Android 覆盖升级后从原位置继续使用

- [ ] 从标签核对原 APK 包名、签名和分 ABI versionCode；建立可覆盖安装的候选包。独立安装的探索壳只供开发调试。
- [ ] 在旧版测试设备准备演示收藏与分类、已读状态、已知页码／播放秒数／小说锚点、可离线打开的下载、源配置、有效演示会话及两个同站游戏存档。记录预期身份、位置和原文件摘要。
- [ ] 对接 park-storage 的旧支持目录、既有库及 WAL、恢复日志、内外部下载及用户目录。分别验证旧库不可读、更高 Schema 和外部卷暂不可用时保留数据并可重试。
- [ ] 接入最小 Compose 路径、一份原样官方插件、可取消的控制接口及 Media3 会话；从发现／收藏／下载打开旧作品，回到旧章节、页码和秒数。验证 UTF-16 锚点解析，断网打开原离线文件，原设置、会话及作品 Profile 可识别。
- [ ] **准出**　在同一台设备从 v0.15.1 直接覆盖安装，全程保留应用数据，无需导入备份。记录一次完整的继续阅读或播放、进度变更、退出及重启恢复。逐项比对升级前后的身份、位置与资产；失败定位到安装、路径、存储、绑定或 UI 后复测。

M1 期间可用最窄接口验证 Swift／C# 回调寿命、QuickJS 差分、远程媒体路由及 Rust 窗口 seek。产出是选型证据，业务展开和 ABI 冻结在 M1 签收后进行。

## M2　底座兼容与接口冻结

- [ ] park-contract、park-domain 核对公共资产实际字段，明确领域 DTO、空值、单位、标识长度与错误；验证八语言占位符、PluginCopy、繁简、旧屏蔽规则与标题词边界。
- [ ] park-runtime 固定 101 份脚本、索引、原运行时和公共契约摘要；按每源实际能力完成同输入旧新对照，核对结果顺序、错误、取消及持久化副作用。记录真实请求、分页、解码和实播范围。验证 OTA 身份与撤回、用户确认、同名第三方保护、安装中断恢复。
- [ ] park-net 与 PlatformHost 按源、代数、用途核对 Cookie 回写、TLS／SNI、地址与重定向、代理、只读回退和注销竞态；验证支持宿主的隔离会话及完成后的原业务请求，检查不重复上传或发送。
- [ ] park-storage 使用 v7 与 .parkbak v1 做双向往返。覆盖默认／含凭据／自动备份、未安装源、跨机目录、酒馆资源冲突与双时间戳。注入未提交、已提交未清日志、磁盘满、访问拒绝和再次中断，核对恢复前后数据。
- [ ] park-media 用原封装器对照 TS→fMP4 轨道、关键帧、时长、时间戳、音画同步、跨窗 seek、取消与离线完结；验证 HLS 解密／解包、Range、会话撤销、条带与裁边、图片优先级、CBZ 与 PDF 分卷。
- [ ] park-ffi、park-daemon 分别验证取消、长标识、所有权、异步回调、释放、事件背压／缺口与快照。实测决定 Kotlin／Swift 绑定及唯一 Windows 门面，生成并联调匹配版本的绑定与二进制。验证 Web 同源 HTTP/SSE 路径和远程媒体。
- [ ] **准出**　发布实施用接口说明与逐源差分结果；记录未通过项及影响。核对敏感演示值未进入宿主、服务访问日志和崩溃输出。比较同设备旧新版的运行时冷启动、六源并发内存、滚动帧时间和远跳首帧。

## M3　Android 旗舰全量验收

- [ ] 按设计的分区表逐项登记全部 17 个入口，覆盖发现、站内、搜索、详情、阅读／播放、返回和失败恢复。独立验证聚合搜索、反搜、榜单、元数据、原站互动和屏蔽显隐。
- [ ] 漫画验证单双页／条漫与预加载；长短视频、漫剧验证手势、释放和恢复；直播验证离页持续录制；ASMR 验证同级快照、字幕、未知时长与锁屏。
- [ ] 小说验证 UTF-16 书签与字号／翻译切换；酒馆验证 CCv2／CCv3、递归开关与 32 轮上限、预算、流式候选与分支；游戏验证同站不同作品、旧存档、Ruffle、localStorage 导入失败恢复及按键释放。
- [ ] 书库迁移、下载删除／重试、离线包、双轨更新、后台租约、通知、自动备份、APK 自更新逐项走通。正常屏＋默认字号、窄屏＋大字体、平板、旋转、IME、RTL、应用锁和后台恢复分别留证。
- [ ] **准出**　在全量客户端上重跑 M1 覆盖升级路径，复核 17 分区及系统能力记录，所有基线差异均有归属与处理结果。

## M4　其他原生宿主与 Web 验收

- [ ] **Windows**　先盘点现有工程，再完成 WinUI 3 多窗／画中画、WebView2、键鼠、高对比度、音频转交、所有窗口锁定、退出落盘及备份互读。记录目标 Windows 上实际媒体与捕获能力。
- [ ] **iOS / iPadOS**　逐项对照 Android 行为表。分别记录最低系统及较新系统的游戏隔离、手势、AVPlayer seek、音频中断、系统后台到期与隐私；验证真机签名安装及原有 Bundle ID／钥匙串访问。Flash 等未证实能力保持缺口状态。
- [ ] **macOS**　验收三栏折叠、多窗菜单路由、锁定、最后窗口关闭后的任务、AVPlayer 及系统捕获边界。在 macOS 与 iOS 分别执行运行验收。
- [ ] **Web**　先清点原独立服务的数据和 JSON 备份，以演示数据验证迁移与失败恢复，再切换 React 19 至 daemon。覆盖 NAS 异机媒体、SSE 续接、文件归属、深链接、多标签登出和 PWA 离线提示。
- [ ] **准出**　逐平台登记 17 分区覆盖、媒体实播、备份互读、交互、设备与未验证范围。移动平台缺口持续追踪，旧 Web 数据有可验证的迁移结果；各端核心数据与用户任务通过后，另行决定旧实现退役。
