# دليل تطوير المكونات الإضافية المصدر

كل أصل HentaiPark هو ملف JavaScript منفصل. تقوم التطبيقات بتحميلها في وقت التشغيل: يمكن تثبيتها وتحديثها وتمكينها/إلغاء تنشيطها من مستودع المصدر دون إعادة ترجمة التطبيق.
يقع المصدر المدمج في [`assets/sources/`](../../../assets/sources/) ويمكن استخدامه مباشرة كمرجع نموذجي.

## بيئة التشغيل

- تعمل نصوص المصادر داخل WebView بلا واجهة في التطبيق (JavaScript حديث كامل مع `DOMParser`). توفر الطبقة الأصلية التشفير ومعالجة Cookie وطلبات HTTP الأصلية. لا تخضع طلبات HTTP الأصلية لقيود CORS؛ أما طلبات الشبكة والوسائط في المتصفح فتتبع القواعد المستقلة أدناه.
- يمكن أيضًا تشغيل نفس وقت التشغيل ([`assets/runtime/park_runtime.js`](../../../assets/runtime/park_runtime.js)) في Node، ويمكنك إجراء اختبار الدخان مباشرةً على الموقع الحقيقي أثناء التطوير:

ثبت اعتماديات runner المشترك من الجذر ثم أنشئ `test/source-smoke.mjs` المتجاهل حسب المثال. يحمل manifest فقط؛ أضف تحققاً فعلياً للصفحة الرئيسية والصفحة2 والبحث والتفاصيل وفك الغلاف والفصول والوسائط للمصدر المعدل. مضيف Node أداة تطوير وليس عزلاً أمنياً للنصوص غير الموثوقة.

```js
import { loadSource } from '../tools/source-runner/host.mjs';
const { manifest } = await loadSource('nhentai.js');
console.log(manifest.key, manifest.version);
```

```powershell
npm ci --prefix 'tools/source-runner'
node 'test/source-smoke.mjs'
```

## تسجيل المصدر

```js
Park.register({
  key: 'mysite',              // المعرف الفريد، لا يمكن تغييره بعد التثبيت
  name: 'Example Source',
  version: '0.0.1',           // عندما يكون رقم الإصدار الموجود في المستودع أعلى، سيطالبك التطبيق بالتحديث.
  type: 'comic',              // comic | video | novel | game
  category: 'doujin',         // doujin | anime | aiDrama | jav | adult | shortvideo | gallery | novel | game | other
  color: '#E5355F',           // لون العلامة التجارية: يستخدم لبطاقات الدخول المصدر وألوان موضوع الصفحة المصدر
  description: 'Example source description',
  homepage: 'https://example.com',
  domains: ['example.com'],                   // لمعرفة الموقع الذي ينتمي إليه، راجع "العزل والأمن"؛ إذا تم حذفه، فسيتم استخلاصه من عنوان مثل الصفحة الرئيسية.
  linkPatterns: ['example\\.com/g/(\\d+)'],   // يستخدم للوصول المباشر عند لصق الروابط في عمليات البحث المجمعة؛ المجموعة الأولى هي معرف العمل
  idPattern: '^(\\d+)$',                      // يستخدم للوصول المباشر عند إدخال الرقم مباشرة
  imageHeaders: { Referer: 'https://example.com/' },  // يتم حمله بشكل افتراضي عند تحميل الأغلفة والصور
  network: { mode: 'native', vpnHint: true },                // راجع قسم "الشبكة".
  media: { mode: 'browser', origin: 'https://example.com', domains: ['media.example.com'] },  // إذن HLS اختياري؛ راجع أدناه

  settings: [ /* option definitions */ ],
  account: { /* optional account */ },
  defaultFeed: 'ranking',                     // تم إدخال التسمية افتراضيًا عند فتح الصفحة الأصلية (ادخل في الخلاصات)
  feeds: [ /* browse tabs */ ],
  searchFilters: [ /* search filters */ ],
  searchHint: 'Search by title or tag',

  async init() {},                            // اختياري: يتم الاتصال به مرة واحدة عند التحميل (على سبيل المثال، تحديث قائمة أسماء النطاقات)
  async onSettingsChanged() {},               // اختياري: يتم استدعاؤه بعد قيام المستخدم بتعديل إعدادات المصدر

  async feed(key, { page, cursor, options }) {},
  async search({ keyword, page, cursor, filters }) {},
  async random() {},                          // إرجاع معرف العمل
  async detail(id, preview) {},
  async chapter(id, chapterId) {},            // كاريكاتير
  async resolveImage({ id, chapterId, index, token, retry }) {},  // اختياري: تأخير تحليل الصور
  async thumbnails(id, page) {},              // اختياري: قم بتحميل الصور المصغرة للمعاينة في الصفحات
  async videos(id, episodeId = '_') {},                        // فيديو
});
```

يحدد `type` القراءة أو التشغيل، ويحدد `category` التجميع في الرئيسية وإدارة المصادر والبحث. التصنيف غير المعروف أو الغائب يوضع ضمن أخرى. اختر التوصيات ثم الترتيب ثم الشائع للصفحة الافتراضية، ولا تستخدم الأحدث إلا عند غيابها.

تستخدم الدراما القصيرة بالذكاء الاصطناعي `category: 'aiDrama'`، ولا يُقبل المعرّف القديم `drama`. أسماء قنوات الموقع مستقلة عن تصنيف التطبيق وتحتفظ بأسمائها الأصلية. لا يستبعد تصنيف التطبيق قنوات الموقع تلقائيًا.

يجمع `adult` المواقع العامة مثل Pornhub وXVideos و91porn مع `type: 'video'`. تستخدم مواقع JAV المتخصصة `jav`. لا تحل الفئات محل وسوم الموقع أو مرشحات المستخدم.

تعلن المصادر التجميعية أيضاً `type: 'video', category: 'adult'`. عند عدم وجود واجهة وسائط متحقق منها، لا تنفذ `videos` ويصدر وقت التشغيل `capabilities.videos: false`. يفتح الإجراء الرئيسي `detail.url` في متصفح النظام ويخفي التشغيل والتنزيل والحلقات ويتجاوز مزامنة الفصول الوهمية وتحديثاتها مع الحفاظ على المفضلة والسجل. يستقبل `detail(id, preview)` الاختياري بيانات عامة فقط عند تطابق المصدر والمعرّف، وعلى المصدر إعادة التحقق من المعرّف والرابط. يستخدم iXXX رابط المصدر الخارجي بعد إزالة معاملات التتبع المعروفة كمعرّف ثابت، ويحتفظ TubeSafari بالمفتاح الخارجي. لا يطلبان الأعمال الخارجية باستخدام Cookie المصدر. يمكن فتح المراجع المباشرة بلا preview لكن قد ينقصها العنوان أو الغلاف. يحلل Thumbzilla بيانات MP4 تحليلاً ثابتاً ويقيد نطاقات الوسائط.

يجمع `gallery` الرسوم والكوسبلاي ومجموعات التصوير. تحتفظ مصادر الصور بـ `type: 'comic'`: يمثل كل معرض عملاً واحداً ويعيد `chapter()` الصور بالترتيب، مع استخدام القراءة والمكتبة والتنزيلات الحالية. لا يعتمد التصنيف على عدد الصور أو درجة المحتوى الصريح.

صرّح عن الصور المشفرة باستخدام `imageDecrypt`. تُفك قبل فحص التنسيق والتخزين المؤقت، وتدخل الاستراتيجية في هوية التخزين، ولا تُخزّن النتائج الفاشلة. يدعم AES-CBC مع حشو PKCS#7 صارم. تُشفّر `key` و`iv` بترميز UTF-8؛ يجب تحديد نطاقات الصور، وتبقى صور النطاقات الأخرى دون تغيير.

```js
imageDecrypt: {
  type: 'aes-cbc',
  key: '0123456789abcdef', // UTF-8: 16, 24 or 32 bytes
  iv: '0123456789abcdef',  // UTF-8: 16 bytes
  domains: ['images.example.com'],
},
```

تتضمن أخطاء الشبكة حقول `diagnostics` الآمنة: `host` و`transport` و`reason` لتمييز الشهادات ومصافحة TLS وDNS والاتصال والمهلات. تسجل السجلات التلقائية الحقول المسموح بها فقط، دون الرسائل الأصلية أو بيانات الاعتماد أو نص الطلب أو الروابط الموقعة.

يعني `reason: 'TLS_HANDSHAKE_TERMINATED'` فقط أن `HandshakeException.message` الأصلي يطابق تمامًا `Connection terminated during handshake`: انتهى الاتصال قبل اكتمال TLS ولا يعني فشل التحقق من الشهادة. تُعاد محاولة HTTPS GET / HEAD دون نص مرة واحدة لهذا الخطأ فقط. لا تُعاد المحاولة عند الإلغاء أو أخطاء الشهادات أو TLS الأخرى أو HTTP أو قراءة الرد. عند تكرار الفشل يظهر المضيف وتوجيه لفحص VPN أو الوكيل؛ لا تُسجل إلا بيانات تشخيص آمنة.

في الطريقة، يمكنك استخدام `this` للوصول إلى:

| الأعضاء | الوصف |
|------|------|
| `this.http` | `request(opts)`, `get(url, opts)`, `post(url, opts)`, `text(url, opts)`, `json(url, opts)` |
| `this.config` | القيمة التي حددها المستخدم في إعدادات المصدر (`default` إذا لم يتم تعيينها) |
| `this.store` | تخزين قيمة المفتاح المستمر: `get(key, fallback)` / `set(key, value)`، يستخدم لحفظ الرمز المميز وقائمة أسماء النطاقات وما إلى ذلك؛ `await flush()` يؤكد نجاح الكتابة على القرص، ويعطي خطأ إذا فشلت |
| `this.cookies` | `get(url)` / `set(url, {name: value})` / `clear(url)` |
| `this.log({code, host, transport, reason})` | تحفظ الحقول المنظمة المسموحة فقط ويستبعد النص الحر. |

الأدوات العالمية:

| أدوات | تعليمات |

| `Park.html.parse(text)` | معيار الإرجاع `Document` ، يمكنك استخدام `querySelector` |

| `Park.utils.mapLimit(items, n, fn)` / `lruMap(n)` / `parseCount('1.2万')` / `formatDate(ts)` | أدوات أخرى شائعة الاستخدام |
| `Park.error(code, message)` | يلقي خطأ مع رمز الخطأ، انظر أدناه |

### `http.request(opts)`

```js
await this.http.request({
  url, method: 'GET', headers: {}, params: { q: 'x' },   // سيتم ربط المعلمات في عنوان URL
  json: {...} | form: {...} | body: 'raw',
  timeout: 15000,
  responseType: 'text' | 'base64',
});
// → { status, headers, body, url, ok, json() }
```

تطرح `text()` / `json()` خطأ تلقائيًا عند تلقي استجابة خارج نطاق 2xx (404 → `NOT_FOUND`). تُحفظ ملفات Cookie تلقائيًا ويُعاد اختيارها لكل عنوان وجهة لإعادة التوجيه. لا تنقل إعادة التوجيه إلى أصل مختلف ترويسات المصادقة الأصلية، وتُرفض إذا أبقت على جسم الطلب.

## بنية البيانات

**صفحة القائمة** (قيمة الإرجاع `feed` / `search`)

```js
{
  items: [WorkItem], page: 1, totalPages: 20, total: 500,
  hasNext: true,
  cursor: '12345',        // اختياري: المواقع التي يقلب فيها المؤشر الصفحات (مثل E-Hentai) تعرض مؤشر الصفحة التالية، وسيعيدها التطبيق كما هو في المرة التالية التي يقدم فيها طلبًا.
}
// عند إرجاع sections، يختار التطبيق عرض الأقسام من الاستجابة:
{ sections: [{ title: 'Latest chapters', items: [WorkItem] }], hasNext: false }
```

**عنصر العمل**: `{ id, title, subtitle?, cover, coverAspect?, pages?, rating?, likes?, views?, language?, category?, badge?, badgeColor?, duration?, uploaded?, tags? }`

- `coverAspect` (العرض / الارتفاع) يقوم بعمل تخطيط الشبكة قبل تحميل الصورة لتجنب القفز.
- `badgeColor` اللون المستخدم لتسميات الفئات (على سبيل المثال، E-Hentai نظام الألوان التقليدي لكل فئة).

**التفاصيل** (`detail`): جميع حقول عنصر العمل، بالإضافة إلى ذلك:

```js
{
  url, authors: [], description, uploader?, size?, comments?,
  tags: [{ namespace: 'artist', label: 'Author', tags: [{ name, keyword, filters?, count? }] }],
  chapters: [{ id, title }] | null,   // null يمثل فصلًا واحدًا
  singleChapterId?,                   // معرف الفصل المطلوب لعمل فصل واحد (مثل "1" لـ Bika)
  thumbnails?: [url | {url, width, height, offsetX, offsetY}],   // دعم صورة العفريت
  related?: [WorkItem], series?: [WorkItem],
}
```

عند النقر على علامة ما، يبحث التطبيق عن `keyword` و`filters` في المصدر، بحيث يمكن تعيين العلامة إلى بناء الجملة الأصلي للموقع (على سبيل المثال، `artist:"xxx"`) أو معلمات التصفية (على سبيل المثال. Hanime1 من `tags[]`).

**الفصل** (`chapter`)

```js
{ pages: [
  { url, headers?, fallbacks?: [url], width?, height?, transform? },  // العنوان معروف
  { token: '12' },                                                      // القرار المتأخر: سوف يقوم التطبيق باستدعاء ResolveImage
]}
```

- `fallbacks`: مرآة احتياطية، حاول بالتسلسل عند فشل العنوان الأساسي.
- `transform: { type: 'unscramble-strips', segments: N }`: عندما يتم قص الصورة إلى شرائح N أفقيًا وتخزينها بترتيب عكسي (JMComic)، ستتم استعادة التطبيق محليًا على وحدة معالجة الرسومات. يحفظ الملف الذي تم تنزيله دون اتصال الصورة الأصلية ويستعيدها عند عرضها.
- `resolveImage` يُرجع `{ url, headers?, width?, height?, cacheKey? }`. عندما يفشل، سيقوم التطبيق بزيادة `retry` ويتصل مرة أخرى، ويمكن للمصدر استخدام هذا لتغيير الخادم (`nl` معلمة E-Hentai).

**الفيديو** (`videos`): `[{ quality: 1080, label: '1080P', url, headers?, format?, preferred? }]`. عادةً ما يكون لروابط الفيديو المباشرة حد زمني، وسيقوم التطبيق بإعادة الحصول عليها في كل مرة قبل التشغيل/التنزيل.

- تعيد مصادر الفيديو `[{id, title}]` بترتيب التشغيل في `detail(id).chapters`. يجب أن يكون كل `id` ثابتًا، وليس اسم جودة أو عنوان وسائط مؤقتًا. يستخدم التطبيق المعرّف نفسه للاختيار والتقدم المستقل والتنزيل والاستئناف، ويستدعي `videos(id, episodeId = '_')` للحصول على الحلقة. يستخدم الفيديو المنفرد `singleChapterId` أو `'_'` إذا لم يُحدد.
- عند حذف `format`، يبقى مسار تشغيل ملفات MP4 وتنزيلها مباشرةً. يجب أن تُرجع عناصر HLS القيمة `format: 'hls'` صراحةً وأن تعلن إذن `media` الموضح أدناه في manifest.
- يفك التطبيق أولًا قائمة HLS الرئيسية (`#EXT-X-STREAM-INF`) إلى قوائم مقاطع مستقلة لكل جودة، ويقرأ الدقة الفعلية من `RESOLUTION` ثم يمرر هذه القوائم إلى المشغّل أو أداة التنزيل. عند إرجاع قائمة رئيسية، تعبّر `quality` عن الدقة المطلوبة: تُفضّل أعلى دقة متاحة لا تتجاوزها، أو أعلى دقة متاحة إذا لم يوجد خيار مناسب. يجب أن يحتوي كل خيار على صوت وفيديو مدمجين في MPEG-TS. تُرفض المسارات المنفصلة `AUDIO` أو `VIDEO` أو `SUBTITLES` وعناوين URL خارج `media.domains`. يتم تجاهل مسارات المعاينة الاختيارية `#EXT-X-I-FRAME-STREAM-INF` ولا تُسجّل عناوينها أو تُطلب. عندما تكون دقة قائمة وسائط واحدة غير معروفة، قدّم `label: '原画'`؛ تُترجم التسمية إلى لغة الواجهة، ولا تُعرض الجودة المطلوبة بوصفها الدقة الفعلية.
- تدعم قوائم HLS فقط MPEG-TS VOD الكامل والمتصل مع `#EXT-X-ENDLIST`. يدعم فك تشفير CBC/PKCS7 باستخدام `METHOD=AES-128` و`KEYFORMAT=identity` (وهو الافتراضي عند حذفه)، ومفتاح من 16 بايت بالضبط وIV صريح من 128 بت أو مشتق من رقم تسلسل المقطع. تبقى المفاتيح في ذاكرة الجلسة، ويُتحقق من TS بعد فك التشفير ضمن المسار المشترك للتشغيل والتنزيل. لا تُدعم البث المباشر أو SAMPLE-AES أو KEYFORMAT الآخر أو `EXT-X-MAP` أو `EXT-X-BYTERANGE` أو fMP4 أو discontinuity أو gap. تُحذف علامة MissAV غير القياسية `#EXT-X-TOKEN`.
- يستخدم التشغيل منفذًا عشوائيًا مرتبطًا بـ `127.0.0.1` فقط ورمزًا عشوائيًا، مع سجل محدود لعناوين URL لجلب المقاطع التي تم التحقق منها عند الحاجة. إغلاق الجلسة يلغي طلباتها. تنزيل HLS دون اتصال مدعوم حاليًا على Android فقط: يُتحقق من كل مقطع وتُحفظ بصمته SHA-256 ويُعاد التحقق منه عند الاستئناف، مع دعم الإلغاء. يعيد Media3 تغليف الفيديو إلى MP4 محليًا، ولا يُضاف إلى مكتبة المحتوى دون اتصال إلا الملف المكتمل. لم يُتحقق من تشغيل HLS على iOS/macOS في هذه الجولة، ولا ينبغي وصفه بأنه تم التحقق منه.

## تعريف الخيار

`feeds[].options`، `searchFilters`، `settings` استخدم نفس التنسيق:

```js
{ key: 'sort', label: 'Sort', type: 'select', default: 'date',
  values: [{ value: 'date', label: 'Latest' }, { value: 'popular', label: 'Popular', color: '#f00' }] }
// type: select (اختيار واحد) | multi (اختيارات متعددة) | number | text | password | switch
// داخل settings يمكن استخدام options بدلًا من values.
```

كل عنصر في `feeds` هو علامة تبويب في الصفحة المصدر: `{ key, label, options?: [...] }`.

`defaultFeed` يحدد علامة التبويب التي سيتم ادخالها افتراضيا عند فتح الصفحة الأصلية. عندما لا يتم ملء المفتاح المقابل أو لا يمكن العثور عليه، سيحدد التطبيق تلقائيًا وفقًا للمفتاح بترتيب التوصية > التصنيف > الشائع (يتضمن المفتاح `promote` / `recommend` / `featured`، وبعد ذلك `rank` / `toplist`، ثم `popular` / `hot` / `trending`)، إذا لم يكن كذلك، أدخل الأول التسمية.

## شبكة

- `network.mode: 'native'` (افتراضي): يمكن لطلب HTTP الأصلي، باستخدام ملفات تعريف الارتباط الدائمة، المرور عبر الوكيل الذي قام المستخدم بتعيينه. إذا تم اكتشاف الاستعلام Cloudflare، فسيتم طرح `CLOUDFLARE`. سيقوم التطبيق بتوجيه المستخدم لإكمال عملية التحقق في المتصفح المدمج ومزامنة ملف تعريف الارتباط المشترك مرة أخرى مع الطلب الأصلي.
- `network.mode: 'browser'`+`network.origin`: تم الطلب بأصل `fetch()` في صفحة متصفح مخفية مفتوحة على `origin`، ببصمة متصفح حقيقية. ينطبق على Cloudflare المواقع التي تتمتع بحماية أكبر (على سبيل المثال Hanime1). عندما يتلقى طلب GET من الأصل نفسه استجابة تحقق من Cloudflare، يفتح المتصفح المخفي ذلك المستند لإجراء التحقق التلقائي، ثم يعيد الطلب الأصلي مرة واحدة. عند الفشل يستمر إصدار `CLOUDFLARE` ويُستخدم مسار التحقق الحالي.

## أذونات الوسائط (HLS)

إذن `media` مستقل عن `this.http` و`network` ومزامنة Cookie الموقع، ويطبق أسلوبا النقل قواعد النطاقات نفسها:

```js
domains: ['example.com'],
network: { mode: 'native' },
media: { mode: 'native', origin: 'https://example.com', domains: ['media.example.com'] },
```

- يدعم `media.mode` القيمتين `'native'` و`'browser'`. يجب في كليهما أن ينتمي `media.origin` إلى موقع أعلن عنه المصدر ويستخدم HTTPS على المنفذ 443، دون بيانات اعتماد أو استعلام أو جزء URL.
- `media.domains` قائمة مستقلة لنطاقات الوسائط المسموح بها، بما فيها النطاقات الفرعية، ولا تمنح وصولًا إلى Cookie الموقع. القوائم والمقاطع والمفاتيح تتطلب HTTPS 443. تُرفض بيانات اعتماد URL وأجزاؤه وعناوين IP وlocalhost مع نطاقاته الفرعية و`.local`.
- يستخدم `media.mode: 'native'` عميلًا أصليًا مستقلًا دون Cookie الموقع أو Authorization أو مصادقة الوكيل. يُفحص هدف كل إعادة توجيه قبل اتباعه. تُسمح فقط رؤوس `Referer` و`Origin` و`Accept` و`Accept-Language`، ويجب أن يطابق الأولان `media.origin`.
- ينشئ `media.mode: 'browser'` جلسة في متصفح مخفي عند `media.origin` باستخدام `credentials: 'omit'` و`mode: 'cors'` و`redirect: 'error'`. يلتزم بقواعد CORS للـ CDN ولا يتبع إعادة التوجيه.
- يُحد حجم الاستجابة أثناء قراءتها ويُفحص عنوانها مجددًا. الحد الأقصى للقائمة 2 MiB وللمقطع 32 MiB، ومفتاح AES-128 يجب أن يكون 16 بايت بالضبط. تُرفض الاستجابات الفارغة أو الكبيرة والعناوين غير المسموح بها. تبقى قواعد `domains` و`network` الذي يستخدم Cookie مستقلة.

## العزلة والأمن

- يعمل كل مصدر في بيئة JS **مستقلة** (لكل منها WebView بدون واجهة)، ولا يمكن للمصادر رؤية الكائنات العامة لبعضها البعض؛ يتعرف الجسر الأصلي فقط على البيئة التي يأتي منها الاستدعاء، ولا يمكن للنصوص البرمجية انتحال صفة المصادر الأخرى.
- يحتوي كل مصدر على جرة ملفات تعريف ارتباط مستقلة: الطلب الصادر عن المصدر سيجلب ويحفظ ملف تعريف الارتباط الخاص به فقط، ولن يقرأ حالة تسجيل الدخول للمصادر الأخرى.
- لا تُرسل ملفات Cookie ذات الخاصية Secure عبر HTTP. يُتحقق من فتح صفحة التحقق واستيراد Cookie من المتصفح وفق `domains` للمصدر المثبت، مع حفظ خصائص الأمان وتاريخ الانتهاء المتاحين. مسح Cookie للمصدر أو إلغاء تثبيته يغلق جلسات المتصفح المرتبطة ويمسح Cookie لذلك الموقع. يشارك النظام Cookie مواقع المتصفح، لذلك تتأثر أيضًا المصادر التي تعلن الموقع نفسه.
- `domains` يعلن عن الموقع الذي ينتمي إليه المصدر (يمكن تسجيل اسم النطاق، ويتم تضمين اسم النطاق الفرعي تلقائيًا). ستتم مزامنة ملفات تعريف الارتباط من هذه المواقع فقط مع المتصفح المدمج (مشتركة بواسطة مصادقة Cloudflare وتسجيل الدخول عبر الويب)، ويجب أن تنتمي إليها أيضًا `network.origin` في وضع المتصفح. عند الحذف، استنتج من `homepage`، `network.origin`، `account.cookieUrl/loginUrl`.
- عند تثبيت المصدر من موقع ويب أو مستودع، سيقوم التطبيق أولاً بقراءة معلومات البرنامج النصي في وضع الحماية الذي لا يمكن توصيله بالإنترنت، ويعرض الاسم والإصدار وSHA-256 والموقع المعلن وتحذير المخاطر للمستخدم، ثم تثبيته بعد التأكيد. يمكن أن يحتوي الإدخال `index.json` في المستودع المصدر على الحقل `sha256`، وسيتم رفض التثبيت إذا كان محتوى التنزيل غير متطابق.

## الحساب

```js
account: {
  type: 'password' | 'cookies',
  title, hint, required: false,
  fields: [{ key: 'email', label: 'Email' }, { key: 'password', label: 'Password', secret: true }],
  loginUrl?, cookieUrl?, requiredCookies?: ['ipb_member_id'],   // وبعد تقديمه، يمكنك تسجيل الدخول إلى صفحة الويب وسيحصل التطبيق تلقائيًا على ملف تعريف الارتباط.
  async login(values) { return { name } },
  async logout() {},
  async status() { return { loggedIn, name, configured } },
  managedAccount: true,                 // اختياري: توفير حساب صيانة تلقائي مخصص
  async enableManaged() {},             // يتم الاتصال به فقط بعد تأكيد المستخدم للتسجيل
}
```

يشير `configured` إلى أنه تم تكوين الحساب، بغض النظر عما إذا كانت عملية تسجيل الدخول الحالية ناجحة أم لا. `managedAccount: true` يعلن أن المصدر يدعم حساب صيانة تلقائية مخصص؛ تستخدم إعدادات المصدر المفتاح `managedAccount` الذي يحمل نفس الاسم. يجب على المضيف أولاً عرض تعليمات التسجيل التلقائي والحصول على تأكيد المستخدم قبل حفظ إعدادات التمكين والاتصال بالرقم `account.enableManaged()`. يجب حفظ بيانات اعتماد المرشح واستخدام `await this.store.flush()` قبل التسجيل للتأكد من إمكانية استعادة نفس الحساب بعد الفشل أو إعادة تشغيل التطبيق.

مثال PicACG يحفظ بيانات الاعتماد اليدوية والحسابات المخصصة بشكل منفصل، ويجب عدم استبدال الحسابات اليدوية الحالية بحسابات مخصصة. قم بإيقاف تشغيل المفتاح للاحتفاظ بالحساب المخصص وتشغيله مرة أخرى لإعادة استخدامه؛ إذا انتهت صلاحية الرمز، يمكنك فقط تسجيل الدخول مرة أخرى وعدم التسجيل مرة أخرى. بعد فشل التسجيل أو فقدان الاستجابة، أعد محاولة حساب المرشح الأصلي لتجنب إنشاء حسابات زائدة عن الحاجة. كلمة مرور الحساب والرمز المميز وحالة المصدر كلها بيانات محلية للمستخدم. لا تقم بإخراج بيانات الاعتماد الحقيقية في المستندات والسجلات.

## التدويل

دعم واجهة التطبيق `zh-Hans`، `zh-Hant`، `ja`، `ko`، `en`، `es`، `ru`، `ar`. تستخدم عناصر التحكم في المواد والكوبرتينو والنظام اللغات المقابلة؛ الواجهة العربية تنتقل من اليمين إلى اليسار. يصبح إعداد لغة الواجهة ساري المفعول على الفور ويتم حفظه باستمرار. وهو يتبع النظام بشكل افتراضي؛ تحدد النصوص والمناطق الصينية ما إذا كان سيتم استخدام اللغة الصينية المبسطة أو التقليدية.

تستدعي واجهة Flutter بشكل موحد `tr('已选 {count}', {'count': count})` أو `context.tr`. يتم استخدام النص الصيني الأصلي للرسالة كمفتاح المورد، والمعلمة هي `{name}`، ويقع المورد بثماني لغات في `assets/i18n/`. عند إضافة نسخة مرئية أو تعديلها، يجب تحديث جميع الموارد في وقت واحد ويجب أن تكون العناصر النائبة متسقة. يتم تعيين الاسم الثابت والوصف وتسمية التصفح والخيارات ومطالبات الخطأ الخاصة بالمكون الإضافي عند عرض التطبيق؛ يظل العنوان والمؤلف والعلامة وإدخال المستخدم ومفتاح بروتوكول الاستمرارية للعمل عن بعد هو النص الأصلي.

## رمز الخطأ

استخدم `throw Park.error(code, message)` لإلقاء خطأ، وسيوفر التطبيق إرشادات مقابلة بناءً على رمز الخطأ:

| كود | معالجة التطبيق |
|------|-----------|
| `CLOUDFLARE` | زر "الانتقال إلى التحقق": افتح المتصفح المدمج |
| `LOGIN_REQUIRED` | زر "الانتقال إلى تسجيل الدخول": افتح منطقة الحساب في إعدادات المصدر |
| `NOT_FOUND` | عرض "المحتوى غير موجود" |
| `BLOCKED` | يعرض "الوصول مقيد" (مثل IP محظور، استنفاد الحصة)، لن تتم إعادة محاولة الصورة |
| `NETWORK` / `HTTP` / `PARSE` | عرض رسالة خطأ مع زر "إعادة المحاولة" |

## مستودع المصدر

المستودع هو `index.json` ويمكن وضعه على استضافة ثابتة (على سبيل المثال GitHub خام). يمكن للمستخدمين التصفح والتثبيت والتحديث عن طريق إدخال عنوان المستودع في "إدارة موقع المصدر → إضافة مصدر":

```json
{
  "name": "我的源仓库",
  "apiVersion": 1,
  "sources": [
    {
      "key": "mysite",
      "name": "我的站点",
      "version": "0.0.1",
      "description": "一句话介绍",
      "url": "https://example.com/sources/mysite.js",
      "sha256": "脚本 UTF-8 原文的 64 位十六进制 SHA-256",
      "apiVersion": 1
    }
  ]
}
```

`url` هو العنوان الكامل للبرنامج النصي؛ يمكنك أيضًا استخدام `file` بالنسبة إلى `index.json`. يتم تثبيت مستودع الطرف الثالث يدويًا بعد تأكيد المستخدم. `sha256` اختياري. سيتم التحقق من المحتوى الذي تم تنزيله عند تقديمه.

تعتمد التحديثات الرسمية قواعد صارمة: يجب أن يكون الإصدار عبارة عن عدد صحيح غير سالب مكون من ثلاثة أجزاء مفصول بنقاط وبدون أصفار بادئة (على سبيل المثال، `0.0.1`، `0.1.0`)، والتي تتم مقارنتها قطعة تلو الأخرى؛ لا يتم قبول المقاطع المفقودة أو المقاطع المتعددة أو لاحقات الإصدار المسبق. يجب توفير نص UTF-8 الأصلي للبرنامج النصي `sha256` دون قطع المسافات البيضاء أو تحويل الأسطر الجديدة؛ يجب أن يكون `key` و`version` المعلن عنها بواسطة البرنامج النصي متوافقين مع الفهرس. يجب أن يتطابق `apiVersion` تمامًا مع وقت تشغيل التطبيق الحالي. إذا لم يتطابق، سيتم رفض التحديث. تحتاج إلى استخدام تطبيق يدعم واجهة برمجة التطبيقات هذه أولاً؛ لم يتم توفير فرع متوافق.

### التحديثات الرسمية في التطبيق

عند التشغيل يُقرأ الفهرس الرسمي فقط، ويُطلب التأكيد عند وجود إصدار جديد قبل تنزيل الإضافة وتثبيتها. عند العودة إلى الواجهة تبقى مهلة الفحص 12 ساعة، وتشمل المحاولات الفاشلة. الخياران مفعّلان افتراضياً ويمكن تعطيلهما بشكل مستقل، مع بقاء الفحص اليدوي متاحاً. يشمل الفحص المصادر المدمجة والرسمية المثبتة فقط ولا يغيّر المصادر الخارجية.

بعد التأكيد تُراجع هوية المصدر وإصداره وأصله وAPI وSHA-256، ويكتمل التثبيت بعد نجاح التهيئة وحفظ الحالة. عند الفشل يُستعاد النص السابق والبيانات الخاصة، ويُستعاد التثبيت المنقطع عند التشغيل التالي. لا يستبدل التشغيل إضافة مثبتة بنص مدمج حتى إذا كان ملفها مفقوداً؛ تُحفظ معلومات التسجيل والبيانات. تُثبّت النصوص المدمجة أول مرة للإضافات الجديدة فقط. تتطلب استعادة المصدر المدمج تأكيداً أيضاً. على Android يُنزّل APK الرسمي المناسب داخل التطبيق بعد التأكيد. يُتحقق من الحجم وSHA-256 واسم الحزمة والإصدار والتوقيعات قبل فتح مثبّت النظام الذي يطلب التأكيد. عند الحاجة امنح الإذن ثم عد واضغط متابعة التثبيت. يتوفر تقدم التنزيل والإلغاء وإعادة المحاولة، وتُستخدم الصفحة الرسمية عند الفشل. تستخدم المنصات الأخرى التنزيل اليدوي من الصفحة الرسمية.

### الافراج عن المصادر الرسمية

المصدر الرسمي يتبع المستودع الرئيسي العام [drdon1234/Hentai-Park](https://github.com/drdon1234/Hentai-Park) والمدخل الثابت للعميل هو:

```text
https://raw.githubusercontent.com/drdon1234/Hentai-Park/sources/index.json
```

يقبل معرّف المصدر `key` الأحرف `[A-Za-z0-9_-]` فقط بطول 1–100، ولا يجوز استخدام القيمة المحجوزة `_app`؛ ويجب أن يكون اسم ملف البرنامج `{key}.js`.

`assets/sources/index.json` هي قائمة المصدر الوحيدة التي تم الاحتفاظ بها، ويشير `file` إلى كود مصدر البرنامج النصي الوحيد في نفس الدليل. يجب أن يتوافق اسم الملف مع `[A-Za-z0-9_-]+.js`. لا يتم قبول الدلائل الفرعية أو الروابط الرمزية أو النقاط الموجودة في نص اسم الملف ويجب أن تكون متوافقة مع التحقق من عنوان المصدر الرسمي للعميل. `tools/publish_sources.mjs` إنشاء فهرس النشر: يحتوي كل سجل على `key`، `name`، `version`, `category`، `description`، `url` و`sha256` و`apiVersion`. تم تثبيت عنوان URL للبرنامج النصي على رقم الالتزام الكامل المكون من 40 رقمًا لرمز المصدر هذا:

```text
https://raw.githubusercontent.com/drdon1234/Hentai-Park/<源码提交 SHA>/assets/sources/<file>
```

يقوم الفرع `sources` فقط بحفظ الدليل الجذر الذي تم إنشاؤه `index.json`، دون نسخ البرنامج النصي أو الاحتفاظ بقائمة مصادر ثانية يدويًا. عند تحديث البرنامج النصي، يجب ترقية الإصدار الموجود في البرنامج النصي والبيان في نفس الوقت؛ يرفض الناشر خفض الإصدار، ويرفض أيضًا أن يتوافق نفس الإصدار مع محتوى نصي مختلف. يمكن نشر نفس الإصدار بشكل متكرر مع عدم تغيير المحتوى، ولن تتأثر الترقيات العادية بإصدار الفهرس القديم.

يعتمد الناشر فقط على الوحدة النمطية المضمنة Node.js ويمكن تشغيله دون اتصال في Node.js 22 أو أحدث. فهو يتحقق من البيانات ووجود الملفات وحدود الدليل، ويحمل وقت التشغيل المشترك والبرامج النصية في سياق منفصل لا يوفر أي واجهات شبكة أو تخزين، ويتحقق باستخدام نفس مجسات `Park.__pending` / `Park.manifest` مثل معاينة تثبيت التطبيق `key`، `version` و API. لا يستدعي الاكتشاف `setup` أو `init` أو تسجيل الدخول أو أساليب عمل الموقع، ولا يمكن أن يحل محل اختبار قابلية الاستخدام لشبكة الموقع الأصلي.

مثال للمعاينة المحلية (الإخراج هو `test/` والذي تم تجاهله ولن يتم نشره؛ يجب أن يستخدم رقم الالتزام SHA الحقيقي لكود المصدر المقابل):

```powershell
node tools/publish_sources.mjs --commit '<完整 40 位源码提交 SHA>' --output 'test/official-source-index.json'
```

عندما تحتاج إلى التحقق من الإصدارات الموجودة، قم بإدخال `--previous '旧索引本地路径'`. إذا فشل التحقق عندما يكون الفهرس القديم غير صالح، فلن يتم تخطي حماية الإصدار بصمت. عندما تكون هناك تعديلات غير ملتزم بها في مساحة العمل، يتم استخدام النتائج المحلية للمعاينة فقط؛ يتم إنشاء الإصدار الرسمي عن طريق إرسال كود المصدر الذي تم سحبه من خلال سير العمل.

`.github/workflows/publish-sources.yml` يتم تشغيله فقط عندما يتم دفع الملفات ذات الصلة بالفرع الافتراضي `main` أو تشغيلها يدويًا من `main`. يتم تنفيذ سير العمل بشكل تسلسلي، وآخر `main` هو تم سحبه في بداية كل مهمة، ويتم إصلاح عنوان البرنامج النصي وسجل الإصدار برقم التزام السحب الفعلي. لن تمنع عمليات إرسال المستندات اللاحقة أثناء تشغيل المهمة النشر؛ ستؤدي عمليات إرسال الملف المصدر اللاحقة إلى تشغيل المهمة التسلسلية التالية. يقوم سير العمل أولاً بتنزيل الفهرس المستقر الحالي وإكمال جميع عمليات التحقق دون اتصال بالإنترنت، ثم يستخدم Git العادي لدفع التحديث الذري إلى الفرع `sources`؛ لن تتم الكتابة فوق الفهرس عبر الإنترنت عند فشل التحقق أو حدوث تغييرات متزامنة في فرع `sources`. يمكن إنشاء منشور لأول مرة بدون فهرس ثابت. يشير الإصدار فقط إلى أن البرنامج النصي والفهرس قد اجتازا عملية التحقق المذكورة أعلاه. لا يزال يتعين التحقق من الوصول إلى الموقع وتسجيل الدخول إلى الحساب وتحميل الصور أو الفيديو بشكل منفصل.

</div>


يفعّل `type: 'video', category: 'shortvideo'` القائمة العمودية بملء الشاشة. يمثّل كل عمل مقطعًا واحدًا، وتعيد `videos(id, '_')` روابط الوسائط الحالية. يستخدم `feed` حقلي `hasNext` و`cursor` للترقيم التلقائي؛ يجب ألا تتضمن المؤشرات بيانات اعتماد أو روابط وسائط موقّعة. يعمل المقطع الحالي فقط ويُحمّل التالي مسبقًا وهو متوقف وتُلغى بقية المشغلات وتُحرر. لا تعلن `search` دون واجهة بحث متحقق منها.


يمكن إعلان `imageNetwork` اختياريًا مع `mode: browser` و`origin` عبر HTTPS و`domains` ضمن نطاقات المصدر. تُسمح الترويسات المعتمدة فقط دون بيانات اعتماد أو إعادة توجيه وبحد 20 MiB للصورة. يستمر فك التشفير وفحص التنسيق والتحميل والتخزين المؤقت المعزول. تستخدم صفحات وAPI في Tik.porn جلسات بنفس أصل كل منهما، والتشغيل بصيغة MP4.

## بروتوكول الاشتراك

تعريف `subscription.normalize` و`subscription.posts` معاً يولد `capabilities.subscription` للمدخل المستقل. تبقى قواعد الموقع في الإضافة. يتحقق `normalize` محلياً من اسم المستخدم أو رابط الملف المضبوط دون دخول أو شبكة. `resolve` اختياري للتحقق الشبكي و`targets` يعيد الأهداف المنضم إليها ويولد `subscription.joinedTargets: true`. المؤشر نص مبهم و`hasNext: false` ينهي الصفحات، وقد تستمر الصفحة الفارغة. يدل `locked` على نقص الإذن و`previewOnly` يصرح بالمعاينة.

```js
subscription: {
  normalize(input) { return { id: validatedTarget, label: displayName }; },
  async resolve(input) { return { id: validatedTarget, label: displayName }; },
  async targets() { return [{ id: joinedTarget, label: displayName }]; },
  async posts(target, { cursor }) {
    return {
      items: [{ id, title, text, date, url, locked, media: [
        { type: 'image', url, preview, previewOnly: false },
        { type: 'video', url, preview, format: 'mp4', headers: {} },
        { type: 'image', resource: { cacheKey, size } },
      ] }],
      cursor: nextCursor, hasNext: true,
    };
  },
  async mediaChunk(resource, offset) { return { base64, done }; },
}
```

المرفقات المصرح بها دون رابط مباشر تستخدم `media[].resource` مع `size` صحيح و`cacheKey` ثابت وغير سري ولا يتغير بتغير المراجع المؤقتة أو بيانات الدخول. تعيد `subscription.mediaChunk(resource, offset)` القيمة `{base64, done}`: أقصى128 KiB ومحاذاة الإزاحة وكتل وسطية كاملة وأقصى512 MiB للمرفق. يتحقق المضيف من الحجم ويكتب ذرياً في ذاكرته المؤقتة ويحمي الملفات المستخدمة. لا يختار المورد المسار ولا تحفظ الأهداف روابط موقعة أو resource في النسخ.

تستورد الجلسة الموجودة عبر `account.type: 'session'` وحقل سري ويتحقق منها الملحق دون تقسيمها إلى كلمات مرور أو Cookie. يجب تأكيد التفويض فعلياً؛ الحفظ لا يتابع أو ينضم تلقائياً. `bodyBase64` الأصلي حتى2 MiB ولا يجتمع مع body أو وضع المتصفح؛ يمكن الرد بصيغة base64. يقبل `digestBytes('sha1'|'sha256', bytes)` حتى2 MiB من البايتات الصحيحة و`randomBytes(length)` من1 إلى65536. تبقى TLS وعزل النطاقات وقيود إعادة التوجيه؛ لا تفتح شبكة متصفح أو WebSocket أو ملفات عشوائية.

[الاشتراكات](../../SUBSCRIPTIONS.md)

تظهر المصادر التي تعلن subscription وfeeds أيضاً في الفئات العادية. تدعم عناصر feed/search الحقول presentation:'post' وtext وdate وurl ومصفوفة media لبطاقات المنشورات؛ يستخدم presentation:'media' الشبكة. يصف mediaKind وcoverAspect الوسائط وتدعم الصور التنقل بين الصفحات. يعلن network.confirmation:{selector,readySelector,requiredCookies,message} نافذة التأكيد وعلامة المحتوى وCookie المطلوبة. بعد CONFIRM_REQUIRED لا يعود المتصفح إلا بعد إغلاق التأكيد وظهور المحتوى وحفظ Cookie واستقرار التنقل. لا يؤكد التطبيق نيابة عن المستخدم.
