# واجهة إضافات المواقع

[البدء السريع](#البدء-السريع) · [حقول manifest](#حقول-manifest) · [الدوال](#الدوال) · [واجهة بيئة التشغيل](#واجهة-بيئة-التشغيل) · [رموز الأخطاء](#رموز-الأخطاء) · [تعدد اللغات](#تعدد-اللغات) · [النشر](#النشر) · [ملحق: ملاحظات عن المواقع الرسمية](#ملحق-ملاحظات-عن-المواقع-الرسمية)

كل موقع في HentaiPark إضافة JavaScript مستقلة. يحمّل التطبيق الإضافات أثناء التشغيل، ويمكن تثبيتها من مستودع وتحديثها وتفعيلها وتعطيلها **دون إعادة بناء التطبيق**. توجد الإضافات الرسمية في [`assets/sources/`](../../../assets/sources/) وتصلح أمثلةً مباشرة.

النسخة الصينية المبسطة من هذا المستند هي المرجع. تبقى قواعد كل موقع داخل إضافته، ويوفّر الإطار الشبكة والتخزين المؤقت والصور، ولا يعامل أي موقع معاملة خاصة باسمه.

## البدء السريع

### بيئة التشغيل

- تعمل الإضافات داخل WebView بلا واجهة في التطبيق، مع JS حديثة و`DOMParser`. توفّر الطبقة الأصلية التشفير وملفات تعريف الارتباط وHTTP الأصلي؛ لا يخضع HTTP الأصلي لقيود CORS، بينما تتبع شبكة المتصفح والوسائط قواعدها الموضحة أدناه.
- تبدأ بيئة الإضافة عند أول استخدام للموقع، وتُحرَّر بعد نحو 5 دقائق من الخمول أو عند تشغيل أكثر من 6. يُخزَّن manifest مؤقتًا حسب «SHA-256 للنص + إصدار البيئة»، لذا لا يشغّل فتح التطبيق الإضافات. لا تفترض أن الإضافة تعمل فور بدء التطبيق.
- البيئة نفسها ([`assets/runtime/park_runtime.js`](../../../assets/runtime/park_runtime.js)) تعمل في Node، فيمكنك التجربة على مواقع حقيقية أثناء التطوير. مضيف Node أداة تطوير وليس بيئة معزولة للنصوص غير الموثوقة.

### أصغر إضافة

```js
Park.register({
  key: 'mysite',
  name: '我的站点',
  version: '0.0.1',
  type: 'comic',
  category: 'doujin',
  homepage: 'https://example.com',
  domains: ['example.com'],
  defaultFeed: 'popular',
  feeds: [{ key: 'popular', label: '热门' }],

  async feed(key, { page }) {
    const doc = Park.html.parse(await this.http.text(`https://example.com/popular?page=${page}`));
    return {
      items: [...doc.querySelectorAll('.gallery')].map((el) => ({
        id: el.dataset.id,
        title: Park.html.text(el.querySelector('.title')),
        cover: el.querySelector('img').src,
      })),
      hasNext: !!doc.querySelector('.next'),
    };
  },
  async detail(id) { /* … */ },
  async chapter(id, chapterId) { /* … */ },
});
```

### التجربة في Node

ثبّت اعتماديات المشغّل المشترك في جذر المستودع وأنشئ ملف `test/source-smoke.mjs` مُتجاهَلًا كما يلي. يحمّل المثال manifest فقط؛ وعند تعديل إضافة تحقّق أيضًا بطلبات حقيقية من الصفحة الأولى والثانية والبحث والتفاصيل وفك ترميز الأغلفة والفصول أو وسائط الفيديو.

```js
import { loadSource } from '../tools/source-runner/host.mjs';
const { manifest } = await loadSource('nhentai.js');
console.log(manifest.key, manifest.version);
```

```powershell
npm ci --prefix 'tools/source-runner'
node 'test/source-smoke.mjs'
```

## حقول manifest

```js
Park.register({
  key: 'mysite',              // فريد ودائم؛ [A-Za-z0-9_-] فقط، من 1 إلى 100 حرف، وليس _app
  name: '我的站点',
  version: '0.0.1',           // ثلاثة أرقام؛ يعرض التطبيق التحديث إن كان إصدار المستودع أعلى
  type: 'comic',              // comic | video | novel | game: طريقة قراءة الأعمال أو تشغيلها
  category: 'doujin',         // doujin | anime | aiDrama | jav | adult | shortvideo | gallery | novel | game | other
  color: '#E5355F',           // لون العلامة: أيقونة الموقع وصفحته
  description: '一句话介绍',
  homepage: 'https://example.com',
  domains: ['example.com'],                   // المواقع التابعة، راجع «العزل والأمان»؛ يُستنتج من homepage وغيره عند غيابه
  linkPatterns: ['example\\.com/g/(\\d+)'],   // الروابط الملصقة تفتح العمل مباشرة؛ المجموعة الأولى هي معرّف العمل
  idPattern: '^(\\d+)$',                      // المعرّفات المكتوبة تفتح العمل مباشرة
  imageHeaders: { Referer: 'https://example.com/' },  // الترويسات الافتراضية للأغلفة والصور
  network: { mode: 'native', vpnHint: true },  // راجع «الشبكة»
  media: { mode: 'browser', origin: 'https://example.com', domains: ['media.example.com'] },  // إذن وسائط HLS اختياري
  imageNetwork: { mode: 'browser', origin: 'https://img.example.com', domains: ['img.example.com'] }, // اختياري
  imageDecrypt: { /* اختياري، راجع «الصور المشفرة» */ },

  settings: [ /* الخيارات، راجع «تعريف الخيارات» */ ],
  account: { /* اختياري، راجع «الحسابات» */ },
  defaultFeed: 'ranking',     // التبويب المفتوح افتراضيًا في صفحة الموقع (مفتاح من feeds)
  feeds: [ /* تبويبات صفحة الموقع */ ],
  searchFilters: [ /* عوامل تصفية البحث */ ],
  searchHint: '搜索技巧提示',
  i18n: { /* ترجمات الواجهة الخاصة بالإضافة، راجع «تعدد اللغات» */ },

  subscription: { /* اختياري: متابعة القنوات والمبدعين، راجع «الاشتراكات» */ },
  updateSubscriptions: { /* اختياري: اشتراكات التحديث */ },

  async init() {},              // اختياري: يُستدعى مرة عند بدء البيئة (مثل تحديث قائمة النطاقات)
  async onSettingsChanged() {}, // اختياري: يُستدعى بعد تغيير المستخدم إعدادات الموقع
  // إضافةً إلى دوال قسم «الدوال»
});
```

تستخرج البيئة القدرات (`capabilities`) تلقائيًا من الدوال المنفَّذة؛ لا تكتبها يدويًا.

### النوع والفئة

يحدد `type` طريقة قراءة الأعمال أو تشغيلها أو معاملتها كموارد ألعاب، ويحدد `category` مكان الموقع في «استكشاف» وإدارة المواقع والبحث. تذهب الفئات غير المعروفة أو الغائبة إلى «أخرى». يجب أن تعلن المواقع الجديدة نوعها وفئتها وقدراتها بدقة.

| الفئة | المعنى |
| --- | --- |
| `doujin` | دوجينشي وقصص مصورة |
| `gallery` | معارض: رسوم وكوسبلاي وجلسات تصوير. تبقى مواقع الصور على `type: 'comic'`؛ المعرض الواحد عمل واحد وتأتي صوره بالترتيب من `chapter()`، فتعمل القراءة والمفضلة والتنزيل كالمعتاد. لا تُقسَّم الفئة حسب عدد الصور أو جرأتها |
| `anime` | أنمي للبالغين |
| `aiDrama` | دراما قصيرة بالذكاء الاصطناعي. لا تُقبل القيمة القديمة `drama`؛ أعلن أسماء قنوات الموقع كما هي، ولا تُصفّيها فئة التطبيق |
| `jav` | مواقع JAV المتخصصة |
| `adult` | فيديو عام للبالغين (Pornhub وXVideos و91porn…)، `type: 'video'`. الفئة تجميع فقط ولا تحل محل وسوم الموقع أو عوامل تصفية المستخدم |
| `shortvideo` | مقاطع قصيرة: موجز عمودي بملء الشاشة، انظر أدناه |
| `novel` | روايات، `type: 'novel'` |
| `game` | ألعاب، `type: 'game'` |
| `other` | كل ما سوى ذلك (مواقع الاشتراك وغيرها) |

- **المقاطع القصيرة** (`type: 'video', category: 'shortvideo'`): تفتح الأعمال والبحث والمفضلة والسجل الموجز مباشرة. كل عمل مقطع واحد، و`videos(id, '_')` يعيد وسائطه الحالية دون حاجة إلى صفحة تفاصيل. يحمّل `hasNext` و`cursor` من `feed` الصفحة التالية قرب النهاية تلقائيًا، ولا يجوز أن تحتوي المؤشرات على بيانات اعتماد أو تواقيع وسائط. يبدأ التحديث من الصفحة الأولى؛ يُشغَّل العنصر الحالي ويُحمَّل التالي مسبقًا متوقفًا ويُحرَّر الباقي. لا تعلن `search` إن لم يكن للموقع بحث.
- **المجمّعات التي لا تُشغَّل إلا في الموقع الأصلي**: تبقى على `type: 'video', category: 'adult'`؛ وبلا واجهة وسائط مُتحقَّق منها لا تُنفَّذ `videos`، فتُخرج البيئة `capabilities.videos: false`. يفتح الزر الرئيسي `detail.url` في متصفح النظام، ويُخفى التشغيل والتنزيل والحلقات، ولا تُحفظ فصول وهمية ولا يُتحقق من تحديثاتها؛ وتبقى المفضلة والسجل.
- **الروايات** و**الألعاب** مشروحة في «الدوال».

اختر `defaultFeed` بالترتيب **الموصى به > التصنيفات > الرائج**، ولا تستخدم صفحة الأحدث أو مدخلًا آخر إلا إن خلا الموقع منها فعلًا، ولا تخترع واجهة غير مُتحقَّق منها. عند غيابه أو عدم وجود المفتاح يختار التطبيق حسب المفتاح (أولًا `promote` / `recommend` / `featured`، ثم `rank` / `toplist`، ثم `popular` / `hot` / `trending`)، وإلا فالتبويب الأول.

تُعلن المصادر التي تسمح بالتصفح المجهول وتتطلب تسجيل الدخول للتوصيات عن `anonymousDefaultFeed: 'ranking'`. يجب أن يشير إلى مدخل في `feeds` تم التحقق من إتاحته دون تسجيل الدخول، مع تفضيل الترتيب. تستخدم الصفحة الرئيسية وصفحة المصدر هذا المدخل عند عدم تسجيل الدخول و`defaultFeed` عند تسجيل الدخول، مع الاحتفاظ بعلامة التبويب التي اختارها المستخدم صراحةً. لا تعتبر كل قائمة فارغة أو خطأ شبكة دليلًا على جلسة مجهولة.

### تعريف الخيارات

تستخدم `feeds[].options` و`searchFilters` و`settings` الصيغة نفسها:

```js
{ key: 'sort', label: '排序', type: 'select', default: 'date',
  values: [{ value: 'date', label: '最新' }, { value: 'popular', label: '热门', color: '#f00' }] }
// type: select | multi | number | text | password | switch
// يمكن استخدام options بدل values في settings
```

كل عنصر في `feeds` تبويب في صفحة الموقع: `{ key, label, options?: [...] }`.

### الشبكة

- `network.mode: 'native'` (الافتراضي): HTTP أصلي مع ملفات تعريف ارتباط دائمة عبر وكيل المستخدم. يُطلق تحدي Cloudflare الخطأ `CLOUDFLARE`، فيرشد التطبيق المستخدم إلى اجتيازه في المتصفح المدمج ويزامن ملفات العبور مع الطلبات الأصلية.
- `network.mode: 'browser'` + `network.origin`: تُرسل الطلبات بـ `fetch()` من الأصل نفسه عبر صفحة متصفح مخفية مفتوحة على `origin`، ببصمة متصفح حقيقي — للمواقع ذات حماية Cloudflare الصارمة. إذا تلقى طلب GET من الأصل نفسه تحديًا، ينتقل المتصفح المخفي إليه لاجتيازه تلقائيًا ويعيد الطلب مرة واحدة؛ وإن فشل يُطلق `CLOUDFLARE`.
- `network.vpnHint: true`: أعلنه للمواقع التي قد تحتاج إلى VPN أو وكيل في البر الرئيسي للصين؛ فيظهر عند الانتظار أكثر من 8 ثوانٍ وعند الفشل «قد تحتاج إلى VPN أو وكيل». لا تنسب كل الأخطاء إلى الـ VPN.
- `network.confirmation: { selector, readySelector, requiredCookies, message }`: للمواقع التي تتطلب تأكيدًا صريحًا (كالتحقق من العمر). يطابق `selector` نافذة التأكيد و`readySelector` المحتوى المتاح و`requiredCookies` ملفات الارتباط التي يجب أن توجد بعدها. عند صفحة غير مؤكدة تُطلق الإضافة `Park.error('CONFIRM_REQUIRED', message, { url })`، فيعرض التطبيق «تأكيد» ويعود حين تختفي النافذة ويظهر المحتوى وتُكتب الملفات ويستقر التنقل. لا يؤكد التطبيق نيابةً عن المستخدم أبدًا، ويمنع هذا الإعلان أيضًا صفحات التحقق العامة من اعتبار تأكيد العمر اجتيازًا.
- تحمل أخطاء الشبكة حقول `diagnostics` الآمنة `host` و`transport` و`reason` لتمييز شهادات TLS والمصافحة وDNS والاتصال والمهل؛ ولا تسجّل السجلات التلقائية سوى هذه الحقول. يعني `reason: 'TLS_HANDSHAKE_TERMINATED'` فقط أن `HandshakeException.message` الأصلي يساوي تمامًا `Connection terminated during handshake` (انقطع الاتصال قبل اكتمال المصافحة، وليس فشل شهادة)؛ ولا يُعاد إلا طلب HTTPS من نوع GET/HEAD بلا جسم مرة واحدة، ولا يُعاد غير ذلك.

### الصور

- `imageNetwork: { mode: 'browser', origin, domains }`: أعلنه حين تحتاج شبكة توصيل الصور إلى طلبات من المتصفح. يجب أن يقع `origin` وكل نطاقات الصور ضمن `domains`؛ HTTPS والترويسات المسموح بها فقط؛ لا تحمل طلبات الصور بيانات اعتماد ولا تتبع إعادة التوجيه وحدّها 20 MiB للصورة، وتمر كالمعتاد بفك التشفير وفحص الصيغة وفك الترميز والتخزين المؤقت لكل موقع. دونه يُستخدم النقل الأصلي.
- **الصور المشفرة**: أعلن `imageDecrypt` فيفك الإطار التشفير قبل فحص الصيغة والتخزين؛ تدخل إعدادات فك التشفير في هوية التخزين المؤقت ولا تُخزَّن النتائج الفاشلة. يُدعم AES-CBC مع حشو PKCS#7 صارم، و`key` و`iv` بترميز UTF-8؛ ويجب تحديد نطاقات الصور، وتسلك النطاقات الأخرى المسار العادي.

```js
imageDecrypt: {
  type: 'aes-cbc',
  key: '0123456789abcdef', // 16 أو 24 أو 32 بايت UTF-8
  iv: '0123456789abcdef',  // 16 بايت UTF-8
  domains: ['images.example.com'],
},
```

إعادة الغلاف HTTP 200 لا تكفي؛ تحقّق من أنه يُفك ترميزه.

### إذن الوسائط (HLS والملفات المباشرة)

إذن `media` مستقل عن `this.http` و`network` وملفات تعريف ارتباط الموقع:

```js
domains: ['example.com'],
network: { mode: 'native' },
media: { mode: 'native', origin: 'https://example.com', domains: ['media.example.com'] },
```

- `media.mode` إما `'native'` أو `'browser'`. يجب أن ينتمي `media.origin` إلى مواقع الإضافة ويستخدم HTTPS على المنفذ 443 دون بيانات اعتماد أو استعلام أو جزء.
- `media.domains` قائمة مستقلة لنطاقات الوسائط (مع النطاقات الفرعية) لا تمنح وصولًا إلى ملفات ارتباط الموقع. يجب أن تكون القوائم والمقاطع والمفاتيح HTTPS على 443، وتُرفض بيانات الاعتماد في الرابط والأجزاء وعناوين IP وlocalhost (ونطاقاتها الفرعية) و`.local`.
- يستخدم `'native'` عميلًا أصليًا مستقلًا بلا بيانات اعتماد: لا ملفات ارتباط للموقع ولا Authorization ولا مصادقة وكيل، ويُفحص كل انتقال إعادة توجيه مسبقًا. لا يُسمح إلا بـ `Referer` و`Origin` و`Accept` و`Accept-Language`، ويجب أن يطابق الأولان `media.origin`.
- يفتح `'browser'` جلسة وسائط في متصفح مخفي على `media.origin` مع `credentials: 'omit'` و`mode: 'cors'` و`redirect: 'error'`.
- يُقيَّد حجم الاستجابات أثناء استلامها ويُعاد فحص عنوانها النهائي: القوائم حتى 2 MiB، والمقاطع حتى 32 MiB، ومفاتيح AES-128 بطول 16 بايت تمامًا. تُرفض الاستجابات الكبيرة أو الفارغة والعناوين غير المسموح بها.

### العزل والأمان

- تعمل كل إضافة في بيئة JS **خاصة بها** (WebView مستقل بلا واجهة)، فلا ترى المتغيرات العامة للإضافات الأخرى؛ ويعرف الجسر الأصلي البيئة المستدعية، فلا يستطيع نص انتحال إضافة أخرى.
- لكل إضافة **مخزن ملفات ارتباط خاص**: لا تحمل طلباتها ولا تحفظ إلا ملفاتها.
- لا تُرسل ملفات Secure عبر HTTP أبدًا. يُتحقق من فتح صفحات التحقق واستيراد ملفات المتصفح مقابل `domains` للإضافة المثبتة مع الإبقاء على سمات الأمان والصلاحية المتاحة. مسح ملفات ارتباط الموقع أو إلغاء تثبيته يغلق أيضًا جلسة متصفحه ويمسح ملفاته في المتصفح؛ وهذه الملفات مشتركة على مستوى النظام، فتتأثر الإضافات التي تعلن الموقع نفسه بهذا المسح.
- يعلن `domains` المواقع التي تنتمي إليها الإضافة (نطاقات قابلة للتسجيل مع فروعها). لا تُزامَن مع المتصفح المدمج إلا ملفات هذه المواقع (المشترك بين تحقق Cloudflare وتسجيل الدخول عبر الويب)، ويجب أن ينتمي `network.origin` في وضع المتصفح إليها. عند غيابه يُستنتج من `homepage` و`network.origin` و`account.cookieUrl/loginUrl`.
- تُسقط عمليات إعادة التوجيه بين الأصول ترويسات المصادقة للأصل الأول، وتُرفض تلك التي تبقي جسم الطلب. التحقق من شهادات TLS مفعّل دائمًا.
- عند التثبيت من رابط أو مستودع يقرأ التطبيق النص أولًا في بيئة معزولة بلا شبكة، ويعرض الاسم والإصدار وSHA-256 والمواقع المعلنة والمخاطر، ولا يثبّت شيئًا قبل تأكيد المستخدم.

### الحسابات

```js
account: {
  type: 'password' | 'cookies' | 'session',
  title, hint, required: false,
  fields: [{ key: 'email', label: '邮箱' }, { key: 'password', label: '密码', secret: true }],
  loginUrl?, cookieUrl?, requiredCookies?: ['ipb_member_id'],   // يتيح تسجيل الدخول عبر الويب ويجمع التطبيق الملفات
  loginDomains?: ['accounts.google.com', 'appleid.apple.com'],  // نطاقات تسجيل الدخول الخارجية، للتنقل أثناء الدخول فقط
  async login(values) { return { name } },
  async logout() {},
  async status() { return { loggedIn, name, configured } },
  managedAccount: true,                 // اختياري: حساب مُدار تلقائيًا
  async enableManaged() {},             // يُستدعى فقط بعد موافقة المستخدم على التسجيل
}
```

- لا تُحدَّث حالة الحساب إلا عند أول استخدام، وبعد تسجيل الدخول والخروج وتسجيل الدخول عبر الويب، وحين يمضي على آخر تحقق أكثر من 10 دقائق — لا بعد كل استدعاء. يعني `configured` أن الحساب مُعدّ، سواء نجح الدخول حاليًا أم لا.
- `loginDomains`: نطاقات تسجيل الدخول الخارجية التي يستخدمها الموقع فعلًا (مع فروعها). لا يُسمح بها إلا ما دامت صفحة تسجيل الدخول عبر الويب مفتوحة، وعلى HTTPS 443 فقط؛ وتُرفض بيانات الاعتماد في الرابط وعناوين IP وlocalhost و`.local`. تظل صفحات التحقق وتأكيد الوصول وطلبات الإضافة واستيراد الملفات تُفحص مقابل `domains`؛ لا تضف نطاقات الدخول إلى `domains` لتوسيع الوصول. تدعم صفحة الدخول الانتقال في النافذة نفسها والنوافذ المنبثقة التي تحتفظ بـ `window.opener` مع الفحوص نفسها، ولا تمنح الصفحة الفارغة الأولى تنقلًا خارجيًا. لا يُعدّ الدخول مكتملًا أثناء البقاء في صفحة خارجية، وتُزامَن الملفات بعد العودة إلى الموقع. لا تُستورد الملفات الخارجية إلى مخزن الإضافة ولا تُمسح مع ملفات الموقع؛ يديرها WebView النظام. وقد تقيّد الخدمات الخارجية تسجيل الدخول في المتصفحات المدمجة.
- `type: 'session'` يستورد جلسة مصرَّحًا بها مسبقًا: أعلن حقلًا سريًا واحدًا (مثل `session`)، ويُحفظ محتوى الحافظة كاملًا وتتحقق منه الإضافة دون تقسيمه إلى اسم مستخدم وكلمة مرور أو ملفات ارتباط. يجب أن يؤكد تسجيل الدخول التفويض فعلًا؛ لا تعلن النجاح من شكل المُدخل وحده.
- يعلن `managedAccount: true` حسابًا مُدارًا تلقائيًا يتحكم فيه إعداد بالاسم نفسه. يجب أن يشرح التطبيق التسجيل التلقائي ويحصل على موافقة المستخدم أولًا، ثم يحفظ الإعداد ويستدعي `account.enableManaged()`. احفظ بيانات الاعتماد المرشحة ونفّذ `await this.store.flush()` قبل التسجيل لاستعادة الحساب نفسه بعد الفشل أو إعادة التشغيل. احفظ البيانات اليدوية والحساب المُدار منفصلين؛ فالحساب المُدار لا يستبدل اليدوي أبدًا. إيقاف الإعداد يُبقي الحساب المُدار لإعادة استخدامه، وانتهاء الرمز يؤدي إلى إعادة الدخول فقط دون تسجيل حساب جديد.
- كلمات المرور والرموز وحالة الإضافة بيانات محلية للمستخدم؛ لا تضع بيانات اعتماد حقيقية في المستندات أو السجلات.

## الدوال

يُشرح `this` داخل الدوال في «واجهة بيئة التشغيل». يمكن أن تكون كل الدوال `async`.

```js
async feed(key, { page, cursor, options }) {}      // تبويبات صفحة الموقع
async search({ keyword, page, cursor, filters }) {}
async random() {}                                  // يعيد معرّف عمل
async detail(id, preview) {}
async chapter(id, chapterId) {}                    // قصص مصورة ومعارض
async resolveImage({ id, chapterId, index, token, retry }) {}  // اختياري: حل الصور عند الحاجة
async thumbnails(id, page) {}                      // اختياري: صور مصغرة للمعاينة بالصفحات
async videos(id, episodeId = '_') {}               // فيديو
async textChapter(id, chapterId) {}                // روايات
async gameResources(workId) {}                     // ألعاب
async resolveGameResource(workId, resourceId, channelId) {}
```

### القوائم: `feed` / `search`

```js
{
  items: [WorkItem], page: 1, totalPages: 20, total: 500,
  hasNext: true,
  cursor: '12345',        // اختياري: تعيد المواقع ذات المؤشرات المؤشر التالي ويعيده التطبيق كما هو
}
// أو أقسامًا تُعرض في كتل:
{ sections: [{ title: '连载更新', items: [WorkItem] }], hasNext: false }
```

**WorkItem**: `{ id, title, subtitle?, cover, coverAspect?, pages?, rating?, likes?, views?, language?, category?, badge?, badgeColor?, duration?, uploaded?, tags?, mediaKind?, workCode?, editions? }`

- `workCode` هو رمز عمل مؤكّد من المصدر، ويُستخدم فقط للعثور على العمل نفسه. لا يحل محل `id` ولا يدمج هوية الأعمال أو المفضلة أو التقدم أو التنزيلات.
- `editions` يحتوي على تسميات إصدارات ثابتة يذكرها المصدر صراحة، مثل الترجمة الصينية أو نسخة مسرّبة غير خاضعة للرقابة. غياب التسمية لا يعني الإصدار الأصلي. عرض الترجمة لا يغيّر التسميات الأصلية.

- يتيح `coverAspect` (العرض / الارتفاع) ترتيب الشبكة قبل تحميل الصور.
- يلوّن `badgeColor` شارة الفئة.
- `mediaKind: 'comic' | 'video' | 'novel' | 'game'` هو نوع العمل نفسه. يمكن للإضافات ذات النوع الواحد حذفه، أما المختلطة فيجب أن تحدده — لا تعامل الصور كفيديو لمجرد `type` الإضافة. تحدده أعمال الروايات والألعاب دائمًا، كي تفتح الأعمال غير المتصلة والسجل في القارئ الصحيح حتى بعد إلغاء تثبيت الإضافة.
- يمكن أن تحمل نتائج المنشورات `presentation: 'post'` و`text` و`date` و`url` ومصفوفة `media` فتُعرض كبطاقات منشورات؛ ويعرض `presentation: 'media'` شبكة وسائط تفتح الوسائط داخل العمل. قد لا يحتوي المنشور على وسائط، وتخضع عناوين الوسائط للنطاقات والأذونات المعلنة.

### التفاصيل: `detail`

كل حقول WorkItem، إضافةً إلى:

```js
{
  url, authors: [], description, uploader?, size?, comments?,
  tags: [{ namespace: 'artist', label: '作者', tags: [{ name, keyword, filters?, count? }] }],
  chapters: [{ id, title }] | null,   // null يعني فصلًا واحدًا
  singleChapterId?,                   // معرّف الفصل الذي تحتاجه الأعمال ذات الفصل الواحد
  thumbnails?: [url | { url, width, height, offsetX, offsetY }],   // تدعم الصور المجمّعة
  related?: [WorkItem], series?: [WorkItem], variants?: [WorkItem],
}
```

- `variants` يحتوي فقط على روابط فعلية يقدّمها المصدر لإصدارات العمل نفسه في المصدر نفسه، مع `id` مستقل لكل إصدار؛ لا يجوز تخمين عناوين URL. تُبحث إصدارات المصادر الأخرى عبر `workCode` وتبقى المفضلة والتقدم والتنزيلات مستقلة.

- يبحث النقر على وسم في هذا الموقع باستخدام `keyword` و`filters`، فيمكن ربط الوسوم بصيغة الموقع الخاصة (مثل `artist:"xxx"`) أو بمعاملات التصفية.
- الوسيط الثاني الاختياري `preview` يحمل بيانات وصفية عامة معروضة أو محفوظة، ولا يُمرَّر إلا حين يطابق `preview.source` و`preview.id` الطلب. على الإضافة مع ذلك فحص المعرّف والتحقق من الروابط. الأعمال المفتوحة بمعرّف مكتوب لا معاينة لها، فقد يكون العنوان والغلاف ناقصين.

### الفصول: `chapter` / `resolveImage` / `thumbnails`

```js
{ pages: [
  { url, headers?, fallbacks?: [url], width?, height?, transform? },  // عنوان معروف
  { token: '12' },                                                      // مؤجل: يستدعي التطبيق resolveImage
]}
```

- `fallbacks`: مرايا تُجرَّب بالترتيب إذا فشل العنوان الرئيسي.
- `transform: { type: 'unscramble-strips', segments: N }`: للصور المقطّعة إلى N شرائط محفوظة بترتيب معكوس، وتُستعاد على GPU. تحفظ الملفات غير المتصلة الصورة الأصلية وتُستعاد عند العرض.
- تعيد `resolveImage` القيمة `{ url, headers?, width?, height?, cacheKey? }`. عند الفشل يستدعيها التطبيق مجددًا بقيمة `retry` أكبر، فتستطيع الإضافة تبديل الخادم.
- تعيد `thumbnails(id, page)` القيمة `{ thumbnails: [...], hasNext }`.

### الفيديو: `videos`

تعيد `[{ quality: 1080, label: '1080P', url, headers?, format?, preferred? }]`. تنتهي الروابط المباشرة عادةً، لذا يطلبها التطبيق من جديد قبل كل تشغيل أو تنزيل.

- تعيد الفيديوهات متعددة الحلقات `[{ id, title }]` بترتيب التشغيل في `detail(id).chapters`؛ ويجب أن يكون كل `id` ثابتًا، لا جودة ولا رابطًا مؤقتًا. يستخدم التطبيق المعرّف نفسه لاختيار الحلقات وحفظ التقدم والتنزيل والاستئناف، ويستدعي `videos(id, episodeId)` لكل حلقة. تستخدم الفيديوهات المنفردة `singleChapterId`، أو `'_'` عند غيابه.
- دون `format` يُعامل الرابط كملف MP4 مباشر في التشغيل والتنزيل. يجب أن يعيد HLS القيمة `format: 'hls'` ويعلن إذن `media`.
- يوسّع التطبيق قائمة HLS الرئيسية (`#EXT-X-STREAM-INF`) إلى قوائم لكل متغير ويأخذ الجودة الحقيقية من `RESOLUTION`. عند إعادة قائمة رئيسية تكون `quality` هي الجودة المرغوبة: تُختار أعلى جودة حقيقية لا تتجاوزها، وإلا فالأعلى. يجب أن يكون كل متغير MPEG-TS مدمج الصوت والصورة؛ وتُرفض مسارات `AUDIO` و`VIDEO` و`SUBTITLES` المنفصلة والعناوين خارج `media.domains`. تُتجاهل مسارات `#EXT-X-I-FRAME-STREAM-INF`. إذا لم تُعرف دقة قائمة منفردة فاستخدم `label: '原画'` بدل عرض الجودة المرغوبة كأنها حقيقية.
- لا تُدعم إلا قوائم VOD من MPEG-TS كاملة ومتصلة مع `#EXT-X-ENDLIST`؛ ويُفك تشفير `METHOD=AES-128` مع `KEYFORMAT=identity` (CBC/PKCS7) بمفاتيح طولها 16 بايت تمامًا وIV صريح أو مشتق من رقم التسلسل. تبقى المفاتيح في ذاكرة الجلسة فقط. لا يُدعم البث المباشر وSAMPLE-AES وصيغ KEYFORMAT الأخرى و`EXT-X-MAP` و`EXT-X-BYTERANGE` وfMP4 والانقطاعات والفجوات، ويُزال `#EXT-X-TOKEN` غير القياسي.
- يستخدم التشغيل منفذًا عشوائيًا مربوطًا بـ `127.0.0.1` ورمزًا عشوائيًا، ويقدّم المقاطع المُتحقَّق منها عند الطلب من سجل محدود للروابط، ويلغي إغلاق الجلسة الطلبات. تنزيل HLS دون اتصال على Android فقط حاليًا: يُتحقق من كل مقطع ويُحفظ SHA-256 له، ويمكن الاستئناف والإلغاء، ثم يجمع Media3 ملف MP4 في النهاية — ولا تصل إلى المكتبة غير المتصلة إلا الملفات الكاملة.

### الروايات: `textChapter`

تعلن إضافات الروايات `type: 'novel', category: 'novel'`، وتنفيذ `textChapter` يُخرج `capabilities.textChapter: true`. تحدد القوائم والتفاصيل `mediaKind: 'novel'` و`language: 'zh'` أو `'en'`. بلا غلاف حقيقي أعد `cover: ''` فيعرض التطبيق غلافًا نصيًا بدل طلب صورة وهمية.

```js
async textChapter(id, chapterId) {
  // النص الكامل للفصل؛ يجب أن تكون paragraphs مصفوفة سلاسل غير فارغة بلا HTML.
  return { title: '章节标题', paragraphs: ['第一段正文。', '第二段正文。'] };
}
```

- تعيد الروايات متعددة الفصول معرّفات ثابتة بترتيب القراءة المؤكد من الموقع في `detail.chapters`، وتستخدم القصص المنفردة `chapters: null` و`singleChapterId` اختياريًا.
- تدمج الإضافة تقسيم الفصل إلى صفحات بالترتيب، ولا تضم إلى النص الفصل التالي أو ردود المنتدى أو الإعلانات أو التوصيات. يستخرج `Park.html.paragraphs(node)` النص الخام بشكل عام، وتظل حدود الموقع وتقسيمه مسؤولية الإضافة.
- إذا اقتُطع النص بسبب تسجيل الدخول أو الدفع أو الأذونات فأطلق `LOGIN_REQUIRED`؛ ولا تقدّم المعاينة على أنها فصل كامل.
- يكتب التطبيق `text.json` لكل فصل بشكل ذري، ولا يُعدّ التنزيل مكتملًا إلا بالكتابة الكاملة. يستخدم التقدم والملاحظات مواضع UTF-16 في `paragraphs.join('\n\n')`، ولا تؤثر إعدادات الحجم والخط والمسافة البادئة إلا في العرض. تُحفظ الإشارات والملاحظات منفصلة عن التنزيلات، وتدخل في النسخ الاحتياطية، وتبقى بعد حذف التنزيل.

### الألعاب: `gameResources` / `resolveGameResource`

تعلن إضافات الألعاب `type: 'game', category: 'game'`، وتحدد أعمالها `mediaKind: 'game'` دون `chapters` وهمية. تُخرج البيئة `capabilities.gameResources` و`capabilities.resolveGameResource` من الدوال.

```js
async gameResources(workId) {
  return [{ id: 'resource-id', title: '', version: '1.2', size: '2 GB',
    platforms: ['Windows'], languages: ['SimplifiedChinese'], notes: '原站备注',
    status: 'valid', testStatus: 'untested',
    channels: [{ id: 'stable-channel-id', kind: 'direct', label: 'game.zip', size: '2 GB' }] }];
}
async resolveGameResource(workId, resourceId, channelId) {
  return { kind: 'direct', url: 'https://files.example/game.zip?temporary-signature',
    filename: 'game.zip', extractionCode: '', archivePassword: '' };
  // تعيد الأقراص السحابية kind: 'external' وurls: [كل المرايا والأجزاء] وurl: urls[0].
}
```

- لا تعيد `gameResources` إلا معرّفات ثابتة وبيانات وصفية وقنوات — بلا روابط موقّعة أو كلمات مرور أو حالات تنزيل وهمية. `testStatus` هو `tested | untested | unknown` منقولًا من الموقع؛ وتُعطَّل القنوات ذات `status: 'expired'`.
- لا تُستدعى `resolveGameResource` إلا عند نقر المستخدم أو إعادة المحاولة، ولا يُحفظ رابطها ولا يُسجَّل. يمكن حفظ كلمات المرور مع مهمة التنزيل المحلية لكن ليس في التشخيص. لا تُسقط روابط الأقراص السحابية؛ وعند إعادة عدة روابط يمكن أن تطابق `extractionCodes` الروابط `urls` واحدًا لواحد (السلسلة الفارغة تعني بلا رمز)، و`extractionCode` لرمز مشترك.
- تعلن القنوات التي تتطلب ردًا `requiresReply: true, replyText: 'نص الرد الفعلي'`، فيعرض التطبيق «الرد لفتح الروابط» والنص بالضبط، ولا يستدعي إلا بعد تأكيد المستخدم. قبل الحل يجب على الإضافة إعادة فحص المشاركة الأولى: إن كانت مفتوحة فتقرأ فقط، وترسل مرة واحدة وعند نقر المستخدم فقط بعد حفظ حالة الحساب والموضوع بشكل موثوق. إذا كانت النتيجة غير واضحة أو تكررت المحاولة أو لزم تحقق ديناميكي فأعد `CONFIRM_REQUIRED` مع رابط الموضوع ولا تُعِد الإرسال تلقائيًا أبدًا؛ ولا ترد أبدًا من القوائم أو التفاصيل أو التحميل المسبق أو التحديثات في الخلفية.
- تعلن الروابط المباشرة `media: { mode: 'native', origin, domains }`. تُنزَّل الملفات بالبث عبر عميل مستقل بلا ملفات ارتباط، ويتولى الإطار HTTPS وفحص النطاق في كل انتقال وفحص الطول والتنظيف عند الإلغاء وحماية الملفات المكتملة. لا يوجد استئناف؛ وإعادة المحاولة تحل العنوان من جديد وتبدأ من الصفر. تُفتح الأقراص السحابية في تطبيقات خارجية، مقتصرة على HTTP(S) وFTP(S) وmagnet وed2k وthunder، دون ملفات ارتباط الموقع. لا تنشئ الألعاب فصولًا أو تقدم قراءة أو تحديثات فصول، ولا يثبّت التطبيق الملفات أو يفك ضغطها أو يشغّلها أبدًا.

### الاشتراكات: `subscription`

تعلن إضافات الاشتراك (متابعة القنوات أو المبدعين) كائن `subscription`؛ وتُخرج البيئة `capabilities.subscription` عند وجود `normalize` و`posts` معًا، فيظهر الموقع في «استكشاف ← الاشتراكات». وتظهر الإضافات التي تعلن `feeds` أيضًا في الفئات العادية.

```js
subscription: {
  hint: '无需登录即可保存订阅；媒体访问取决于原站权限。',
  normalize(input) { return { id: validatedTarget, label: displayName }; },
  async resolve(input) { return { id: validatedTarget, label: displayName }; },
  async targets() { return [{ id: joinedChannelId, label: channelName }]; },
  async posts(target, { cursor }) {
    return { items: [{ id, title, text, date, url, locked,
      media: [{ type: 'image', url, preview, previewOnly: false },
              { type: 'video', url, preview, format: 'mp4', headers: {} }] }],
      cursor: nextCursor, hasNext: true };
  },
  async mediaChunk(resource, offset) { return { base64, done }; }, // اختياري
}
```

- يتحقق `normalize` محليًا فقط، كي يمكن حفظ الأهداف دون تسجيل دخول أو اتصال؛ ولا يقبل إلا أسماء المستخدمين أو روابط الملفات الشخصية الخاضعة للموقع نفسه. `resolve` و`targets` اختياريتان، ومع `targets` يُخرج manifest القيمة `subscription.joinedTargets: true`.
- مؤشرات `posts` سلاسل معتمة؛ للصفحة الأخيرة `hasNext: false`، ويمكن للصفحات الخالية من الوسائط المتابعة. يعني `locked` نقص الأذونات، ويشير `previewOnly` إلى معاينات عامة — لا تقدّم صورة مصغرة على أنها المحتوى الكامل.
- تستخدم المرفقات المصرَّح بها التي لا رابط مباشرًا لها `media[].resource` وتنفّذ `mediaChunk(resource, offset)`: 128 KiB كحد أقصى في كل استدعاء، والإزاحات مضاعفات 128 KiB؛ ويجب أن يحتوي resource على `size` صحيح وسلسلة `cacheKey` ثابتة غير سرية لا تتغير مع بيانات الاعتماد أو المراجع المؤقتة. يتحقق الإطار من الحجم الكلي ومن كل جزء ويكتب ذريًا في مساره المؤقت الخاص؛ يصل المرفق إلى 512 MiB ولا يختار resource المسار المحلي. لا تُحفظ الروابط الموقّعة ولا resource في سجلات الاشتراك.
- حفظ الاشتراك لا يتابع شيئًا ولا ينضم إلى شيء. يجب أن توجّه عمليات الكتابة غير المُتحقَّق منها المستخدم إلى الموقع الأصلي؛ لا تتابع ولا تنضم ولا تدفع بصمت أبدًا.

### اشتراكات التحديث: `updateSubscriptions`

يمكن للإضافات العادية دعم «متابعة التحديثات» بكائن `updateSubscriptions` مستقل. لا تُخرج البيئة `capabilities.subscriptionUpdates` إلا بوجود `check`، ولا يتغير بذلك تصنيف العمل ولا `capabilities.subscription`. تتضمن البيانات الوصفية `dimensions: [{ key, label, hint }]`، ويمكن لقوائم الوسوم تمرير الكلمة الأصلية ومعاملات التصفية.

- تعيد `normalize(dimension, input)` القيمة `{ id, label }`، وتعيد `check({ dimension, target }, { cursor })` القيمة `{ items, hasNext, cursor }`. العناصر هي `{ id, title, kind, workId, chapterId }` و`kind` مقتصر على `work | post | chapter`، بمعرّفات ثابتة غير فارغة دون روابط وسائط أو ملفات ارتباط أو بيانات اعتماد. تتضمن معرّفات الفصول هوية العمل كي لا يتصادم «الفصل 1» لأعمال مختلفة.
- يوفّر `Park.enableUpdateSubscriptions(Park.__pending, rules)` محوّلًا عامًا؛ أعلن الأبعاد صراحةً في نهاية النص مع `searchFilters` و`seriesPattern` اختياريًا. يستخدم `work` قائمة الفصول الحقيقية، و`posts` واجهة القنوات الحالية، و`search` و`filter` البحث، ويطابق `code` الرموز الكاملة تمامًا، ويستخدم `series` مسارات سلاسل مُتحقَّقًا منها مقابل نطاقات الموقع. تحفظ مؤشرات البحث رقم الصفحة ومؤشر الموقع معًا.
- تعيد فحوص البحث والمنشورات `windowed: true`، أي أنها تفحص آخر ثلاث صفحات: يسجّل الفحص الأول خط أساس فقط، وتُنشئ الفحوص التالية أحداث «محتوى جديد» حسب المعرّف الثابت دون ادعاء معرفة تاريخ النشر. تفحص بروتوكولات الصفحات الأخرى ثلاث صفحات كحد أقصى في كل جولة وتحفظ المؤشرات والمرشحين ثم تعتمدها في معاملة واحدة عند الانتهاء؛ ولا تُقتطع قوائم الفصول أبدًا، بحد أقصى 20,000 مرشح (تجاوزه خطأ). يجب أن تطلق أعطال الشبكة والأذونات والتحقق والقوائم الفارغة والتحليل الناقص أخطاءً صريحة، لا نجاحًا فارغًا.
- تتشارك الواجهة والخلفية بيئة الإضافة وأقسام ملفات الارتباط وقيود النطاقات وآلية الفحص. لا تبدأ الخلفية إلا الإضافات المعنية، ولا تسجّل الدخول ولا تشترك في الموقع ولا تنزّل الوسائط ولا تتجاوز الأذونات. يعيد تغيير الحساب أو إعدادات الإضافة بناء خط الأساس (تجديد الرمز لا يفعل).

## واجهة بيئة التشغيل

داخل الدوال يوفّر `this`:

| العضو | الوصف |
| --- | --- |
| `this.http` | `request(opts)` و`get(url, opts)` و`post(url, opts)` و`text(url, opts)` و`json(url, opts)` |
| `this.config` | القيم التي اختارها المستخدم في إعدادات الموقع (`default` عند عدم الضبط) |
| `this.store` | مخزن دائم للمفاتيح والقيم: `get(key, fallback)` / `set(key, value)` للرموز وقوائم النطاقات وغيرها؛ و`await flush()` يؤكد الكتابة ويطلق خطأ عند الفشل |
| `this.cookies` | `get(url)` / `set(url, { name: value })` / `clear(url)` |
| `this.log({ code, host, transport, reason })` | يكتب هذه الحقول المسموح بها فقط؛ ويُسقط النص الحر كي لا تتسرب بيانات الاعتماد والعناوين |

الأدوات العامة:

| الأداة | الوصف |
| --- | --- |
| `Park.html.parse(text)` | يعيد `Document` قياسيًا لاستخدام `querySelector` |
| `Park.html.text(node)` / `unescape(s)` / `strip(html)` / `paragraphs(node)` | معالجة النصوص |
| `Park.crypto.md5Hex(text \| text[])` | MD5، ويقبل المصفوفات |
| `Park.crypto.sha256Hex` / `hmacSha256Hex(key, text)` / `aesEcbDecrypt(base64, key)` / `uuid()` | تنفيذات أصلية |
| `Park.crypto.digestBytes('sha1' \| 'sha256', bytes)` | مصفوفات أعداد صحيحة 0–255 حتى 2 MiB |
| `Park.crypto.randomBytes(length)` | بايتات عشوائية آمنة، length من 1 إلى 65536 |
| `Park.utils.rateLimiter(ms)` | يعيد `wait()` ويضمن فاصلًا أدنى بين الطلبات |
| `Park.utils.mapLimit(items, n, fn)` / `lruMap(n)` / `parseCount('1.2万')` / `formatDate(ts)` | أدوات أخرى |
| `Park.error(code, message, extra?)` | ينشئ خطأ برمز، راجع «رموز الأخطاء» |

### `http.request(opts)`

```js
await this.http.request({
  url, method: 'GET', headers: {}, params: { q: 'x' },   // تُضاف params إلى الرابط
  json: {...} | form: {...} | body: 'raw' | bodyBase64: '...',
  timeout: 15000,
  responseType: 'text' | 'base64',
});
// → { status, headers, body, url, ok, json() }
```

- تطلق `text()` / `json()` خطأ عند الاستجابات خارج 2xx (404 ← `NOT_FOUND`). تُحفظ ملفات الارتباط تلقائيًا ويُعاد اختيارها لكل وجهة إعادة توجيه.
- `bodyBase64` جسم ثنائي (حتى 2 MiB) لا يُجمع مع `body` أو وضع المتصفح، ويتبع قواعد عزل النطاقات وTLS وإعادة التوجيه نفسها الخاصة بالطلبات النصية. لا تستطيع الإضافات فتح شبكة المتصفح أو WebSocket أو وصول عشوائي إلى الملفات بنفسها.

## رموز الأخطاء

أطلق الخطأ بـ `throw Park.error(code, message, extra)`، فيتصرف التطبيق حسب الرمز:

| code | ما يفعله التطبيق |
| --- | --- |
| `CLOUDFLARE` | «التحقق»: يفتح المتصفح المدمج |
| `CONFIRM_REQUIRED` | «تأكيد»: ينتظر حتى يُكمل المستخدم تأكيد الوصول المعلن (يشير إليه `extra.url`) |
| `LOGIN_REQUIRED` | «تسجيل الدخول»: يفتح قسم الحساب في إعدادات الموقع |
| `NOT_FOUND` | يعرض «المحتوى غير موجود» |
| `BLOCKED` | يعرض «الوصول مقيّد» (حظر IP أو نفاد الحصة…) ولا يعيد محاولة الصور |
| `NETWORK` | يعرض «تعذّر الاتصال» مع السبب و«إعادة المحاولة» |
| `HTTP` / `PARSE` / `UNSUPPORTED` / `CONFIG` | يعرض رسالة الإضافة و«إعادة المحاولة» |

### الرسائل المنظَّمة

`message` **قالب بالصينية** وهو أيضًا مفتاح الترجمة؛ ضع الأجزاء المتغيرة في `extra.params` بدل ربطها بالنص:

```js
throw Park.error('HTTP', '站点返回 HTTP {status}', { params: { status: res.status }, status: res.status });
throw Park.error('NOT_FOUND', '影片不存在');
```

يترجم التطبيق القالب أولًا بـ `i18n` الخاص بالإضافة ثم بالمفردات المشتركة للتطبيق، ويملأ العناصر النائبة من `params`. لا يمكن ترجمة النص المربوط، فسيراه المستخدمون الذين لا يقرؤون الصينية بالصينية. تعمل `status` و`url` و`diagnostics` في `extra` كما كانت.

### التخزين المؤقت للصفحة الرئيسية ودلالة الأخطاء

- تحتفظ نتائج `feed` الحية بكل حقول الإضافة؛ أما التخزين المؤقت على القرص فلا يحفظ إلا بيانات العرض المسموح بها (المعرّف والعنوان والغلاف والوسوم والناشر ونوع الوسائط والفئة وإحصاءات العرض)، ولا تُكتب `url` أو بيانات الاعتماد أو قوائم الوسائط أو المنشورات. لا تضع بيانات اعتماد في المعرّفات أو روابط الأغلفة أو المؤشرات. لا تُخزَّن النتائج التي تحتاج إلى وسائط ديناميكية أو منشورات.
- لا يُعرض التخزين المؤقت القديم كمحتوى غير متصل إلا عند أخطاء `NETWORK` / `TIMEOUT` الصريحة، ويُوسَم بأنه مخزَّن. يجب أن تطلق أعطال الدخول والتأكيد والتحقق البشري والتحليل والإعداد أخطاءها الخاصة؛ ولا يقدّمها الإطار كأعطال شبكة أبدًا، ويعرض التحديث الذي يبدؤه المستخدم الخطأ الحقيقي أيضًا.

## تعدد اللغات

تدعم واجهة التطبيق `zh-Hans` و`zh-Hant` و`ja` و`ko` و`en` و`es` و`ru` و`ar` (العربية من اليمين إلى اليسار). اكتب كل نص ثابت ظاهر للمستخدم في الإضافة (الاسم والوصف وأسماء التبويبات والخيارات وتلميح البحث وملاحظات الحساب ورسائل الأخطاء) **بالصينية المبسطة**؛ فالنص الأصلي هو مفتاح الترجمة.

تحمل الإضافة ترجماتها في حقل `i18n` من manifest:

```js
Park.register({
  i18n: {
    'zh-Hant': { '发行日期': '發行日期', '影片不存在': '影片不存在' },
    'en': { '发行日期': 'Release date', '影片不存在': 'Video not found', '站点返回 HTTP {status}': 'The site returned HTTP {status}' },
    // وكذلك ja وko وes وru وar
  },
  key: 'mysite',
  // …
});
```

- ترتيب البحث: `i18n` الإضافة للغة الحالية ← `en` الخاص بالإضافة (عدا الصينية المبسطة) ← المفردات المشتركة للتطبيق (`assets/i18n/`، مثل «الترتيب» و«الأحدث» و«رائج») ← النص الأصلي.
- لا يلزم في `i18n` إلا ما ليس في التطبيق أصلًا؛ وتستعمل الكلمات الشائعة ترجمات التطبيق. يجب أن تطابق العناصر النائبة `{name}` الأصل.
- لا يُترجم المحتوى البعيد (العناوين والمؤلفون والوسوم والأوصاف) ولا ما يكتبه المستخدم ولا مفاتيح البروتوكول المحفوظة كنصوص واجهة.
- تغيير `i18n` تغيير للإضافة ويتطلب رفع الإصدار. يرى مستخدمو الإصدار الأقدم النصوص القديمة حتى يحدّثوا.

تُستدعى نصوص واجهة التطبيق نفسه عبر `tr('已选 {count}', { 'count': count })` أو `context.tr`، وتوجد ملفات اللغات الثماني في `assets/i18n/`، ويجب أن تحدّث كل إضافة أو تعديل جميعها بالعناصر النائبة نفسها.

## النشر

### المستودعات

المستودع ملف `index.json` واحد على أي استضافة ثابتة. يكتب المستخدم عنوانه في «المزيد ← المواقع ← إضافة موقع» ليتصفح ويثبّت ويحدّث:

```json
{
  "name": "我的站点仓库",
  "apiVersion": 1,
  "sources": [
    {
      "key": "mysite",
      "name": "我的站点",
      "version": "0.0.1",
      "description": "一句话介绍",
      "url": "https://example.com/sources/mysite.js",
      "sha256": "SHA-256 لنص UTF-8 للنص البرمجي بـ 64 رقمًا ست عشريًا",
      "apiVersion": 1
    }
  ]
}
```

`url` هو العنوان الكامل للنص، ويصلح أيضًا `file` نسبةً إلى `index.json`. تُثبَّت المستودعات الخارجية يدويًا بعد تأكيد المستخدم؛ و`sha256` اختياري ويُتحقق منه عند وجوده.

### الإصدارات وقواعد التحديث

- الإصدار ثلاثة أعداد صحيحة غير سالبة مفصولة بنقاط دون أصفار بادئة (مثل `0.0.1`)، تُقارَن رقميًا جزءًا جزءًا؛ وتُرفض الأجزاء الناقصة أو الزائدة ولواحق الإصدارات التجريبية.
- يجب أن تقدّم التحديثات الرسمية `sha256` لنص UTF-8 للنص البرمجي (دون قص المسافات أو تحويل نهايات الأسطر)، وأن يطابق `key` و`version` في النص الفهرس؛ ويجب أن يساوي `apiVersion` إصدار بيئة التطبيق تمامًا وإلا يُرفض التحديث.
- إصدارات الإضافات والتطبيق مستقلة. عند تعديل نص إضافة (بما فيه `i18n`) ارفع الإصدار في النص وفي `assets/sources/index.json`؛ ويرفض الناشر خفض الإصدار والإصدار نفسه بمحتوى مختلف.

### التحديثات الرسمية في التطبيق

- خيار «التحقق من تحديثات الإضافات عند التشغيل» في «المزيد ← المواقع» و«المزيد ← حول التطبيق ← التحديثات» مفعّل افتراضيًا: يقرأ كل تشغيل الفهرس الرسمي فقط، ويعلن عن الإصدارات الجديدة، ولا ينزّل ويتحقق ويثبّت إلا بعد تأكيد المستخدم. عند العودة إلى الواجهة يحترم فاصلًا مدته 12 ساعة، ويُسجَّل وقت الفحص حتى عند الفشل. مع إيقاف الفحص التلقائي يبقى الفحص اليدوي متاحًا. لا يُفحص إلا الإضافات المدمجة والرسمية المثبتة؛ ولا تُثبَّت إضافات جديدة تلقائيًا ولا يُستولى على إضافات خارجية بالمفتاح نفسه.
- يعيد التثبيت التحقق من الهوية والإصدار والمصدر والواجهة والبصمة، ولا يكتمل إلا بعد نجاح التهيئة وحفظ الحالة؛ وعند الفشل يبقى النص القديم وحالة المستخدم، ويُستعاد التثبيت المقطوع عند التشغيل التالي. لا يكتب التشغيل فوق الإضافات المثبتة بالنصوص المرفقة أبدًا؛ وإن فُقد نص بقي سجلّه وبياناته حتى يستعيده المستخدم أو يحدّثه. يعيد «استعادة الإصدار المدمج» بعد التأكيد الإصدار المضمَّن في حزمة التطبيق الحالية.
- تُفحص تحديثات التطبيق نفسه افتراضيًا أيضًا: على Android وبعد التأكيد ينزّل التطبيق ملف APK الرسمي المناسب ويتحقق من الحجم وSHA-256 واسم الحزمة والإصدار والتوقيع ثم يفتح مثبّت النظام، مع التقدم والإلغاء وإعادة المحاولة؛ وصفحة الإصدارات الرسمية هي البديل.

### نشر الإضافات الرسمية

تُنشر الإضافات الرسمية من المستودع الرئيسي [drdon1234/Hentai-Park](https://github.com/drdon1234/Hentai-Park)، ويقرأ التطبيق:

```text
https://raw.githubusercontent.com/drdon1234/Hentai-Park/sources/index.json
https://raw.githubusercontent.com/drdon1234/Hentai-Park/rankings/index.json
```

- `assets/sources/index.json` هو القائمة الوحيدة المُدارة؛ ويشير `file` إلى نص في المجلد نفسه باسم `{key}.js` (`[A-Za-z0-9_-]+.js`؛ دون مجلدات فرعية أو روابط رمزية أو نقاط في الاسم الأساسي).
- يولّد `tools/publish_sources.mjs` الفهرس المنشور بـ `key` و`name` و`version` و`category` و`description` و`url` و`sha256` و`apiVersion`، وتُثبَّت روابط النصوص على الإيداع الكامل للمصدر: `https://raw.githubusercontent.com/drdon1234/Hentai-Park/<SHA الإيداع>/assets/sources/<file>`. لا يحوي فرع `sources` إلا `index.json` المولَّد.
- لا يحتاج الناشر إلا الوحدات المدمجة في Node.js 22 فأحدث ويعمل دون اتصال: يفحص القائمة والملفات وحدود المجلد، ويحمّل البيئة والنصوص دون شبكة أو تخزين، ويتحقق من `key` و`version` والواجهة بفحص `Park.__pending` / `Park.manifest` نفسه المستخدم في معاينة التثبيت. لا يستدعي `init` أو تسجيل الدخول أو دوال المواقع، لذا لا يغني عن الطلبات الحقيقية.

```powershell
node tools/publish_sources.mjs --commit '<SHA الإيداع الكامل من 40 حرفًا>' --output 'test/official-source-index.json'
```

يبقى المصدر في الفرع الرئيسي. يوزع `sources` الإضافات العادية و`rankings` إضافات الترتيب. يحفظ الفرعان فهرساً مولداً فقط يتضمن رابط التزام ثابت وSHA-256. يتحقق سير العمل من كل قناة وينشرها بصورة مستقلة، ويقرأ التطبيق القناتين بصورة مستقلة ويرفض العلامات المخالفة ومفاتيح key المكررة ويحتفظ بتأكيد التحديث.

## ملحق: ملاحظات عن المواقع الرسمية

اصطلاحات يلزم معرفتها عند صيانة الإضافات الرسمية. المواقع تتغير، والمرجع هو شيفرة الإضافة.

**الألعاب**

- الترتيب الافتراضي: KUN Galgame ← GalgameX ← مقهى الأبعاد. يفعّل GalgameX وKUN محتوى NSFW افتراضيًا (واجهة الضيف `content-filter` والمعامل `include_nsfw` على الترتيب).
- يفتح GalgameX افتراضيًا الأكثر رواجًا هذا الأسبوع. تستخدم قائمة الموارد المحدَّثة Next Server Action مكتشفة من الواجهة الحالية للموقع؛ يُخزَّن معرّفها 15 دقيقة ويُعاد اكتشافه عند توقفه، دون تنفيذ نصوص بعيدة. تُحلَّل التفاصيل من بيانات SSR Flight. تستخدم الموارد العامة المضيف وتجزئة المسار معرّفًا ثابتًا للقناة، وتُطابَق النتائج حسب المضيف واسم الملف / معرّف المشاركة مع رفض عدم التطابق والتكرار، دون الاعتماد على ترتيب الروابط المؤقتة.
- يفتح KUN افتراضيًا ترتيب المشاهدات لسبعة أيام عبر واجهته الأصلية العامة؛ ولا تُستدعى واجهة التنزيل إلا عند النقر حتى لا يضخّم التحميل المسبق عداد تنزيلات الموقع. تُتصفح صفحات الموارد حسب العدد الكلي من الواجهة؛ والصفحات المكررة أو الفارغة مبكرًا أخطاء.
- يستخدم مقهى الأبعاد وضع المتصفح مع تسجيل دخول خاص، ويفتح افتراضيًا الرائج في لوحة موارد Galgame؛ تأتي الأغلفة من مرفقات المشاركة الأولى بفاصل 400 ms بين الطلبات. قائمة الموارد للقراءة فقط، ولا يُرسل الرد «感谢分享，好人一生平安» بالنموذج الكامل إلا بعد تأكيد المستخدم. لا يُرد في المواضيع المفتوحة مسبقًا؛ وإن كانت النتيجة غير واضحة تُحفظ الحالة ويُوجَّه المستخدم إلى الموضوع، ولا يُعاد الإرسال بعد إعادة التشغيل.

## الترتيبات والتوزيع المستقل

يعرّف `rankings` القوائم عبر `key` و`label` و`category` و`metric` و`options`. تضبط الإضافة المخصصة `rankingOnly: true` دون `feeds`. تعيد `ranking(board, {page, offset, cursor, options})` صفحة أعمال تحتوي على `id` و`rank` الأصلي و`title` و`cover` وحقول اختيارية `keyword` و`subtitle` و`url` منتج HTTPS. تُحفظ المراكز المتساوية. يمكن للمصدر الحالي تحديد `feed` لتوريث الخيارات عند حذفها وإعادة استخدام `feed()`، مع حفظ الحقول وإضافة `workId` والمركز المفقود لفتح التفاصيل. تبحث النتائج التجارية ضمن الفئة المحددة.

يبقى المصدر في الفرع الرئيسي. يوزع `sources` الإضافات العادية و`rankings` إضافات الترتيب. يحفظ الفرعان فهرساً مولداً فقط يتضمن رابط التزام ثابت وSHA-256. يتحقق سير العمل من كل قناة وينشرها بصورة مستقلة، ويقرأ التطبيق القناتين بصورة مستقلة ويرفض العلامات المخالفة ومفاتيح key المكررة ويحتفظ بتأكيد التحديث.

```powershell
node tools/publish_sources.mjs --commit '<SHA>' --channel rankings --output 'test/official-ranking-index.json'
```
