# 公共设计准则

本文件是项目设计规范的入口，维护跨平台的产品语义、交互原则和设计方法。具体视觉、尺寸、导航形式、输入方式与系统行为由各平台准则定义；公共准则不代表某个平台已经实现或完成验收。

## 内容与任务

1. **内容优先。** 封面、标题、正文和播放画面承担主要信息，界面装饰服务于识别、操作和阅读。没有数据的字段不制造占位信息，不用装饰填满内容自然结束后的视口。
2. **围绕完整任务组织入口。** 页面应回答当前位置、可执行动作、动作结果和下一步。一级导航服务于稳定的主要任务；详情、历史、更新和管理功能按实际任务关系组织。
3. **主要动作明确。** 同一任务保持一致入口和名称，每个操作区有清晰的主次层级。移除重复入口时保留完成任务所需的能力；工具区拥挤时按优先级组织，不让常用操作消失。
4. **结构服从内容。** 漫画、视频、小说、游戏和帖子可以共用视觉语言，但不强行共用布局。分类决定发现范围，媒体类型决定阅读或播放方式；订阅、排行榜、反搜候选和资料条目各有独立语义。
5. **真实能力决定入口。** 只展示已经接通的站点与设备能力；付费限制、登录要求、预览与完整内容需要准确表达。不以空结果、默认字段或相似图标掩盖不支持与失败。

## 操作语义与用户意图

- 本地收藏、原站收藏、订阅、下载、历史和已读状态分别表达，不用一个操作隐式改变其他状态。
- 翻译属于展示层，搜索值、原文、标签和内容身份保留原值；屏蔽在展示时应用，临时显隐与永久规则编辑区分。
- 屏蔽预设分别展示普通与扩大范围规则，生效项显示勾选，摘要只统计当前生效的主规则（不含别名）；标题匹配独立控制，无扩大范围规则时隐藏对应开关。规则可编辑、删除，展示与匹配使用同一生效集合。
- 可点击、可选择、静态元数据和破坏性操作各自保持可辨识的表达；图标含义不明确时提供文字，不让用户猜测。
- 同一功能跨页面复用同一组件与状态表达：分类导航保留相同按钮外观和选择反馈，下载进度保留相同方向与状态含义；不因入口位于主页、域页、网格或列表而改变操作心智。进入下一层的链接与切换当前范围的选项分别表达。
- 操作在用户意图明确后提交：输入法组词不等于搜索，未完成的拖动不等于切集，新资源准备失败不应丢弃旧内容。
- 普通可逆操作减少确认打断；不可撤销的删除和代替用户对外发送的行为先确认，说明对象、范围和结果。取消保留原状态。
- 下载、导出、保存与删除在实际完成后才报告成功；本地文件缺失时明确提示，不悄悄改变为联网操作或写入其他位置。

## 状态连续性与资源边界

- 保留用户当前查询、筛选范围、阅读位置、播放分集、暂停意图及必要设置。刷新、返回、旋转与显示模式切换分别定义恢复行为。
- 页面状态与底层资源分开管理；需要释放播放器、请求或浏览器会话时保留恢复所需的信息，不依靠无限保留资源维持上下文。
- 菜单、弹层、完整页面覆盖、后台和退出是不同状态，不能统一当作暂停或销毁。具体行为由平台准则定义。
- 页面已构建不等于可见。自动分页、翻译、推荐和预加载需要同时考虑路由、视口、账号与查询有效性；迟到结果不能覆盖新状态。
- 当前阅读和播放优先于预加载；请求、缓存、解码器及销毁中的资源都有明确上限与所有者。可取消的操作需要真实停止和释放。
- 内容身份与临时访问地址分开；账号、权限、插件或设置变化后重新核对可用性，已有缓存不扩大访问权限。

## 反馈、失败与恢复

- 区分初次加载、后台刷新、空结果、部分失败、完全失败和结束状态。空结果不代替解析失败或权限不足。
- 已有可用内容继续展示，局部失败就近提供重试；翻译失败保留原文，联想失败不阻断搜索，单个站点失败不拖垮其他站点。
- 可先显示有效缓存或已取得的部分结果，再渐进补全；缓存结果与实时分页状态分开，不能把过期游标当作新会话继续推进。
- 自动重试以请求无副作用为前提；不能仅凭所在页面名称判断。登录、上传、互动写入及取消不盲目重放，工程边界见开发说明。
- 反馈说明发生了什么、影响范围和可执行的下一步。网络、代理、证书、登录与服务端错误分别表达，不把所有失败都归因于 VPN。
- 切换选中、展开、加载完成和提示显隐尽量保持布局稳定；控制层叠加在阅读或播放内容上，不因显隐重排正文与画面。

## 可访问性与平台适配

- 正常屏幕和默认字号下先保证信息比例、主要操作与阅读顺序，再处理窄屏、大字体、长文案和宽屏场景。
- 字体、点击区域、系统栏、键盘、返回、文件选择和权限提示采用目标平台行为。适配不能只按宽度把手机布局放大或把桌面交互缩小。
- 状态不能只靠颜色表达；为操作提供语义名称和选择状态，装饰元素不干扰读屏。尊重字体缩放和系统移除动画。
- 动效表达状态和空间关系，不做无用途的循环装饰。触感只确认已生效的用户动作，具体反馈强度由平台准则规定。
- 文字复制限定在实际内容区域，独立点击或长按操作不与文字选择抢手势；正文仍保留合理的跨行选择与滚动能力。

## 设计与修复方法

1. **画清任务路径。** 写出进入、主要操作、失败、取消、退出和再次进入；先定位用户实际受阻的环节，再决定是否需要改变结构。
2. **厘清语义和边界。** 明确数据身份、账号与权限、操作副作用，以及本地状态与原站状态的区别。
3. **确定层级和内容结构。** 选择主要入口与主要动作，根据内容类型组织信息，删除重复表达；具体样式引用平台令牌和共用组件。
4. **定义状态转换。** 为加载、空、失败、重试、隐藏、后台和返回写出行为；明确异步结果何时仍有效、资源何时释放、用户意图何时提交。
5. **修正共同根因。** 相同问题优先在组件、控制器或通用能力中解决；站点差异留在插件，避免逐页增加互相矛盾的特例。
6. **验证完整路径。** 先检查默认场景的真实画面和操作，再检查大字体、窄屏、弱网、快速连续操作、生命周期与恢复；布局不溢出仅是最低条件。
7. **更新唯一规则。** 把确认后的公共结论或平台细则写回对应文档，删除被替换的规则，工程机制写入开发说明。

## 设计验收边界

- 同一帖子或消息的图片、视频按原始顺序在同一浏览页左右切换；打开任一附件后仍可访问全部附件。视频封面保留播放提示，切出视频页立即停止播放；横向切换不与视频拖动进度竞争。

- 每次界面视觉验收必须同时覆盖“正常屏幕＋正常字体”和“窄屏＋大字体”两组组合场景，对改动涉及的同一页面、组件与关键状态分别检查并保留证据；两组均通过才算完成。不能仅检查其中一组，也不能用分别检查窄屏和大字体代替二者同时启用。
- 检查信息层级、内容比例、按钮辨识度、入口可发现性、反馈、空状态和恢复路径；静态检查或组件可容纳内容不能单独证明易用性。
- 横向检查同类功能是否复用相同控件与状态表达；逐层核对页面外边距、分组边距与控件内边距，确认标题、正文、列表和操作遵守同一页面边界。滚动到中段与末尾后再次检查，不能只验收初始位置。
- 组件截图补充目标平台的真实运行证据；记录设备、系统、页面、主题、字号和场景。模拟平台外观不等于对应平台验收。
- 安卓手机、安卓平板、Web 和 Windows 的验收范围分别记录；平台规范占位不能作为已实现或已验收的证据。
- 设计文档描述有效规则和明确限制，不堆放实施流水、测试数量与已经废止的方案。

### 站点浏览形态

- 主页和域页统一使用作品卡片，不继承站内布局。没有作品封面时使用内容语义图标：音声为耳机，小说与漫画为书本，游戏为手柄，视频为影片，资讯为文章；不得用损坏图片图标表示缺少封面。
- 站内入口、分类结果、筛选结果和搜索结果遵循同一原站浏览形态：封面目录使用网格，论坛和无封面的音声条目使用文字横条，小说使用文字列表，资讯与社区使用文章流、帖子流。插件通过 browseLayout 声明普通目录的默认布局，框架不按站点名称分支。
- 原站目录有真实层级时保留文件夹、面包屑及逐层进入；分类存在依赖时保留上级到下级的选择关系，不把无层级的平面分类伪造成树。原站排序、动态选项和搜索专属筛选由插件声明，不用统一虚构选项替代。
- 列表加载占位应与最终排列一致；退出账号等异步操作立即显示进度并禁用重复触发，成功后切换账号状态，失败后恢复操作并就近反馈。

- 详情命中屏蔽规则时默认隐藏作品内容，使用主题中性色提示与页面级临时显隐入口；列表、推荐、相册和短视频的临时显隐不得改写永久规则。
- 详情顶部主标题及副标题按完整内容自然换行，译文长度变化后重新排版；不要使用内部滚动文本框或固定行数裁切，收起后的导航栏标题仍可单行省略。

### 酒馆任务语义

- 角色卡与世界书共用发现、收藏和详情导航，角色卡的主要动作是开始对话；世界书用于关联会话。保存到本地与导出原文件分别表达，取消导出不得隐式新增已保存资源。
- 每条消息展示头像与发送时的名称，角色优先使用角色卡头像，用户以人格标识及靠右中性色消息块区分；头像缺失时提供身份占位。会话正文优先展示角色身份、用户身份和文本；消息编辑、删除及分支收入消息菜单，最后一条回复保留续写与重生成。生成只在用户仍跟随底部时滚动，回看历史不被流式更新打断。
- 用户人格属于会话数据；候选回复、分支、部分生成、未保存状态各自表达。删除此条及后续消息先说明范围，保存失败和离开页面不能静默丢弃用户内容。
