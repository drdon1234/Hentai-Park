# واجهة إضافات المواقع

[البدء السريع](#البدء-السريع) · [حقول manifest](#حقول-manifest) · [الدوال](#الدوال) · [واجهة بيئة التشغيل](#واجهة-بيئة-التشغيل) · [رموز الأخطاء](#رموز-الأخطاء) · [تعدد اللغات](#تعدد-اللغات) · [النشر](#النشر)

كل موقع في HentaiPark إضافة JavaScript مستقلة. يحمّل التطبيق الإضافات أثناء التشغيل، ويمكن تثبيتها من مستودع وتحديثها وتفعيلها وتعطيلها **دون إعادة بناء التطبيق**. توجد الإضافات الرسمية في [`assets/sources/`](../../../assets/sources/) وتصلح أمثلةً مباشرة.

النسخة الصينية المبسطة من هذا المستند هي المرجع. تبقى قواعد كل موقع داخل إضافته، ويوفّر الإطار الشبكة والتخزين المؤقت والصور، ولا يعامل أي موقع معاملة خاصة باسمه.

## البدء السريع

### بيئة التشغيل

- تعمل الإضافات داخل WebView بلا واجهة في التطبيق، مع JS حديثة و`DOMParser`. توفّر الطبقة الأصلية التشفير وملفات تعريف الارتباط وHTTP الأصلي؛ لا يخضع HTTP الأصلي لقيود CORS، بينما تتبع شبكة المتصفح والوسائط قواعدها الموضحة أدناه.
- تبدأ بيئة الإضافة عند أول استخدام للموقع، وتُحرَّر بعد نحو 5 دقائق من الخمول أو عند تشغيل أكثر من 6. يُخزَّن manifest مؤقتًا حسب «SHA-256 للنص + إصدار البيئة»، لذا لا يشغّل فتح التطبيق الإضافات. لا تفترض أن الإضافة تعمل فور بدء التطبيق.
- البيئة نفسها ([`assets/runtime/park_runtime.js`](../../../assets/runtime/park_runtime.js)) تعمل في Node، فيمكنك التجربة على مواقع حقيقية أثناء التطوير. مضيف Node أداة تطوير وليس بيئة معزولة للنصوص غير الموثوقة.

### أصغر إضافة

```js
Park.register({
  key: 'mysite',
  name: '我的站点',
  version: '0.0.1',
  minAppVersion: '0.9.2',
  type: 'comic',
  category: 'doujin',
  homepage: 'https://example.com',
  domains: ['example.com'],
  defaultFeed: 'popular',
  feeds: [{ key: 'popular', label: '热门' }],

  async feed(key, { page }) {
    const doc = Park.html.parse(await this.http.text(`https://example.com/popular?page=${page}`));
    return {
      items: [...doc.querySelectorAll('.gallery')].map((el) => ({
        id: el.dataset.id,
        title: Park.html.text(el.querySelector('.title')),
        cover: el.querySelector('img').src,
      })),
      hasNext: !!doc.querySelector('.next'),
    };
  },
  async detail(id) { /* … */ },
  async chapter(id, chapterId) { /* … */ },
});
```

## حقول manifest

```js
Park.register({
  key: 'mysite',              // فريد ودائم؛ [A-Za-z0-9_-] فقط، من 1 إلى 100 حرف، وليس _app
  name: '我的站点',
  version: '0.0.1',
  minAppVersion: '0.9.2',           // ثلاثة أرقام؛ يعرض التطبيق التحديث إن كان إصدار المستودع أعلى
  type: 'comic',              // comic | video | novel | game: طريقة قراءة الأعمال أو تشغيلها
  category: 'doujin',         // doujin | anime | aiDrama | jav | adult | shortvideo | recording | live | gallery | illustration | novel | game | other
  color: '#E5355F',           // لون العلامة: أيقونة الموقع وصفحته
  description: '一句话介绍',
  homepage: 'https://example.com',
  domains: ['example.com'],                   // المواقع التابعة، راجع «العزل والأمان»؛ يُستنتج من homepage وغيره عند غيابه
  linkPatterns: ['example\\.com/g/(\\d+)'],   // الروابط الملصقة تفتح العمل مباشرة؛ المجموعة الأولى هي معرّف العمل
  idPattern: '^(\\d+)$',                      // المعرّفات المكتوبة تفتح العمل مباشرة
  imageHeaders: { Referer: 'https://example.com/' },  // الترويسات الافتراضية للأغلفة والصور
  network: { mode: 'auto', vpnHint: true },  // راجع «الشبكة»
  media: { mode: 'browser', origin: 'https://example.com', domains: ['media.example.com'] },  // إذن الوسائط للفيديو والملفات المباشرة
  imageNetwork: { mode: 'browser', origin: 'https://img.example.com', domains: ['img.example.com'] }, // اختياري
  imageDecrypt: { /* اختياري، راجع «الصور المشفرة» */ },

  settings: [ /* الخيارات، راجع «تعريف الخيارات» */ ],
  account: { /* اختياري، راجع «الحسابات» */ },
  defaultFeed: 'ranking',     // التبويب المفتوح افتراضيًا في صفحة الموقع (مفتاح من feeds)
  feeds: [ /* تبويبات صفحة الموقع */ ],
  searchFilters: [ /* عوامل تصفية البحث */ ],
  searchHint: '搜索技巧提示',
  i18n: { /* ترجمات الواجهة الخاصة بالإضافة، راجع «تعدد اللغات» */ },

  subscription: { /* اختياري: متابعة القنوات والمبدعين، راجع «الاشتراكات» */ },
  postShortVideos: true,
  updateSubscriptions: { /* اختياري: اشتراكات التحديث */ },

  async init() {},              // اختياري: يُستدعى مرة عند بدء البيئة (مثل تحديث قائمة النطاقات)
  async onSettingsChanged() {}, // اختياري: يُستدعى بعد تغيير المستخدم إعدادات الموقع
  // إضافةً إلى دوال قسم «الدوال»
});
```

تستخرج البيئة القدرات (`capabilities`) تلقائيًا من الدوال المنفَّذة؛ لا تكتبها يدويًا.

### النوع والفئة

يحدد `type` طريقة قراءة الأعمال أو تشغيلها أو معاملتها كموارد ألعاب، ويحدد `category` مكان الموقع في «استكشاف» وإدارة المواقع والبحث. تذهب الفئات غير المعروفة أو الغائبة إلى «أخرى». يجب أن تعلن المواقع الجديدة نوعها وفئتها وقدراتها بدقة.

| الفئة | المعنى |
| --- | --- |
| `doujin` | دوجينشي وقصص مصورة |
| `gallery` | معارض الصور: كوسبلاي وتصوير ومجموعات صور لأشخاص حقيقيين. تستخدم مواقع الصور `type: 'comic'`؛ كل مجموعة عمل واحد وتعيد `chapter()` الصور بالترتيب مع مشاركة القراءة والمفضلة والتنزيل. لا يحدد عدد الصور أو جرأتها الفئة |
| `illustration` | معارض الرسوم: الرسوم التوضيحية وصور الأنمي. تستخدم مواقع الصور `type: 'comic'`؛ كل مجموعة عمل واحد وتعيد `chapter()` الصور بالترتيب مع مشاركة القراءة والمفضلة والتنزيل. لا يحدد عدد الصور أو جرأتها الفئة |
| `anime` | أنمي للبالغين |
| `aiDrama` | دراما قصيرة بالذكاء الاصطناعي. لا تُقبل القيمة القديمة `drama`؛ أعلن أسماء قنوات الموقع كما هي، ولا تُصفّيها فئة التطبيق |
| `jav` | مواقع JAV المتخصصة |
| `adult` | فيديو عام للبالغين (Pornhub وXVideos و91porn…)، `type: 'video'`. الفئة تجميع فقط ولا تحل محل وسوم الموقع أو عوامل تصفية المستخدم |
| `shortvideo` | مقاطع قصيرة: موجز عمودي بملء الشاشة، انظر أدناه |
| `recording` | تسجيلات الفيديو والمشاهدة عند الطلب، `type: 'video'` |
| `live` | البث المباشر, `type: 'video'` |
| `novel` | روايات، `type: 'novel'` |
| `game` | ألعاب، `type: 'game'` |
| `other` | مجتمعات المبدعين |

- **المقاطع القصيرة** (`type: 'video', category: 'shortvideo'`): تفتح الأعمال والبحث والمفضلة والسجل الموجز مباشرة. كل عمل مقطع واحد، و`videos(id, '_')` يعيد وسائطه الحالية دون حاجة إلى صفحة تفاصيل. يحمّل `hasNext` و`cursor` من `feed` الصفحة التالية قرب النهاية تلقائيًا، ولا يجوز أن تحتوي المؤشرات على بيانات اعتماد أو تواقيع وسائط. يبدأ التحديث من الصفحة الأولى؛ يُشغَّل العنصر الحالي ويُحمَّل التالي مسبقًا متوقفًا ويُحرَّر الباقي. لا تعلن `search` إن لم يكن للموقع بحث.
- **فيديوهات المنشورات** (`postShortVideos: true`): تشغّل صفحات الموقع وأهداف الاشتراك كل فيديو في `media[]` منفصلًا. يلزم `url` مباشر أو `episodeId` غير فارغ؛ يستدعي الحل المؤجل `videos(originalPostId, episodeId)` عند التشغيل أو التحميل المسبق، ولا يستخدم صفحة ويب كرابط وسائط. الصور خارج المشغّل؛ وتدعم المرفقات `preview` و`format` و`headers`. يحافظ التقليب والتحديث على feed ومرشحاته أو نطاق `subscription.posts` للهدف. يميز التشغيل المرفقات، بينما تستخدم المفضلة والسجل وتفاعلات الموقع معرّف المنشور الأصلي. لا تتغير الفئة ولا يُفترض وجود API مستقل للفيديو العشوائي.
- **المجمّعات التي لا تُشغَّل إلا في الموقع الأصلي**: تبقى على `type: 'video', category: 'adult'`؛ وبلا واجهة وسائط مُتحقَّق منها لا تُنفَّذ `videos`، فتُخرج البيئة `capabilities.videos: false`. يفتح الزر الرئيسي `detail.url` في متصفح النظام، ويُخفى التشغيل والتنزيل والحلقات، ولا تُحفظ فصول وهمية ولا يُتحقق من تحديثاتها؛ وتبقى المفضلة والسجل.
- **الروايات** و**الألعاب** مشروحة في «الدوال».

اختر `defaultFeed` بالترتيب **الموصى به > التصنيفات > الرائج**، ولا تستخدم صفحة الأحدث أو مدخلًا آخر إلا إن خلا الموقع منها فعلًا، ولا تخترع واجهة غير مُتحقَّق منها. عند غيابه أو عدم وجود المفتاح يختار التطبيق حسب المفتاح (أولًا `promote` / `recommend` / `featured`، ثم `rank` / `toplist`، ثم `popular` / `hot` / `trending`)، وإلا فالتبويب الأول.

تُعلن المصادر التي تسمح بالتصفح المجهول وتتطلب تسجيل الدخول للتوصيات عن `anonymousDefaultFeed: 'ranking'`. يجب أن يشير إلى مدخل في `feeds` تم التحقق من إتاحته دون تسجيل الدخول، مع تفضيل الترتيب. تستخدم الصفحة الرئيسية وصفحة المصدر هذا المدخل عند عدم تسجيل الدخول و`defaultFeed` عند تسجيل الدخول، مع الاحتفاظ بعلامة التبويب التي اختارها المستخدم صراحةً. لا تعتبر كل قائمة فارغة أو خطأ شبكة دليلًا على جلسة مجهولة.

### تعريف الخيارات

تستخدم `feeds[].options` و`searchFilters` و`settings` الصيغة نفسها:

```js
{ key: 'sort', label: '排序', type: 'select', default: 'date',
  values: [{ value: 'date', label: '最新' }, { value: 'popular', label: '热门', color: '#f00' }] }
// type: select | multi | number | text | password | switch
// يمكن استخدام options بدل values في settings
```

كل عنصر في `feeds` تبويب في صفحة الموقع: `{ key, label, options?: [...] }`.

### عوامل التصفية والترتيب العامة

تعلن الإضافات عن `commonFilters` لكل موجز و`searchCommonFilters` للبحث. يعرض التطبيق القدرات المعلنة فقط ولا يصفّي الأعمال المحمّلة محليًا بالتقريب. يجب تحويل الشروط إلى استعلام حقيقي للموقع والحفاظ عليها بين الصفحات. الأبعاد هي `pages` و`likes` و`duration`؛ يعلن `range: true` أو مصفوفة الحدود `min` و`max`، ويعلن `sort: true` أو مصفوفة اتجاهات `asc` و`desc`. الصفحات والإعجابات أعداد صحيحة غير سالبة، والمدة بالثواني. تمرر طلبات `feed` و`search` خريطة `common` مستقلة، ويمكن ترك أي حد فارغًا، ولا يسمح بالترتيب إلا لبعد واحد في كل مرة. يجب رفض الأبعاد غير المعلنة.

### التصفية الديناميكية والمتسلسلة

يمكن لخيارات الاختيار في `feeds[].options` و`searchFilters` إعلان `dynamic: true, values: []`. يشير الخيار التابع إلى آباء المجموعة نفسها عبر `dependsOn: ['range']`. يجب أن تكون المفاتيح فريدة والتبعيات موجودة وبلا دورات. تعلن الخيارات الديناميكية وحدها التبعيات.

تعيد `filterOptions(request)` مصفوفة خيارات. يتضمن الطلب `scope: 'feed' | 'search'` و`filter` و`values`؛ وتضيف القوائم `feed` وقد يضيف البحث `keyword`. تتضمن `values` الآباء المباشرين المعلنين فقط، دون بيانات الحساب أو الإعدادات أو المرشحات الأخرى. لا تُحمّل الخيارات التابعة ما دام أحد الآباء فارغاً أو غير محدد.

أعلن `keywordDependent: true` إذا كانت الخيارات تعتمد على كلمة البحث. يؤدي تغيير الكلمة إلى إعادة ضبط الخيار وتوابعه مع إبقاء المرشحات الأخرى. تكون قيم الآباء في `values` نصوصاً أو أرقاماً أو قيماً منطقية، لا مصفوفات اختيار متعدد. التسميات الأصلية ليست نصوص واجهة ثابتة، ويمكن استخدام ترجمة المحتوى والوسوم.

الحد الأقصى 500 عنصر بصيغة `{value, label, color?}`. القيم نصوص فريدة أو أرقام محدودة. التسميات أسماء أصلية غير فارغة بلا محارف تحكم وبحد 256 محرفاً، والألوان ستة أرقام سداسية عشرية. تُقسّم الأدلة الكبيرة إلى مجموعات متسلسلة دون بتر صامت. لا تُترجم تسميات الموقع تلقائياً.

تصل الاختيارات إلى `feed` عبر `options` وإلى `search` عبر `filters`. تتحقق الإضافة من الانتماء الفعلي للدليل وتحافظ على الشروط عبر الصفحات؛ ويجب أن يطلق فشل التحليل خطأً. تُخزن الخيارات دقيقتين بحسب الموقع والنطاق والقائمة أو كلمة البحث وقيم الآباء. يزيل تغيير الأب اختيارات الأبناء ويهمل الردود القديمة، ويمكن إعادة المحاولة عند الفشل.

تقرأ إضافة كل نطاق دليله فقط. لا تستدعي النطاقات المرتبطة إضافات بعضها ولا تشارك Cookie. يُعاد استخدام التحليل بقوالب وقت البناء مع توليد سكربتات مستقلة. يولّد `node tools/build_catalog_sources.mjs` الأدلة، ويتحقق `--check` من تطابقها.

```js
{key: 'category', label: '分类', type: 'select', default: '',
 dynamic: true, dependsOn: ['range'], values: []}

async filterOptions({scope, feed, filter, keyword, values}) {
  return [{value: 'site-category-id', label: 'Site category'}];
}
```

### الشبكة

- `network.mode: 'auto'` (الافتراضي): يستخدم HTTP الأصلي أولاً. لطلبات GET/HEAD عبر HTTPS من الأصل نفسه ومن دون جسم، تؤدي تحديات Cloudflare أو استجابات HTTP ‏403 و429 أو أخطاء الاتصال القابلة للتعافي إلى إعادة محاولة واحدة عبر المتصفح. لا تفتح أخطاء DNS وTLS والمهلة وتدفق الاستجابة واستجابات 5xx العادية المتصفح، لتجنب التأخير الإضافي. يجب أن يكون الهدف ضمن نطاقات المصدر المعلنة، وتبقى قيود الأصل نفسه وإعادة التوجيه سارية.
- `network.mode: 'native'`: يفرض HTTP الأصلي مع Cookie الدائمة والوكيل المضبوط. عند اكتشاف Cloudflare يعيد `CLOUDFLARE` لإعادة المحاولة داخل التطبيق؛ إذا تضمن الخطأ رابط تحقق داخل الموقع، يمكن للمستخدم فتح صفحة التأكيد.
- `network.mode: 'browser'` + `network.origin`: يرسل `fetch()` من صفحة مخفية على `origin` ضمن المصدر نفسه. عند Cloudflare (بما فيه HTTP 200) أو بوابة عمر دون Cookie/المحتوى المطلوب، ينتقل طلب القراءة للتحقق مرة واحدة كحد أقصى ثم يعيد القراءة؛ لا يكرر الكتابة. يتبع العمر `network.confirmation`. يرسل Android وWindows إدخالًا لخانة Cloudflare القياسية الوحيدة، وتنتظر المنصات الأخرى التحقق التلقائي. عند الفشل يمكن إعادة المحاولة أو فتح التأكيد إذا توفر رابط تحقق داخل الموقع.

  يتنقل المستند ضمن النطاقات المعلنة بنفس البروتوكول والمنفذ. إن لم يُحدد `origin` للطلب، يُشتق من عنوان الموقع المستهدف. يحتفظ الرد بعنوان `url` النهائي.

  لا يُستخدم الانتقال التلقائي مع `followRedirects: false` أو `connectAddress` أو أخطاء الشبكة غير المصنفة. لطلبات GET/HEAD في المتصفح دون جسم ثلاث محاولات عادية كحد أقصى ومحاولة إضافية واحدة بعد التحقق، فقط لأعطال الاتصال أو HTTP ‏408 و500 و502 و503 و504؛ ولا تُكرر استجابات 429 أو المهلات. يُسمح بانتقال تحقق واحد لكل طلب منطقي عبر جميع المحاولات. لبدء المتصفح والطلبات وقراءة المستند والإغلاق حدود انتظار. تُرسل رؤوس API المخصصة عبر `fetch()` فعليًا دون استبدال الطلب بنتيجة التنقل. تحتفظ مستندات HTML المعاد استخدامها بحالة الخطأ، ويُرجع `responseType: 'base64'` البايتات الأصلية بترميز base64.

- `network.vpnHint: true`: أعلنه للمواقع التي قد تحتاج إلى VPN أو وكيل في البر الرئيسي للصين؛ فيظهر عند الانتظار أكثر من 8 ثوانٍ وعند الفشل «قد تحتاج إلى VPN أو وكيل». لا تنسب كل الأخطاء إلى الـ VPN.
- `network.confirmation: { selector, readySelector, requiredCookies, auto: { clickSelector }, message }`: يعلن بوابة تأكيد العمر. يحدد `selector` النافذة، و`auto.clickSelector` زر التأكيد الوحيد داخلها، و`readySelector` المحتوى المتاح، و`requiredCookies` أسماء ملفات Cookie المطلوبة بعد التأكيد. لا يحاكي المتصفح المخفي النقر إلا بعد تأكيد البلوغ عند دخول التطبيق، ثم يتحقق من اختفاء النافذة وظهور المحتوى ووجود Cookie واستقرار التنقل. عند نقص القاعدة أو عدم تطابقها أو فشل التأكيد التلقائي، يمكن إعادة المحاولة. إذا تضمن الخطأ رابط تحقق داخل الموقع، يمكن فتحه والتعامل معه يدوياً ثم الضغط على تم. تبقى قيود نطاق المصدر وفصل Cookie سارية، ولا تعيد إشعارات العمليات تنفيذ الإجراء الأصلي تلقائياً. لا يستخدم لتسجيل الدخول أو الدفع أو النشر.
- تحمل أخطاء الشبكة حقول `diagnostics` الآمنة `host` و`transport` و`reason` لتمييز شهادات TLS والمصافحة وDNS والاتصال والمهل؛ ولا تسجّل السجلات التلقائية سوى هذه الحقول. يعني `reason: 'TLS_HANDSHAKE_TERMINATED'` فقط أن `HandshakeException.message` الأصلي يساوي تمامًا `Connection terminated during handshake` (انقطع الاتصال قبل اكتمال المصافحة، وليس فشل شهادة)؛ ولا يُعاد إلا طلب HTTPS من نوع GET/HEAD بلا جسم مرة واحدة، ولا يُعاد غير ذلك.

### الصور

- `imageNetwork: { mode: 'browser', origin, domains }`: نطاقات الصور وفروعها مستقلة عن صلاحيات Cookie للموقع. ينتمي `origin` إلى الموقع أو الصور. تستخدم الطلبات HTTPS 443 والترويسات المسموحة مع جلسة الموقع للصور من نفس الأصل عندما ينتمي origin إلى نطاق الموقع المعلن؛ لا ترسل الصور من أصل آخر أو أصول الصور الخارجية أو الفيديو بيانات اعتماد، مع إعادة التوجيه بين نطاقات الصور المصرح بها. يبقى حد 20 MiB وفك التشفير وفحص الصيغة وفك الترميز والتخزين لكل موقع. دون التصريح يُستخدم النقل الأصلي. راجع صلاحيات الوسائط لقيود إعادة التوجيه حسب المنصة.
- **الصور المشفرة**: أعلن `imageDecrypt` فيفك الإطار التشفير قبل فحص الصيغة والتخزين؛ تدخل إعدادات فك التشفير في هوية التخزين المؤقت ولا تُخزَّن النتائج الفاشلة. يُدعم AES-CBC مع حشو PKCS#7 صارم، و`key` و`iv` بترميز UTF-8؛ ويجب تحديد نطاقات الصور، وتسلك النطاقات الأخرى المسار العادي.

```js
imageDecrypt: {
  type: 'aes-cbc',
  key: '0123456789abcdef', // 16 أو 24 أو 32 بايت UTF-8
  iv: '0123456789abcdef',  // 16 بايت UTF-8
  domains: ['images.example.com'],
},
```

إعادة الغلاف HTTP 200 لا تكفي؛ تحقّق من أنه يُفك ترميزه.

### إذن الوسائط (HLS والملفات المباشرة)

إذن `media` مستقل عن `this.http` و`network` وملفات تعريف ارتباط الموقع:

يجب على كل إضافة تنفذ `videos()` إعلان أذونات `media` صالحة، حتى عند إرجاع MP4 فقط. يمكن الجمع بين `scope: 'session'` وقائمة `domains` الثابتة: يستخدم HLS عناوين URL المحددة المصرح بها للجلسة، بينما يجب أن يطابق MP4 المباشر قائمة النطاقات الثابتة. يرفض فحص النشر الرسمي الإعلانات المفقودة أو غير الصالحة.

```js
domains: ['example.com'],
network: { mode: 'native' },
media: { mode: 'native', origin: 'https://example.com', domains: ['media.example.com'] },
```

- `media.mode` إما `'native'` أو `'browser'`. يجب أن ينتمي `media.origin` إلى مواقع الإضافة ويستخدم HTTPS على المنفذ 443 دون بيانات اعتماد أو استعلام أو جزء.
- `media.domains` قائمة مستقلة لنطاقات الوسائط (مع النطاقات الفرعية) لا تمنح وصولًا إلى ملفات ارتباط الموقع. يجب أن تكون القوائم والمقاطع والمفاتيح HTTPS على 443، وتُرفض بيانات الاعتماد في الرابط والأجزاء وعناوين IP وlocalhost (ونطاقاتها الفرعية) و`.local`.
- `'native'`: يستخدم عميلًا مستقلًا دون Cookie أو Authorization أو مصادقة الوكيل ويفحص كل إعادة توجيه قبل الاتصال. يسمح بـ `Referer` و`Origin` و`Accept` و`Accept-Language` فقط؛ ينتمي الأولان إلى نطاقات الموقع المعلنة بما فيها فروع اللغة، ويحتوي `Origin` على الأصل فقط.
- الحقل الاختياري `media.referrerDomains` مخصص لوسائط الفيديو الأصلية فقط، بحد أقصى 16 نطاقًا عامًا صالحًا مع نطاقاتها الفرعية. يوسع مصادر `Referer` المسموح بها فقط كاستثناء صريح لقيد نطاقات الموقع أعلاه. لا يمنح صلاحيات إضافية لـ `Origin` أو عناوين الوسائط أو تنقل المستندات أو ملفات الارتباط، ولا يُسمح به في `imageNetwork` أو وسائط المتصفح.
- `'browser'`: ينشئ جلسة مخفية في `media.origin` مع التنقل ضمن نطاقات الموقع. يستخدم `credentials: 'omit'` و`mode: 'cors'` ويحدد المستند الحقيقي والمتصفح Origin/Referer. يفحص WebView2 في Windows النطاق قبل كل اتصال ويسمح بإعادة التوجيه المصرح بها ويفحص العنوان النهائي. لا توفر المحركات الأخرى اعتراض كل خطوة فتستخدم `redirect: 'error'`. تبقى CORS وCSP نافذتين؛ لا يكفي فحص العنوان النهائي للسماح بإعادة التوجيه.
- يُقيَّد حجم الاستجابات أثناء استلامها ويُعاد فحص عنوانها النهائي: القوائم حتى 2 MiB، والمقاطع حتى 32 MiB، ومفاتيح AES-128 بطول 16 بايت تمامًا. تُرفض الاستجابات الكبيرة أو الفارغة والعناوين غير المسموح بها.

- يمكن لشبكات HLS المتغيرة إعلان `media.scope: 'session'` مع `mode: 'native'`. يقتصر الإذن على الروابط وموارد القائمة والتحويلات المسموحة التي حُلّت لجلسة التشغيل أو التنزيل الحالية وينتهي بإغلاقها. لا يوسّع صلاحيات Cookie أو النطاقات الدائمة. تبقى قيود HTTPS والطلبات بلا بيانات اعتماد والوجهة وحجم الاستجابة؛ ويستخدم MP4 المباشر ووسائط المتصفح قوائم نطاقات ثابتة.

### العزل والأمان

- تعمل كل إضافة في بيئة JS **خاصة بها** (WebView مستقل بلا واجهة)، فلا ترى المتغيرات العامة للإضافات الأخرى؛ ويعرف الجسر الأصلي البيئة المستدعية، فلا يستطيع نص انتحال إضافة أخرى.
- لكل إضافة **مخزن ملفات ارتباط خاص**: لا تحمل طلباتها ولا تحفظ إلا ملفاتها.
- لا تُرسل ملفات Secure عبر HTTP أبدًا. يُتحقق من فتح صفحات التحقق واستيراد ملفات المتصفح مقابل `domains` للإضافة المثبتة مع الإبقاء على سمات الأمان والصلاحية المتاحة. مسح ملفات ارتباط الموقع أو إلغاء تثبيته يغلق أيضًا جلسة متصفحه ويمسح ملفاته في المتصفح؛ وهذه الملفات مشتركة على مستوى النظام، فتتأثر الإضافات التي تعلن الموقع نفسه بهذا المسح.
- يعلن `domains` المواقع التي تنتمي إليها الإضافة (نطاقات قابلة للتسجيل مع فروعها). لا تُزامَن مع المتصفح المدمج إلا ملفات هذه المواقع (المشترك بين تحقق Cloudflare وتسجيل الدخول عبر الويب)، ويجب أن ينتمي `network.origin` في وضع المتصفح إليها. عند غيابه يُستنتج من `homepage` و`network.origin` و`account.cookieUrl/loginUrl`.
- تُسقط عمليات إعادة التوجيه بين الأصول ترويسات المصادقة للأصل الأول، وتُرفض تلك التي تبقي جسم الطلب. التحقق من شهادات TLS مفعّل دائمًا.
- عند التثبيت من رابط أو مستودع يقرأ التطبيق النص أولًا في بيئة معزولة بلا شبكة، ويعرض الاسم والإصدار وSHA-256 والمواقع المعلنة والمخاطر، ولا يثبّت شيئًا قبل تأكيد المستخدم.

### الحسابات

```js
account: {
  type: 'password' | 'cookies' | 'session',
  title, hint, required: false,
  fields: [{ key: 'email', label: '邮箱' }, { key: 'password', label: '密码', secret: true }],
  loginUrl?, cookieUrl?, requiredCookies?: ['session_id'],   // يتيح تسجيل الدخول عبر الويب ويجمع التطبيق الملفات
  loginDomains?: ['accounts.google.com', 'appleid.apple.com'],  // نطاقات تسجيل الدخول الخارجية، للتنقل أثناء الدخول فقط
  localStorageKeys?: ['session_key'],  // قراءة المفاتيح المسموحة فقط من أصل cookieUrl وتمريرها إلى login(values)؛ يُمنع تسجيل قيمها
  async login(values) { return { name } },
  async logout() {},
  async status() { return { loggedIn, name, configured } },
  managedAccount: true,                 // اختياري: حساب مُدار تلقائيًا
  async enableManaged() {},             // يُستدعى فقط بعد موافقة المستخدم على التسجيل
}
```

عند تسجيل الخروج، يحذف التطبيق من أصل cookieUrl المفاتيح المعلنة في localStorageKeys فقط ويحتفظ ببقية التخزين المحلي. تستخدم تشخيصات القوائم الفارغة أسباباً ثابتة: UPSTREAM_EMPTY (القائمة الأصلية فارغة)، NO_VIDEO (لم يتم اختيار فيديو)، EMPTY_RESULT (لا محتوى بعد التحميل)، CONTENT_FILTERED (مخفي بقواعد العرض)، SEARCH_ONLY (تجاوز التوصيات لتوفير البيانات). تسجل فقط تغيرات الحالة الفارغة والتعافي، وليس كل صفحة ناجحة. يجب ألا تحتوي السجلات على العناوين أو كلمات البحث أو معرفات المحتوى أو الجلسات أو روابط الوسائط.

- لا تُحدَّث حالة الحساب إلا عند أول استخدام، وبعد تسجيل الدخول والخروج وتسجيل الدخول عبر الويب، وحين يمضي على آخر تحقق أكثر من 10 دقائق — لا بعد كل استدعاء. يعني `configured` أن الحساب مُعدّ، سواء نجح الدخول حاليًا أم لا.
- `loginDomains`: نطاقات تسجيل الدخول الخارجية التي يستخدمها الموقع فعلًا (مع فروعها). لا يُسمح بها إلا ما دامت صفحة تسجيل الدخول عبر الويب مفتوحة، وعلى HTTPS 443 فقط؛ وتُرفض بيانات الاعتماد في الرابط وعناوين IP وlocalhost و`.local`. تظل صفحات التحقق وتأكيد الوصول وطلبات الإضافة واستيراد الملفات تُفحص مقابل `domains`؛ لا تضف نطاقات الدخول إلى `domains` لتوسيع الوصول. تدعم صفحة الدخول الانتقال في النافذة نفسها والنوافذ المنبثقة التي تحتفظ بـ `window.opener` مع الفحوص نفسها، ولا تمنح الصفحة الفارغة الأولى تنقلًا خارجيًا. لا يُعدّ الدخول مكتملًا أثناء البقاء في صفحة خارجية، وتُزامَن الملفات بعد العودة إلى الموقع. لا تُستورد الملفات الخارجية إلى مخزن الإضافة ولا تُمسح مع ملفات الموقع؛ يديرها WebView النظام. وقد تقيّد الخدمات الخارجية تسجيل الدخول في المتصفحات المدمجة.
- `type: 'session'` يستورد جلسة مصرَّحًا بها مسبقًا: أعلن حقلًا سريًا واحدًا (مثل `session`)، ويُحفظ محتوى الحافظة كاملًا وتتحقق منه الإضافة دون تقسيمه إلى اسم مستخدم وكلمة مرور أو ملفات ارتباط. يجب أن يؤكد تسجيل الدخول التفويض فعلًا؛ لا تعلن النجاح من شكل المُدخل وحده.
- يوفّر `managedAccount: true` و`account.enableManaged()` إدارة اختيارية للحساب، ولا تُفعّل إلا بعد شرحها وتأكيد المستخدم. احفظ الحسابات اليدوية والمُدارة منفصلة دون استبدال بيانات الاعتماد الحالية. تبقى بيانات الحساب على الجهاز ولا تُدرج في الوثائق أو التشخيص أو ملفات الإصدار.
- كلمات المرور والرموز وحالة الإضافة بيانات محلية للمستخدم؛ لا تضع بيانات اعتماد حقيقية في المستندات أو السجلات.

## الدوال

يُشرح `this` داخل الدوال في «واجهة بيئة التشغيل». يمكن أن تكون كل الدوال `async`.

```js
async feed(key, { page, cursor, options, common }) {} // تبويبات صفحة الموقع
async search({ keyword, page, cursor, filters, common }) {}
async random() {}                                  // يعيد معرّف عمل
async detail(id, preview) {}
async chapter(id, chapterId) {}                    // قصص مصورة ومعارض
async resolveImage({ id, chapterId, index, token, retry }) {}  // اختياري: حل الصور عند الحاجة
async thumbnails(id, page) {}                      // اختياري: صور مصغرة للمعاينة بالصفحات
async videos(id, episodeId = '_') {}               // فيديو
async textChapter(id, chapterId) {}                // روايات
async gameResources(workId) {}                     // ألعاب
async resolveGameResource(workId, resourceId, channelId) {}
```

### القوائم: `feed` / `search`

```js
{
  items: [WorkItem], page: 1, totalPages: 20, total: 500,
  hasNext: true,
  cursor: '12345',        // اختياري: تعيد المواقع ذات المؤشرات المؤشر التالي ويعيده التطبيق كما هو
}
// أو أقسامًا تُعرض في كتل:
{ sections: [{ title: '连载更新', items: [WorkItem] }], hasNext: false }
```

**WorkItem**: `{ id, title, subtitle?, cover, coverBlurred?, coverAspect?, pages?, rating?, likes?, views?, language?, category?, badge?, badgeColor?, duration?, uploaded?, tags?, mediaKind?, workCode?, editions?, commentsAvailable? }`

- `workCode` هو رمز عمل مؤكّد من المصدر، ويُستخدم فقط للعثور على العمل نفسه. لا يحل محل `id` ولا يدمج هوية الأعمال أو المفضلة أو التقدم أو التنزيلات.
- `editions` يحتوي على تسميات إصدارات ثابتة يذكرها المصدر صراحة، مثل الترجمة الصينية أو نسخة مسرّبة غير خاضعة للرقابة. غياب التسمية لا يعني الإصدار الأصلي. عرض الترجمة لا يغيّر التسميات الأصلية.

- يتيح `coverAspect` (العرض / الارتفاع) ترتيب الشبكة قبل تحميل الصور.
- يلوّن `badgeColor` شارة الفئة.
- `mediaKind: 'comic' | 'video' | 'novel' | 'game'` هو نوع العمل نفسه. يمكن للإضافات ذات النوع الواحد حذفه، أما المختلطة فيجب أن تحدده — لا تعامل الصور كفيديو لمجرد `type` الإضافة. تحدده أعمال الروايات والألعاب دائمًا، كي تفتح الأعمال غير المتصلة والسجل في القارئ الصحيح حتى بعد إلغاء تثبيت الإضافة.
- يمكن أن تحمل نتائج المنشورات `presentation: 'post'` و`text` و`date` و`url` ومصفوفة `media` فتُعرض كبطاقات منشورات؛ ويعرض `presentation: 'media'` شبكة وسائط تفتح الوسائط داخل العمل. قد لا يحتوي المنشور على وسائط، وتخضع عناوين الوسائط للنطاقات والأذونات المعلنة.

### التفاصيل: `detail`

كل حقول WorkItem، إضافةً إلى:

```js
{
  url, authors: [], description, uploader?, size?, comments?, commentsAvailable?,
  tags: [{ namespace: 'artist', label: '作者', tags: [{ name, keyword, filters?, count? }] }],
  chapters: [{ id, title }] | null,   // null يعني فصلًا واحدًا
  singleChapterId?,                   // معرّف الفصل الذي تحتاجه الأعمال ذات الفصل الواحد
  thumbnails?: [url | { url, width, height, offsetX, offsetY }],   // تدعم الصور المجمّعة
  related?: [WorkItem], series?: [WorkItem], variants?: [WorkItem],
}
```

- `variants` يحتوي فقط على روابط فعلية يقدّمها المصدر لإصدارات العمل نفسه في المصدر نفسه، مع `id` مستقل لكل إصدار؛ لا يجوز تخمين عناوين URL. تُبحث إصدارات المصادر الأخرى عبر `workCode` وتبقى المفضلة والتقدم والتنزيلات مستقلة.

- يبحث النقر على وسم في هذا الموقع باستخدام `keyword` و`filters`، فيمكن ربط الوسوم بصيغة الموقع الخاصة (مثل `artist:"xxx"`) أو بمعاملات التصفية.
- الوسيط الثاني الاختياري `preview` يحمل بيانات وصفية عامة معروضة أو محفوظة، ولا يُمرَّر إلا حين يطابق `preview.source` و`preview.id` الطلب. على الإضافة مع ذلك فحص المعرّف والتحقق من الروابط. الأعمال المفتوحة بمعرّف مكتوب لا معاينة لها، فقد يكون العنوان والغلاف ناقصين.

### الفصول: `chapter` / `resolveImage` / `thumbnails`

```js
{ pages: [
  { url, headers?, fallbacks?: [url], width?, height?, transform? },  // عنوان معروف
  { token: '12' },                                                      // مؤجل: يستدعي التطبيق resolveImage
]}
```

- `fallbacks`: مرايا تُجرَّب بالترتيب إذا فشل العنوان الرئيسي.
- `transform: { type: 'unscramble-strips', segments: N }`: للصور المقطّعة إلى N شرائط محفوظة بترتيب معكوس، وتُستعاد على GPU. تحفظ الملفات غير المتصلة الصورة الأصلية وتُستعاد عند العرض.
- تعيد `resolveImage` القيمة `{ url, headers?, width?, height?, cacheKey? }`. عند الفشل يستدعيها التطبيق مجددًا بقيمة `retry` أكبر، فتستطيع الإضافة تبديل الخادم.
- تعيد `thumbnails(id, page)` القيمة `{ thumbnails: [...], hasNext }`.

### الفيديو: `videos`

تعيد `[{ quality: 1080, label: '1080P', url, headers?, format?, preferred?, hls? }]`. تنتهي الروابط المباشرة عادةً، لذا يطلبها التطبيق من جديد قبل كل تشغيل أو تنزيل.

- يمكن أن يتضمن `format: 'hls'` الحقل `hls: {manifest, keys}`: يمثل `url` عنوان HTTPS الأساسي الحقيقي للقائمة الفرعية، و`manifest` قائمة وسائط VOD كاملة ومجهزة (بحد أقصى 2 MiB بترميز UTF-8)، ويربط `keys` عناوين المفاتيح المطلقة المشار إليها بمفاتيح من 16 بايت بترميز Base64، بحد أقصى 32 مفتاحًا. للوسائط الأصلية فقط، مع بقاء تفويض العناوين والتحقق من المحتوى ورفض المفاتيح غير المشار إليها. لا تُخزّن النتائج التي تتضمن هذا الحقل على القرص؛ تبقى المفاتيح في ذاكرة الجلسة ولا تدخل store أو السجلات أو الأعمال أو المؤشرات.

- تعيد الفيديوهات متعددة الحلقات `[{ id, title }]` بترتيب التشغيل في `detail(id).chapters`؛ ويجب أن يكون كل `id` ثابتًا، لا جودة ولا رابطًا مؤقتًا. يستخدم التطبيق المعرّف نفسه لاختيار الحلقات وحفظ التقدم والتنزيل والاستئناف، ويستدعي `videos(id, episodeId)` لكل حلقة. تستخدم الفيديوهات المنفردة `singleChapterId`، أو `'_'` عند غيابه.
- دون `format` يُعامل الرابط كملف MP4 مباشر في التشغيل والتنزيل. يجب أن يعيد HLS القيمة `format: 'hls'` ويعلن إذن `media`.
- يوسّع التطبيق قائمة HLS الرئيسية (`#EXT-X-STREAM-INF`) إلى قوائم لكل متغير ويأخذ الجودة الحقيقية من `RESOLUTION`. عند إعادة قائمة رئيسية تكون `quality` هي الجودة المرغوبة: تُختار أعلى جودة حقيقية لا تتجاوزها، وإلا فالأعلى. يجب أن يكون كل متغير MPEG-TS أو fMP4 للفيديو حسب الطلب مدمج الصوت والصورة؛ وتُرفض مسارات `AUDIO` و`VIDEO` و`SUBTITLES` المنفصلة والعناوين خارج `media.domains`. تُتجاهل مسارات `#EXT-X-I-FRAME-STREAM-INF`. إذا لم تُعرف دقة قائمة منفردة فاستخدم `label: '原画'` بدل عرض الجودة المرغوبة كأنها حقيقية. عند غياب `RESOLUTION` يلزم `BANDWIDTH` صالح؛ تُعرض الخيارات بوحدة kbps ويُختار الأعلى افتراضياً دون اختلاق دقة.
- يشير `type: 'video', category: 'live'` إلى بث عام ضمن المحتوى ثلاثي الأبعاد ببطاقات صور فقط. تُرجع `videos()` رابط HLS للغرفة العامة الحالية؛ لا تُرجع نتائج تشغيل وهمية للغرف الخاصة أو المدفوعة أو غير المتصلة. تُستخدم قوائم متجددة دون حفظ تقدم الفيديو أو تنزيله. يبدأ التسجيل بإجراء صريح ويحفظ المقاطع الأحدث من النافذة الأولية فقط. ينتهي بالإيقاف أو الخروج ولا يُستأنف بعد إعادة التشغيل. تتحقق جلسة وسائط مستقلة ومهمة خلفية من المقاطع وتفك تشفيرها وتحفظ قائمة محلية مكتملة. يُحل عنوان الوسائط مجدداً عند إعادة الاتصال، وقد تنشئ حدود الترميز والتسجيلات الطويلة أجزاء جديدة. تبقى البيانات المحفوظة عند الفشل. يُدعم MPEG-TS المدمج فقط؛ لا تُدعم MAP/fMP4 أو PART أو BYTERANGE أو GAP.
- يتطلب VOD قائمة MPEG-TS أو fMP4 كاملة ومتصلة مع `#EXT-X-ENDLIST`. يدعم fMP4 مقطع تهيئة واحداً `#EXT-X-MAP` قبل مقاطع الوسائط، دون تبديل التهيئة أو نطاقات البايت. تخضع التهيئة والوسائط لترخيص العناوين والتحقق وإعادة الكتابة محلياً؛ وتُحفظ التهيئة عند التشغيل دون اتصال والتصدير. يبقى البث مقصوراً على MPEG-TS مع القوائم المتجددة وdiscontinuity. يدعم كلاهما `METHOD=AES-128` و`KEYFORMAT=identity` بنمط CBC/PKCS7 ومفتاح 16 بايت. يُحدد IV للوسائط صراحة أو من التسلسل، وتتطلب التهيئة المشفرة IV صريحاً. تبقى المفاتيح في ذاكرة الجلسة. لا تُدعم SAMPLE-AES أو KEYFORMAT الأخرى أو BYTERANGE أو GAP؛ ويرفض VOD أيضاً discontinuity. تُزال `#EXT-X-TOKEN`.
- تدعم قوائم HLS ومقاطع MPEG-TS تغليف PNG `roUd` (خام أو مضغوط باستخدام zlib). يُفك التغليف قبل التحليل والتحقق أو فك التشفير، مع حدود بعد الفك تبلغ 2 MiB للقائمة و32 MiB للمقطع. تستمر الإضافات بإرجاع `format: 'hls'` دون أذونات إضافية.
- يستخدم التشغيل منفذًا عشوائيًا مربوطًا بـ `127.0.0.1` ورمزًا عشوائيًا، ويقدّم المقاطع المُتحقَّق منها عند الطلب من سجل محدود للروابط، ويلغي إغلاق الجلسة الطلبات. تنزيل HLS دون اتصال على Android فقط حاليًا: يُتحقق من كل مقطع ويُحفظ SHA-256 له، ويمكن الاستئناف والإلغاء، ثم يجمع Media3 ملف MP4 في النهاية — ولا تصل إلى المكتبة غير المتصلة إلا الملفات الكاملة. يحفظ fMP4 التهيئة والوسائط بالترتيب دون تحويل TS عبر Media3.

### الروايات: `textChapter`

تعلن إضافات الروايات `type: 'novel', category: 'novel'`، وتنفيذ `textChapter` يُخرج `capabilities.textChapter: true`. تحدد القوائم والتفاصيل `mediaKind: 'novel'` و`language: 'zh'` أو `'en'`. بلا غلاف حقيقي أعد `cover: ''` فيعرض التطبيق غلافًا نصيًا بدل طلب صورة وهمية.

```js
async textChapter(id, chapterId) {
  // النص الكامل للفصل؛ يجب أن تكون paragraphs مصفوفة سلاسل غير فارغة بلا HTML.
  return { title: '章节标题', paragraphs: ['第一段正文。', '第二段正文。'] };
}
```

- تعيد الروايات متعددة الفصول معرّفات ثابتة بترتيب القراءة المؤكد من الموقع في `detail.chapters`، وتستخدم القصص المنفردة `chapters: null` و`singleChapterId` اختياريًا.
- تدمج الإضافة تقسيم الفصل إلى صفحات بالترتيب، ولا تضم إلى النص الفصل التالي أو ردود المنتدى أو الإعلانات أو التوصيات. يستخرج `Park.html.paragraphs(node)` النص الخام بشكل عام، وتظل حدود الموقع وتقسيمه مسؤولية الإضافة.
- إذا اقتُطع النص بسبب تسجيل الدخول أو الدفع أو الأذونات فأطلق `LOGIN_REQUIRED`؛ ولا تقدّم المعاينة على أنها فصل كامل.
- يكتب التطبيق `text.json` لكل فصل بشكل ذري، ولا يُعدّ التنزيل مكتملًا إلا بالكتابة الكاملة. يستخدم التقدم والملاحظات مواضع UTF-16 في `paragraphs.join('\n\n')`، ولا تؤثر إعدادات الحجم والخط والمسافة البادئة إلا في العرض. تُحفظ الإشارات والملاحظات منفصلة عن التنزيلات، وتدخل في النسخ الاحتياطية، وتبقى بعد حذف التنزيل.

### الألعاب: `gameResources` / `resolveGameResource`

تعلن إضافات الألعاب `type: 'game', category: 'game'`، وتحدد أعمالها `mediaKind: 'game'` دون `chapters` وهمية. تُخرج البيئة `capabilities.gameResources` و`capabilities.resolveGameResource` من الدوال.

```js
async gameResources(workId) {
  return [{ id: 'resource-id', title: '', version: '1.2', size: '2 GB',
    platforms: ['Windows'], languages: ['SimplifiedChinese'], notes: '原站备注',
    status: 'valid', testStatus: 'untested',
    channels: [{ id: 'stable-channel-id', kind: 'direct', label: 'game.zip', size: '2 GB' }] }];
}
async resolveGameResource(workId, resourceId, channelId) {
  return { kind: 'direct', url: 'https://files.example/game.zip?temporary-signature',
    filename: 'game.zip', extractionCode: '', archivePassword: '' };
  // تعيد الأقراص السحابية kind: 'external' وurls: [كل المرايا والأجزاء] وurl: urls[0].
}
```

- لا تعيد `gameResources` إلا معرّفات ثابتة وبيانات وصفية وقنوات — بلا روابط موقّعة أو كلمات مرور أو حالات تنزيل وهمية. `testStatus` هو `tested | untested | unknown` منقولًا من الموقع؛ وتُعطَّل القنوات ذات `status: 'expired'`.
- لا تُستدعى `resolveGameResource` إلا عند نقر المستخدم أو إعادة المحاولة، ولا يُحفظ رابطها ولا يُسجَّل. يمكن حفظ كلمات المرور مع مهمة التنزيل المحلية لكن ليس في التشخيص. لا تُسقط روابط الأقراص السحابية؛ وعند إعادة عدة روابط يمكن أن تطابق `extractionCodes` الروابط `urls` واحدًا لواحد (السلسلة الفارغة تعني بلا رمز)، و`extractionCode` لرمز مشترك.
- تعلن القنوات التي تتطلب ردًا `requiresReply: true, replyText: 'نص الرد الفعلي'`، فيعرض التطبيق «الرد لفتح الروابط» والنص بالضبط، ولا يستدعي إلا بعد تأكيد المستخدم. قبل الحل يجب على الإضافة إعادة فحص المشاركة الأولى: إن كانت مفتوحة فتقرأ فقط، وترسل مرة واحدة وعند نقر المستخدم فقط بعد حفظ حالة الحساب والموضوع بشكل موثوق. إذا كانت النتيجة غير واضحة أو تكررت المحاولة أو لزم تحقق ديناميكي فأعد `CONFIRM_REQUIRED` مع رابط الموضوع ولا تُعِد الإرسال تلقائيًا أبدًا؛ ولا ترد أبدًا من القوائم أو التفاصيل أو التحميل المسبق أو التحديثات في الخلفية.
- تعلن الروابط المباشرة `media: { mode: 'native', origin, domains }`. تُنزَّل الملفات بالبث عبر عميل مستقل بلا ملفات ارتباط، ويتولى الإطار HTTPS وفحص النطاق في كل انتقال وفحص الطول والتنظيف عند الإلغاء وحماية الملفات المكتملة. لا يوجد استئناف؛ وإعادة المحاولة تحل العنوان من جديد وتبدأ من الصفر. تُفتح الأقراص السحابية في تطبيقات خارجية، مقتصرة على HTTP(S) وFTP(S) وmagnet وed2k وthunder، دون ملفات ارتباط الموقع. لا تنشئ الألعاب فصولًا أو تقدم قراءة أو تحديثات فصول، ولا يثبّت التطبيق الملفات أو يفك ضغطها أو يشغّلها أبدًا.

### الاشتراكات: `subscription`

تعلن إضافات الاشتراك (متابعة القنوات أو المبدعين) كائن `subscription`؛ وتُخرج البيئة `capabilities.subscription` عند وجود `normalize` و`posts` معًا، فيظهر الموقع في «استكشاف ← الاشتراكات». وتظهر الإضافات التي تعلن `feeds` أيضًا في الفئات العادية.

```js
subscription: {
  hint: '无需登录即可保存订阅；媒体访问取决于原站权限。',
  normalize(input) { return { id: validatedTarget, label: displayName }; },
  async resolve(input) { return { id: validatedTarget, label: displayName }; },
  async targets() { return [{ id: joinedChannelId, label: channelName }]; },
  async posts(target, { cursor }) {
    return { items: [{ id, title, text, date, url, locked, commentsAvailable,
      media: [{ type: 'image', url, preview, previewOnly: false },
              { type: 'video', url, preview, format: 'mp4', headers: {} }] }],
      cursor: nextCursor, hasNext: true };
  },
  async mediaChunk(resource, offset) { return { base64, done }; }, // اختياري
}
```

- يتحقق `normalize` محليًا فقط، كي يمكن حفظ الأهداف دون تسجيل دخول أو اتصال؛ ولا يقبل إلا أسماء المستخدمين أو روابط الملفات الشخصية الخاضعة للموقع نفسه. `resolve` و`targets` اختياريتان، ومع `targets` يُخرج manifest القيمة `subscription.joinedTargets: true`.
- لإدخال مستقل للمجتمعات، أعلن `communities: true` و`communityHint` و`communityExample`؛ يصدّرها وقت التشغيل كما هي. تعيد الأهداف `{ id, label, kind: 'community' }` بمعرّفات تختلف عن أهداف المؤلفين. يسرد `targets({ kind: 'community' })` المجتمعات المنضم إليها و`targets()` الأهداف الافتراضية. افصل المعالجة كي لا يعطّل فشل المجتمعات قائمة المؤلفين. يتحقق `resolve` من الاسم والصلاحية للقراءة فقط، دون انضمام تلقائي.
- مؤشرات `posts` سلاسل معتمة؛ للصفحة الأخيرة `hasNext: false`، ويمكن للصفحات الخالية من الوسائط المتابعة. يعني `locked` نقص الأذونات، ويشير `previewOnly` إلى معاينات عامة — لا تقدّم صورة مصغرة على أنها المحتوى الكامل.

### الألبومات العامة: `subscription.media`

الألبوم قدرة مستقلة، لا يُجمع من المنشورات المحمّلة ولا يعود إلى `subscription.posts`. نفّذ `subscription.media(scope, { page, cursor })`؛ ويمكن لمصدر ذي feed عام بلا أهداف اشتراك إعلان هذه الدالة وحدها ضمن `subscription`. يصدّر وقت التشغيل `capabilities.album` منفصلًا عن `capabilities.subscription`.

يكون `scope` إما `{ feed, options }` أو `{ target }`: موجز بمرشحاته أو مستخدم أو مجتمع أو قناة أو مجموعة. يتولى المصدر تحديد الأهداف وتصفحها دون شروط بأسماء المواقع في الواجهة. النتيجة `{ items, cursor, hasNext }`؛ قد تتابع صفحة بلا وسائط مطابقة، ويجب أن يتقدم كل مؤشر متابعة. تكرار المؤشر خطأ.

لكل عنصر `id` نصي ثابت و`presentation: 'post' | 'work'` وتاريخ ISO 8601 قابل للتحليل إن عُرف ومصفوفة `media` كاملة بترتيب الموقع. لكل مرفق `id` نصي فريد ثابت و`type: 'image' | 'video'` و`url` للمحتوى الفعلي أو `resource` خاضع للتحكم. `preview` صورة مصغرة؛ ويمكن استخدام `previewResource` بالتنسيق المضبوط أدناه لصورة مستقلة لا تتجاوز 2 MiB. لا تستبدل المصغرة بغلاف أو رابط فيديو. يعيد المحتوى المقيد معاينة عامة فقط مع `previewOnly: true` وطمس الموقع الأصلي، و`locked: true` إن كان المنشور كله مقفلًا.

يكمل المصدر المرفقات عبر الصفحات ويدمج مجموعات الموقع. يدمج العميل الأعمال المتكررة حسب `id` المرفق؛ ولا يرتب بواسطة `order` الرقمي المحدود إلا إذا وُفر لكل مرفقات العمل. يشمل مرشح التاريخ طرفي النطاق بالتوقيت المحلي ويستبعد التاريخ المجهول عند تحديد نطاق. لا يغيّر ترشيح الصور والفيديو أو طي المنشور هويته. بعد عدد محدود من الصفحات الخالية من النتائج يمكن المتابعة يدويًا. يفتح `presentation: 'work'` تفاصيل العمل و`'post'` المنشور كاملًا. تستخدم أغلفة الألبوم الصور أو المصغرات الصريحة فقط، ولا تستخدم روابط تشغيل الفيديو.

- يحافظ `coverBlurred: true` و`blurred: true` للوسائط على ضبابية أغلفة الموقع وصوره في المصغرات والعرض الكامل. لا تعرض الصور المقيدة كمحتوى كامل واضح. تُحل قوائم HLS الرئيسية للمعاينات والفيديو الكامل قبل تشغيل نسخة VOD المختارة.
- تستخدم المرفقات المصرَّح بها التي لا رابط مباشرًا لها `media[].resource` وتنفّذ `mediaChunk(resource, offset)`: 128 KiB كحد أقصى في كل استدعاء، والإزاحات مضاعفات 128 KiB؛ ويجب أن يحتوي resource على `size` صحيح وسلسلة `cacheKey` ثابتة غير سرية لا تتغير مع بيانات الاعتماد أو المراجع المؤقتة. يتحقق الإطار من الحجم الكلي ومن كل جزء ويكتب ذريًا في مساره المؤقت الخاص؛ يصل المرفق إلى 512 MiB ولا يختار resource المسار المحلي. لا تُحفظ الروابط الموقّعة ولا resource في سجلات الاشتراك.
- يجب توضيح أي متابعة أو انضمام على الموقع الأصلي وطلب تأكيد المستخدم قبل حفظ الاشتراك. يجب إحالة عمليات الكتابة غير المتحققة إلى الموقع الأصلي؛ لا تتابع أو تنضم أو تدفع بصمت.

### اشتراكات التحديث: `updateSubscriptions`

يمكن للإضافات العادية دعم «متابعة التحديثات» بكائن `updateSubscriptions` مستقل. لا تُخرج البيئة `capabilities.subscriptionUpdates` إلا بوجود `check`، ولا يتغير بذلك تصنيف العمل ولا `capabilities.subscription`. تتضمن البيانات الوصفية `dimensions: [{ key, label, hint }]`، ويمكن لقوائم الوسوم تمرير الكلمة الأصلية ومعاملات التصفية.

- تعيد `normalize(dimension, input)` القيمة `{ id, label }`، وتعيد `check({ dimension, target }, { cursor })` القيمة `{ items, hasNext, cursor }`. العناصر هي `{ id, title, kind, workId, chapterId }` و`kind` مقتصر على `work | post | chapter`، بمعرّفات ثابتة غير فارغة دون روابط وسائط أو ملفات ارتباط أو بيانات اعتماد. تتضمن معرّفات الفصول هوية العمل كي لا يتصادم «الفصل 1» لأعمال مختلفة.
- يوفّر `Park.enableUpdateSubscriptions(Park.__pending, rules)` محوّلًا عامًا؛ أعلن الأبعاد صراحةً في نهاية النص مع `searchFilters` و`seriesPattern` اختياريًا. يستخدم `work` قائمة الفصول الحقيقية، و`posts` واجهة القنوات الحالية، و`search` و`filter` البحث، ويطابق `code` الرموز الكاملة تمامًا، ويستخدم `series` مسارات سلاسل مُتحقَّقًا منها مقابل نطاقات الموقع. تحفظ مؤشرات البحث رقم الصفحة ومؤشر الموقع معًا.
- ينشئ `windowed: true` خط أساس من ثلاث صفحات عند الفحص الأول. بعد ذلك تُفحص ثلاث صفحات كحد أقصى في كل دفعة مع حفظ المؤشر والعناصر حتى صفحة معروفة بالكامل أو نهاية النتائج، ثم تُحفظ الأحداث الجديدة. لا تُقتطع قائمة الفصول؛ تجاوز 20,000 عنصر أو فشل التحليل ينتج خطأ.
- يعيد `query({ dimension, target })` القيمة `{ keyword, filters }` المشتركة بين تصفح الاشتراك وفحصه. تدعم الألبومات أيضاً `{ search: { keyword, filters } }` وتحافظ على البحث أثناء التنقل. تدعم فيديوهات المنشورات مرفقات `resource` وتتابع ضمن البحث نفسه.
- تتشارك الواجهة والخلفية بيئة الإضافة وأقسام ملفات الارتباط وقيود النطاقات وآلية الفحص. لا تبدأ الخلفية إلا الإضافات المعنية، ولا تسجّل الدخول ولا تشترك في الموقع ولا تنزّل الوسائط ولا تتجاوز الأذونات. يعيد تغيير الحساب أو إعدادات الإضافة بناء خط الأساس (تجديد الرمز لا يفعل).

## واجهة بيئة التشغيل

داخل الدوال يوفّر `this`:

| العضو | الوصف |
| --- | --- |
| `this.http` | `request(opts)` و`get(url, opts)` و`post(url, opts)` و`text(url, opts)` و`json(url, opts)` |
| `this.config` | القيم التي اختارها المستخدم في إعدادات الموقع (`default` عند عدم الضبط) |
| `this.store` | مخزن دائم للمفاتيح والقيم: `get(key, fallback)` / `set(key, value)` للرموز وقوائم النطاقات وغيرها؛ و`await flush()` يؤكد الكتابة ويطلق خطأ عند الفشل |
| `this.cookies` | `get(url)` / `set(url, { name: value })` / `clear(url)` |
| `this.log({ code, host, transport, reason })` | يكتب هذه الحقول المسموح بها فقط؛ ويُسقط النص الحر كي لا تتسرب بيانات الاعتماد والعناوين |

الأدوات العامة:

| الأداة | الوصف |
| --- | --- |
| `Park.html.parse(text)` | يعيد `Document` قياسيًا لاستخدام `querySelector` |
| `Park.html.text(node)` / `unescape(s)` / `strip(html)` / `paragraphs(node)` | معالجة النصوص |
| `Park.crypto.md5Hex(text \| text[])` | MD5، ويقبل المصفوفات |
| `Park.crypto.sha256Hex` / `hmacSha256Hex(key, text)` / `aesEcbDecrypt(base64, key)` / `uuid()` | تنفيذات أصلية |
| `Park.crypto.digestBytes('sha1' \| 'sha256', bytes)` | مصفوفات أعداد صحيحة 0–255 حتى 2 MiB |
| `Park.crypto.randomBytes(length)` | بايتات عشوائية آمنة، length من 1 إلى 65536 |
| `Park.url.parse(value, base, domains)` / `site(source, value, base?)` / `response(source, response, requested)` | يحلل عناوين HTTPS 443 ضمن النطاقات المصرح بها وفروعها، ويرفض بيانات الاعتماد ويحذف الأجزاء؛ يعيد `null` عند الفشل. يستخدم `site` نطاقات `domains` للمصدر؛ يفحص `response` العنوان النهائي من دون تعديل قاعدة المصدر المشتركة، أو يرفع `BLOCKED`. يتحقق الملحق من المسار والصفحة والعمل والبحث؛ تجنب قوائم مفاتيح الاستعلام وأسماء عقد CDN المغلقة. |
| `Park.utils.rateLimiter(ms)` | يعيد `wait()` ويضمن فاصلًا أدنى بين الطلبات |
| `Park.utils.mapLimit(items, n, fn)` / `lruMap(n)` / `parseCount('1.2万')` / `formatDate(ts)` | أدوات أخرى |
| `Park.error(code, message, extra?)` | ينشئ خطأ برمز، راجع «رموز الأخطاء» |

تستقبل `Park.crypto.aesGcmDecrypt(ciphertext, key, iv)` نصًا مشفرًا سداسيًا (مع وسم المصادقة النهائي من 16 بايت، بحد أقصى 4096 بايت) ومفتاحًا من 16/24/32 بايت وIV من 12 بايت، وتعيد بايتات النص الواضح. يؤدي فشل المصادقة إلى خطأ دون إعادة نص غير موثّق.

### `http.request(opts)`

```js
await this.http.request({
  url, method: 'GET', headers: {}, params: { q: 'x' },   // تُضاف params إلى الرابط
  json: {...} | form: {...} | body: 'raw' | bodyBase64: '...',
  timeout: 15000,
  responseType: 'text' | 'base64',
});
// → { status, headers, body, url, ok, json() }
```

- تطلق `text()` / `json()` خطأ عند الاستجابات خارج 2xx (404 ← `NOT_FOUND`). تُحفظ ملفات الارتباط تلقائيًا ويُعاد اختيارها لكل وجهة إعادة توجيه.
- `bodyBase64` جسم ثنائي (حتى 2 MiB) لا يُجمع مع `body` أو وضع المتصفح، ويتبع قواعد عزل النطاقات وTLS وإعادة التوجيه نفسها الخاصة بالطلبات النصية. لا تستطيع الإضافات فتح شبكة المتصفح أو WebSocket أو وصول عشوائي إلى الملفات بنفسها.

## رموز الأخطاء

أطلق الخطأ بـ `throw Park.error(code, message, extra)`، فيتصرف التطبيق حسب الرمز:

| code | ما يفعله التطبيق |
| --- | --- |
| `CLOUDFLARE` | «التحقق»: يفتح المتصفح المدمج |
| `CONFIRM_REQUIRED` | «تأكيد»: ينتظر حتى يُكمل المستخدم تأكيد الوصول المعلن (يشير إليه `extra.url`) |
| `LOGIN_REQUIRED` | «تسجيل الدخول»: يفتح قسم الحساب في إعدادات الموقع |
| `NOT_FOUND` | يعرض «المحتوى غير موجود» |
| `BLOCKED` | يعرض «الوصول مقيّد» (حظر IP أو نفاد الحصة…) ولا يعيد محاولة الصور |
| `NETWORK` | يعرض «تعذّر الاتصال» مع السبب و«إعادة المحاولة» |
| `HTTP` / `PARSE` / `UNSUPPORTED` / `CONFIG` | يعرض رسالة الإضافة و«إعادة المحاولة» |

### الرسائل المنظَّمة

`message` **قالب بالصينية** وهو أيضًا مفتاح الترجمة؛ ضع الأجزاء المتغيرة في `extra.params` بدل ربطها بالنص:

```js
throw Park.error('HTTP', '站点返回 HTTP {status}', { params: { status: res.status }, status: res.status });
throw Park.error('NOT_FOUND', '影片不存在');
```

يترجم التطبيق القالب أولًا بـ `i18n` الخاص بالإضافة ثم بالمفردات المشتركة للتطبيق، ويملأ العناصر النائبة من `params`. لا يمكن ترجمة النص المربوط، فسيراه المستخدمون الذين لا يقرؤون الصينية بالصينية. تعمل `status` و`url` و`diagnostics` في `extra` كما كانت.

### التخزين المؤقت للصفحة الرئيسية ودلالة الأخطاء

- تحتفظ نتائج `feed` المباشرة بكل الحقول. تخزن ذاكرة القرص الخاصة بالتطبيق والقابلة لإعادة البناء بيانات الأعمال المسموحة ونص المنشورات وبيانات الوصول للمرفقات وحقول التفاصيل المدعومة، لفتح العناصر قبل التحديث. قد تحتوي روابط وسائط مؤقتة ومراجع موارد؛ تتطلب الروابط المنتهية تحديثًا. لا تحل محل التنزيل أو النسخ الاحتياطي. تفصل هوية الذاكرة الموقع والحساب والإعدادات ونطاق الطلب. لا تضع بيانات اعتماد الحساب في المحتوى المعاد أو المعرّفات أو المؤشرات، ولا تنسخ بيانات الوصول المخزنة إلى التشخيص أو سجلات الاشتراك.
- لا يُعرض التخزين المؤقت القديم كمحتوى غير متصل إلا عند أخطاء `NETWORK` / `TIMEOUT` الصريحة، ويُوسَم بأنه مخزَّن. يجب أن تطلق أعطال الدخول والتأكيد والتحقق البشري والتحليل والإعداد أخطاءها الخاصة؛ ولا يقدّمها الإطار كأعطال شبكة أبدًا، ويعرض التحديث الذي يبدؤه المستخدم الخطأ الحقيقي أيضًا.

## تعدد اللغات

تدعم واجهة التطبيق `zh-Hans` و`zh-Hant` و`ja` و`ko` و`en` و`es` و`ru` و`ar` (العربية من اليمين إلى اليسار). اكتب كل نص ثابت ظاهر للمستخدم في الإضافة (الاسم والوصف وأسماء التبويبات والخيارات وتلميح البحث وملاحظات الحساب ورسائل الأخطاء) **بالصينية المبسطة**؛ فالنص الأصلي هو مفتاح الترجمة.

تحمل الإضافة ترجماتها في حقل `i18n` من manifest:

```js
Park.register({
  i18n: {
    'zh-Hant': { '发行日期': '發行日期', '影片不存在': '影片不存在' },
    'en': { '发行日期': 'Release date', '影片不存在': 'Video not found', '站点返回 HTTP {status}': 'The site returned HTTP {status}' },
    // وكذلك ja وko وes وru وar
  },
  key: 'mysite',
  // …
});
```

- ترتيب البحث: `i18n` الإضافة للغة الحالية ← `en` الخاص بالإضافة (عدا الصينية المبسطة) ← المفردات المشتركة للتطبيق (`assets/i18n/`، مثل «الترتيب» و«الأحدث» و«رائج») ← النص الأصلي.
- لا يلزم في `i18n` إلا ما ليس في التطبيق أصلًا؛ وتستعمل الكلمات الشائعة ترجمات التطبيق. يجب أن تطابق العناصر النائبة `{name}` الأصل.
- لا يُترجم المحتوى البعيد (العناوين والمؤلفون والوسوم والأوصاف) ولا ما يكتبه المستخدم ولا مفاتيح البروتوكول المحفوظة كنصوص واجهة.
- تغيير `i18n` تغيير للإضافة ويتطلب رفع الإصدار. يرى مستخدمو الإصدار الأقدم النصوص القديمة حتى يحدّثوا.

تُستدعى نصوص واجهة التطبيق نفسه عبر `tr('已选 {count}', { 'count': count })` أو `context.tr`، وتوجد ملفات اللغات الثماني في `assets/i18n/`، ويجب أن تحدّث كل إضافة أو تعديل جميعها بالعناصر النائبة نفسها.

## النشر

### المستودعات

المستودع ملف `index.json` واحد على أي استضافة ثابتة. يكتب المستخدم عنوانه في «المزيد ← المواقع ← إضافة موقع» ليتصفح ويثبّت ويحدّث:

```json
{
  "name": "我的站点仓库",
  "apiVersion": 2,
  "sources": [
    {
      "key": "mysite",
      "name": "我的站点",
      "version": "0.0.1",
      "minAppVersion": "0.9.2",
      "description": "一句话介绍",
      "url": "https://example.com/sources/mysite.js",
      "sha256": "SHA-256 لنص UTF-8 للنص البرمجي بـ 64 رقمًا ست عشريًا",
      "apiVersion": 2
    }
  ]
}
```

`url` هو العنوان الكامل للنص، ويصلح أيضًا `file` نسبةً إلى `index.json`. تُثبَّت المستودعات الخارجية يدويًا بعد تأكيد المستخدم؛ و`sha256` اختياري ويُتحقق منه عند وجوده.

### الإصدارات وقواعد التحديث

- يجب أن تعلن الإضافات عن minAppVersion (مثل 0.9.2) مطابق للفهرس الرسمي. الإصدار الحالي من apiVersion هو 2 ويتطلب HentaiPark 0.9.2 أو أحدث. تتحقق التحديثات والتثبيت عبر الرابط من التوافق قبل الاستبدال؛ وتُحفظ الإضافة المثبتة عند عدم التوافق. تميز الإشعارات التلقائية بين التحديثات المتوافقة وتلك التي تتطلب تطبيقًا أحدث. يقتصر تجاهل الإصدار على إصدارات التطبيق أو الإضافات المعروضة، ويستمر بعد إعادة التشغيل ولا يؤثر على الفحص اليدوي.

- الإصدار ثلاثة أعداد صحيحة غير سالبة مفصولة بنقاط دون أصفار بادئة (مثل `0.0.1`)، تُقارَن رقميًا جزءًا جزءًا؛ وتُرفض الأجزاء الناقصة أو الزائدة ولواحق الإصدارات التجريبية.
- يجب أن تقدّم التحديثات الرسمية `sha256` لنص UTF-8 للنص البرمجي (دون قص المسافات أو تحويل نهايات الأسطر)، وأن يطابق `key` و`version` في النص الفهرس؛ ويجب أن يساوي `apiVersion` إصدار بيئة التطبيق تمامًا وإلا يُرفض التحديث.
- إصدارات الإضافات والتطبيق مستقلة. عند تعديل نص إضافة (بما فيه `i18n`) ارفع الإصدار في النص وفي `assets/sources/index.json`؛ ويرفض الناشر خفض الإصدار والإصدار نفسه بمحتوى مختلف.

### التحديثات الرسمية في التطبيق

- خيار «التحقق من تحديثات الإضافات عند التشغيل» في «المزيد ← المواقع» و«المزيد ← حول التطبيق ← التحديثات» مفعّل افتراضيًا: يقرأ كل تشغيل الفهرس الرسمي فقط، ويعلن عن الإصدارات الجديدة، ولا ينزّل ويتحقق ويثبّت إلا بعد تأكيد المستخدم. عند العودة إلى الواجهة يحترم فاصلًا مدته 12 ساعة، ويُسجَّل وقت الفحص حتى عند الفشل. مع إيقاف الفحص التلقائي يبقى الفحص اليدوي متاحًا. لا يُفحص إلا الإضافات المدمجة والرسمية المثبتة؛ ولا تُثبَّت إضافات جديدة تلقائيًا ولا يُستولى على إضافات خارجية بالمفتاح نفسه.
- يعيد التثبيت التحقق من الهوية والإصدار والمصدر والواجهة والبصمة، ولا يكتمل إلا بعد نجاح التهيئة وحفظ الحالة؛ وعند الفشل يبقى النص القديم وحالة المستخدم، ويُستعاد التثبيت المقطوع عند التشغيل التالي. لا يكتب التشغيل فوق الإضافات المثبتة بالنصوص المرفقة أبدًا؛ وإن فُقد نص بقي سجلّه وبياناته حتى يستعيده المستخدم أو يحدّثه. يعيد «استعادة الإصدار المدمج» بعد التأكيد الإصدار المضمَّن في حزمة التطبيق الحالية.
- تُفحص تحديثات التطبيق نفسه افتراضيًا أيضًا: على Android وبعد التأكيد ينزّل التطبيق ملف APK الرسمي المناسب ويتحقق من الحجم وSHA-256 واسم الحزمة والإصدار والتوقيع ثم يفتح مثبّت النظام، مع التقدم والإلغاء وإعادة المحاولة؛ وصفحة الإصدارات الرسمية هي البديل.

### نشر الإضافات الرسمية

تُدار الإضافات الرسمية في `assets/sources/index.json`. تطابق أداة `tools/publish_sources.mjs` الفهرس مع تعريفات بيئة التشغيل دون اتصال، ثم تنشئ فهرس نشر بروابط نصوص ثابتة وSHA-256. لا تسجّل الدخول ولا تستدعي طرق المواقع، ولا تحل محل التحقق بطلبات حقيقية. راجع [دليل التطوير](../../DEVELOPMENT.md) للبناء والنشر.

### الإضافات المولَّدة

التنفيذ الوحيد لإضافة Telegram هو `assets/sources/telegram_entry.mjs`، أما `assets/sources/telegram.js` فمولَّد ولا يجوز تعديله يدويًا:

```powershell
npm ci --prefix 'tools/source-runner'
node tools/build_subscription_sources.mjs
```

تستخدم [@mtproto/core 6.3.0](https://github.com/alik0211/mtproto-core) (GPL-3.0، [الترخيص](../../licenses/mtproto-core.txt)؛ وملخص الاعتماديات في [تراخيص الأطراف الثالثة](../../licenses/telegram-dependencies.txt)). يستبدل محوّل الموقع النقل والتشفير والتخزين، ولا يفعّل WebSocket الافتراضي للمكتبة ولا localStorage المتصفح ولا سجلات التصحيح.

### `webVideo(id, episodeId)`

يعالج مشغل الويب تحقق Cloudflare ضمن جلسة مؤقتة معزولة. يسمح فقط بإطار التحقق ذي المضيف المطابق تمامًا `challenges.cloudflare.com`، وليس بالتنقل الرئيسي إليه. يطبق `network.confirmation` على نطاقات المصدر المعلنة فقط دون المشغلات الخارجية. إذا لم يكتمل التحقق التلقائي تبقى الصفحة متاحة للمستخدم، ولا تستورد ملفات Cookie الخاصة بالمشغل أو تصدر. يحافظ `CONFIRM_REQUIRED` على رسالة الإضافة ويفتح صفحة تأكيد داخل التطبيق لمزامنة جلسة المصدر بعد الإكمال الصريح، دون إعادة العملية الأصلية تلقائيًا.

تُفضّل المصادر المدعومة في iXXX وTubeSafari التشغيل الأصلي مع استئناف المشاهدة والحفظ دون اتصال. تستخدم المصادر الأخرى تشغيل الويب داخل التطبيق، وقد يتطلب تأكيد الموقع ولا يدعم تنزيلات التطبيق أو الاستئناف الدقيق. يتطلب تشغيل الويب على Android إصدارًا حديثًا من Android System WebView يدعم الجلسات المعزولة.

## التعليقات وروابط المحتوى

يؤدي تنفيذ `comments` إلى تصدير `capabilities.comments` تلقائياً، ويصدّر `resolveContentLink` و`searchLink` القدرات المطابقة. أعلن عمليات القراءة المتحقق منها فقط. لا تتضمن الواجهة نشر التعليقات أو الردود أو التصويت أو الإبلاغ.

تشمل تطبيقات التعليقات الرسمية Reddit وmyfans وFansly وGalgameX وXVideos وPornhub Shorties وPicACG وSpankBang وX / Twitter وTelegram؛ ويظل نطاق القراءة خاضعًا لصلاحيات الموقع الأصلي. يتطلب X / Twitter وTelegram تسجيل الدخول، ويدعم Telegram المنشورات التي تتيح المناقشة. احتفظ بالرابط الدقيق للتعليق الأصلي للمرفقات التي لا يمكن عرضها مباشرةً.

```js
// WorkItem / WorkDetail / SubscriptionPost: { ..., commentsAvailable?: boolean }
comments(workId, {page = 1, cursor = null, parentId = null, sort = 'default', context = {}})
// context: {url?, episodeId?, board?}
// result: {items, hasNext, page?, cursor?, total?, reset?, sorts?: [{value, label}]}
// item: {id, author: {name, avatar?, url?, badges?: []}, body,
//        date?, likes?, rating?, spoiler?, parentId?, replyCount?,
//        repliesAvailable?, replies?: [item]}
// body: [{type: 'text' | 'link' | 'image' | 'quote', text?, url?}]
resolveContentLink(url) // null | {type: 'work', id} | {type: 'search', url} | {type: 'external', url}
searchLink(url, request) // WorkPage
```

- يشير الحقل الاختياري على المستوى الأعلى `commentsAvailable?: boolean` في `WorkItem` و`WorkDetail` و`SubscriptionPost` إلى إتاحة التعليقات للعمل. تُخفي القيمة المنطقية الصريحة `false` مدخل التعليقات؛ وتظل `true` مشروطة بدعم المصدر لـ `capabilities.comments`. يعني غياب القيمة أو كونها غير منطقية أن الحالة غير معروفة، فتُحدَّد الإتاحة وفق قدرة المصدر. لا يعني العدد 0 تعطيل التعليقات. إذا تبيّن أثناء القراءة أن المنشور الأصلي عطّل التعليقات، فأصدر `UNSUPPORTED` بدل إخفاء الحالة بقائمة فارغة.
- يحدد `workId` العمل داخل المصدر، ويحمل `context` الصفحة الأصلية أو الحلقة أو قائمة الترتيب. افصل التعليقات حسب العمل والحلقة.
- يجب أن يكون `id` نصاً ثابتاً وغير فارغ داخل المصدر. يمكن ترك `author.name` فارغاً دون اختلاق أسماء. يحتاج المتن إلى نص غير فارغ أو صورة صالحة، مع الاحتفاظ بالتعليقات التي تتضمن صوراً فقط. يحتفظ `date` بنص الموقع أو وقت ISO. تكون `likes` و`replyCount` غير سالبتين، و`rating` بين 0 و5، ويشير `spoiler` إلى حرق الأحداث.
- تستخدم `replies` البنية نفسها ويحدد `parentId` التعليق الأب. يجب ألا يتضمن متن الأب نص الردود. يمثّل `replyCount` عدد الردود في الموقع. اضبط `repliesAvailable: true` فقط بعد التحقق من القراءة باستخدام `parentId`؛ القيمة الافتراضية false والعدد وحده لا يتيح التحميل. إذا لم يوفّر الموقع عددًا، يمكن الجمع بين `replyCount: 0` و`repliesAvailable: true`. تظل الواجهة تعرض خيار عرض الردود دون اختلاق عدد أو منع الوصول بسبب عدد الردود المحمّلة. عند قراءة الردود المتداخلة تكون قيمة `parentId` في الطلب هي `id` للتعليق المختار.
- تُشتق `hasNext` من استجابة الموقع الفعلية. لا تحتوي المؤشرات على بيانات اعتماد وتُعاد كما هي في الطلب التالي. توقف عند تكرار المعرّفات أو بلوغ العدد الإجمالي أو إعلان النهاية، واستخدم false للتصفح غير المتحقق منه. تعرض `sorts` الترتيبات المتحقق منها فقط، وتستخدم `label` مفاتيح ترجمة الواجهة.
- عند تغير لقطة الصفحات، أعد `reset: true` مع `page` الفعلية التي أُعيد تحميلها، عادةً 1، ومؤشر جديد لاستبدال القائمة. لا تعرض الصفحة الأولى على أنها صفحة لاحقة. أبلغ عن أخطاء الخدمة أو طلب تسجيل الدخول أو أخطاء التحليل بدلاً من إخفائها بقائمة فارغة.

تحوّل `Park.comments.html(html, baseUrl)` محتوى HTML إلى أجزاء آمنة تحتفظ بالنص والأسطر والروابط والصور والاقتباسات وتزيل المحتوى القابل للتنفيذ. تفصل `Park.comments.text(text)` عناوين HTTP(S) الصريحة من النص. تعيد `Park.comments.url(value, baseUrl)` عنوان HTTP(S) صالحاً أو null. يجب ألا تحتوي عناوين الصور الشخصية والملفات الشخصية والمتن على userinfo. يعرض الإطار بيانات منظّمة ولا ينفّذ HTML الموقع. تتولى الإضافة تحليل حقول الموقع وتستخدم `this.http` للطلبات.

يتعرف `resolveContentLink` على المضيف الدقيق والمسارات والمعاملات المتحقق منها ويعيد null للأهداف الأخرى. استخدم `type: 'work'` للأعمال و`type: 'search'` لبحث الموقع، ويمكن استخدام `type: 'external'` للصفحات الآمنة الأخرى. لا تخلط بين الأعمال والملفات الشخصية أو روابط التعليقات أو التواريخ أو أرقام التعليقات أو أوقات التشغيل. يتلقى `searchLink` عنوان الموقع الأصلي كاملاً ويعيد WorkPage مع الحفاظ على الكلمات والفلاتر والتصنيفات والصفحات. لا تستخرج الكلمات وحدها مع إسقاط المعاملات الأخرى، ولا تصل إلى نقاط كتابة البيانات. تبقى إمكانية فتح الصفحة الأصلية متاحة للروابط غير المعروفة.

## دردشة البث للقراءة فقط

لا تُعلن `capabilities.liveChat` إلا عند تنفيذ `liveChat(id)` و`liveChatEvent(state, event)` معًا. يشمل الدعم الرسمي CAM4 وXLoveCam وStripchat وSOOP. تمثل `chat.domains` قائمة مستقلة بالمضيفين والمنافذ ولا ترث صلاحيات الصفحات أو الصور أو الوسائط. يسمح `host` بالمنفذ 443 فقط. يجب التصريح بالمنافذ غير القياسية بصيغة `host:port` ضمن 1024–65535. تطابق `*.host:port` مستوى واحدًا فقط من النطاقات الفرعية على ذلك المنفذ، ولا تطابق المضيف الأساسي أو المستويات الأعمق أو المنافذ الأخرى. يُسمح فقط بـ HTTPS/SSE وWSS دون نقل غير مشفّر أو معلومات مستخدم أو أجزاء عنوان. لا يجوز إعادة توجيه رموز تهيئة الضيف المؤقتة إلى مضيف أو منفذ آخر.

تعيد `liveChat` الحقول `transport: "sse" | "websocket"` و`url` و`state` مع `headers` اختياري. استخدم `this.chatHttp.request({url, method, headers, body|json})` لتهيئة جلسة ضيف ضمن القائمة مع إلغاء مرتبط بالاستدعاء الحالي. تُعزل Cookie حسب المصدر، وتبقى الرموز وعناوين الاتصال والحالة والرسائل في الذاكرة فقط.

- `protocols`: خاص بـ WebSocket؛ حتى 8 سلاسل RFC token فريدة وغير فارغة، لا تتجاوز كل منها 128 محرفًا.
- `binary: true`: خاص بـ WebSocket؛ إرسال واستقبال إطارات ثنائية بترميز UTF-8، مع بقاء `event.data` و`send` سلاسل نصية لدى الإضافة. الحد الأقصى لكل إطار 65536 بايت مع تحقق صارم من UTF-8. الإعداد الافتراضي يستخدم إطارات نصية.
- `heartbeatIntervalMs`: عدد صحيح اختياري بين 10000 و60000. بعد نجاح الاتصال تدخل أحداث `{type: "tick"}` إلى الطابور المتسلسل نفسه بهذا الفاصل. تُلغى عند التوقف أو مغادرة الصفحة. لا تمدد أحداث tick مهلة مصافحة الاتصال أو مهلة استقبال SSE.

تغطي مهلة ثابتة إجمالية قدرها 25 ثانية إنشاء الاتصال ومصافحة البروتوكول. يستخدم WebSocket الذي لا يصرّح بالحقل `heartbeatIntervalMs` آلية ping/pong الأصلية كل 30 ثانية. عند التصريح بهذا الحقل تتولى أحداث tick الخاصة بالإضافة إبقاء الاتصال بدلًا منها، ويُحدَّد الانقطاع بأخطاء النقل الفعلية أو أحداث الإغلاق. لا يعتبر أي من الوضعين غياب نص الدردشة انقطاعًا، كما أن أحداث tick المحلية ليست دليلًا على بقاء الخادم متصلًا. يحتفظ SSE بمهلة 90 ثانية لاستقبال بيانات الخادم.

تستقبل `liveChatEvent` الحدث `{type: "open"}` أو `{type: "message", data, event?}` أو `{type: "tick"}` مع الاحتفاظ باسم حدث SSE. تعيد `state` الجديدة والحقول الاختيارية `connected` و`error` و`messages` و`send`. تتضمن الرسالة `id` ثابتًا و`text` عاديًا و`author` اختياريًا و`isHistory`. يُستخدم السجل لمنع التكرار ولا يعرض كرسائل جديدة. يقتصر `send` على إطارات المصادقة والاشتراك واستجابة نبض الاتصال التي تم التحقق منها. لا توجد واجهة لإرسال رسائل المستخدم.

يحد المضيف من حجم الإطارات والطوابير والتخزين المؤقت وعدد المحاولات. تجلب إعادة الاتصال رموز ضيف جديدة وتتيح إعادة المحاولة عند الفشل. يؤدي تعطيل الدردشة أو حجب الصفحة أو الانتقال للخلفية أو قفل التطبيق أو إغلاق المشغل إلى إلغاء الاتصال والاستدعاءات فورًا ورفض النتائج القديمة. لا يشمل ذلك تعليقات الأعمال أو صفحات السجل أو تعليقات التسجيل المرتبطة بالزمن.

```js
chat: {domains: ["chat.example.com"]},
async liveChat(id) {
  return {transport: "websocket", url: "wss://chat.example.com/room", state: {}};
},
liveChatEvent(state, event) {
  return {state, connected: true, messages: [
    {id: "message-id", text: "message", author: "author", isHistory: false}
  ], send: []};
}
```
